# WINDOW.exe — Game Design Document

> 역할: 플레이어의 경험·세계관·규칙·콘텐츠를 다루는 순수 게임 기획 문서.
> 기준일: 2026-10-30. 확정·제안·미정 표기는 [README의 문서 규칙](../README.md#문서-관리-규칙)을 따른다.
> 작업 담당과 완료 상태는 [구현 체크리스트](IMPLEMENTATION_CHECKLIST.md), 기술 방식은 [개발 가이드](DEVELOPMENT.md), 일정·시연은 [제작 계획](PRODUCTION_PLAN.md)에서 관리한다.

## 1. 개요 [확정]

- **제목:** WINDOW.exe
- **장르:** 아날로그 호러 · 미스터리 · 퍼즐 어드벤처
- **한 줄 소개:** 오래된 컴퓨터에 남겨진 이전 사용자의 흔적을 따라, 정체불명의 프로그램을 삭제하고 살아남는 호러 게임
- **주요 소재:** 오래된 컴퓨터, 가상 창, 오류 메시지, 정체불명의 프로그램, 갇힌 사람
- **핵심 경험:** 익숙한 컴퓨터 화면이 점점 기괴하게 변하고, 플레이어가 직접 창을 조작하면서 공포와 미스터리를 겪는다
- **핵심 목표:** 프로그램 내부의 규칙과 단서를 알아내 WINDOW.exe를 삭제하고 살아남는다

### 기획 의도

평범한 컴퓨터 화면과 익숙한 운영체제 화면을 공포의 공간으로 바꾼다. 플레이어는 일반적인 게임 화면이 아니라 여러 개의 창과 오류 메시지를 직접 조작하며 컴퓨터 속 기이한 현상을 겪는다. 처음엔 단순한 오류처럼 보이던 현상이 점점 플레이어를 위협하고, **창을 열고 문제를 해결하는 행동 자체가 위험할 수 있다**는 불안감을 만든다.

## 2. 핵심 플레이 요약

| 항목 | 내용 | 상태 |
|---|---|---|
| 행동 | 탐색 + 회피 (전 사용자의 파일을 뒤지고, 위험한 창과 '그것'을 피함) | [제안] |
| 조작 | 창 드래그, 파일 열기, 비밀번호 입력, 버튼 선택, 아이콘을 휴지통에 드롭. 리사이즈의 퍼즐 활용은 선택 | [제안] |
| 판정 | 연결 해제 후 WINDOW.exe를 휴지통에 드롭하면 삭제 엔딩 / 위험한 X 또는 시선 위협 채택 시 오염도 3으로 중간 게임 오버 / 구출 경로 완료 시 자리 교환 엔딩 | [제안] |
| 보상 | 새 규칙·단서 발견, 이전 피해자의 기억 조각, 설명서의 지워진 줄이 드러남 | [제안] |
| 한 판 | 시작 오류 확인 → 파일 조사 → WINDOW.exe 실행·엿보기 → 연결 해제·삭제. 구출 분기는 후속 설계 | [제안] |

### 2-1. 한 판의 진행 흐름 [제안]

표는 삭제 경로의 단서를 이해하는 권장 흐름이며, WINDOW.exe를 사진 조사 전에 실행해도 된다. 파일과 창은 자유롭게 열되, 퍼즐 완료 조건으로 진행을 구분한다.

| 단계 | 플레이어가 아는 것·하려는 일 | 핵심 행동 | 다음 단계로 이어지는 조건 |
|---|---|---|---|
| 도입 | 이상한 프로그램이 남아 있다 | 시작 오류 확인, 메모·설명서 열람 | 바탕화면 조작 가능. 오류 확인만으로 WINDOW.exe가 실행되지는 않음 |
| 파일 조사 | 전 사용자가 사진에 단서를 남겼다 | 메모의 날짜로 사진 폴더 잠금 해제 | 사진에서 방과 창 이동의 관계를 배움 |
| 엿보기 | 창을 움직이면 사진 속 방을 조사할 수 있다 | WINDOW.exe 실행, 제목 표시줄 이동, 벽 단서 클릭 | 실행 중이며 사진 해제·벽 단서 확인을 모두 충족하면 반환 순서를 발견한 것으로 처리 |
| 연결 해제 | X 대신 정해진 순서로 반환해야 한다 | `기록 → 시선 → 연결` 하위 창의 `반환` 선택 | 세 연결 해제 후 삭제 가능 |
| 삭제 | 삭제하면 안쪽의 사람도 함께 지워진다 | 결과를 암시하는 기록 확인 후 WINDOW.exe를 휴지통에 드롭 | 삭제 굿 엔딩. 삭제에 상대가 포함된다는 단서는 최종 행동 전에 제공 |

위험한 X에 의한 중간 게임 오버는 실행 이후에만 발생한다. 실행 직후부터 위험 표시와 경고를 함께 보여주며, 퍼즐 도중 같은 X의 의미를 예고 없이 바꾸지 않는다. 시선 위협을 채택하지 않아도 위 흐름은 성립해야 한다.

## 3. 세계관과 규칙

### 3-1. 설정 규칙 [확정]

1. 프로그램을 실행한 뒤 강제 종료하거나 컴퓨터를 부수려고 하면 사용자가 프로그램 안에 갇힌다.
2. 컴퓨터를 끄거나 물리적으로 부수는 것만으로는 해결되지 않는다.
3. 탈출하려면 WINDOW.exe 자체를 삭제해야 한다.
4. 삭제 방법은 처음엔 알 수 없고, 프로그램 안의 단서와 규칙으로 알아내야 한다.

### 3-2. 설정 원칙 [제안]

- 다음은 **정하지 않고 열어둔다** (설명되지 않은 부분이 더 무서움):
  - 프로그램이 다른 컴퓨터로 옮겨가도 살아남는지
  - 갇힌 사람의 현실 육체는 어떻게 되는지

### 3-3. 플레이 규칙 [제안]

설정 규칙을 플레이어가 **직접 겪으면서 알아내는 규칙**으로 바꾼다.
- 실행 중인 WINDOW.exe와 그 하위 창의 X 버튼 = 함정 (규칙 1을 체험하게 만듦). 일반 메모·사진·설명서 창은 안전하게 닫을 수 있다.
- 실행 전 설명서에서 “실행 후 X로 강제 종료하지 마세요”를 읽을 수 있게 하고, 실행 시 같은 경고를 한 번 더 확인시킨다. 위험 창에는 붉은 X와 `강제 종료` 표시를 함께 둔다. 색상 외에도 위험을 구분할 수 있어야 한다.
- 작업 관리자·전원 버튼은 세계관상의 강제 종료 사례로만 언급한다.
- 시선 위협을 추가할 경우, 엿보기 본문에 '그것'의 시선 영역이 노출되면 위험해진다. 제목 표시줄이나 일반 기록 창은 판정 대상이 아니다 (6장).
- 실행 후에는 연결을 모두 해제하기 전까지 WINDOW.exe를 삭제할 수 없다 ("사용 중인 파일" 오류). 실행 전 드롭은 “먼저 메모와 설명서를 확인하세요”라는 안내만 주고 아이콘을 유지하며, 위험·오염을 발생시키지 않는다.
- 위 규칙은 게임 속 가짜 데스크톱과 창에 적용한다. 실제 게임 앱의 종료를 함정으로 처리하지 않는다.

## 4. 등장인물

### 플레이어 [확정]

- 오래된 컴퓨터에서 WINDOW.exe를 실행해버린 사람
- 아직 **바깥에 있지만**, 잘못 행동하면 다음 피해자가 된다

### 갇힌 사람 [확정: 이전 피해자]

- 이 컴퓨터의 **전 사용자**이자 WINDOW.exe의 이전 피해자
- 바탕화면에 그 사람의 파일(메모, 사진, 문서, 휴지통 속 실패한 시도)이 남아 있다
- 직접 겪어봐서 규칙을 알지만, 일부만 알거나 잘못 기억하고 있을 수 있다 [제안]
- **소통 방식 [미정 — 간접 전달 중심으로 구상]**
  - 메모장의 문구, 과거에 남긴 문서·파일을 통해 상대의 흔적을 쫓는다.
  - 문구가 현재 시점에 바뀌는지, 과거 기록만 남아 있는지는 아직 정하지 않는다.
  - 실시간 채팅이나 엿보기만을 유일한 소통 수단으로 전제하지 않는다.
  - 엿보기는 같은 흔적을 공간에서 발견하는 수단으로 활용할 수 있다 [제안].

### WINDOW.exe / '그것' [제안]

- 정체를 설명하지 않는다. 말이 없거나 극히 적음 (포니 아일랜드의 수다스러운 루시퍼와 톤 차별화)
- 엿보기 공간 안에서 시선 규칙을 가진 존재로 등장

## 5. 핵심 메카닉

### 5-1. 조작 동사 [제안]

1. **창 조작:** 제목 표시줄 드래그, 클릭하면 맨 앞으로. 크기 조절·최대화·최소화의 퍼즐 허용 범위는 창 종류별로 정함
2. **파일 탐색:** 아이콘 더블클릭으로 열기, 비밀번호 입력
3. **규칙 실행:** 단서를 클릭해 확인하고 하위 창의 `반환` 버튼 선택
4. **드래그 앤 드롭:** 바탕화면의 WINDOW.exe 아이콘을 휴지통으로 옮기기. 다른 창으로 파일을 옮기는 행동의 용도는 구출 분기와 함께 미정

### 5-2. 엿보기 [확정: 여러 메카닉 중 하나로 포함]

- WINDOW.exe를 실행하면 뜨는 메인 창이 **뷰포트** 역할을 한다
- 창 안의 콘텐츠는 창이 아니라 바탕화면 좌표에 고정 → 창을 움직이면 그 너머 공간의 다른 부분이 보임
- 창 크기를 키우면 더 넓게 보이지만 '그것'에게 들킬 위험도 커진다 [제안]
- 엿보기 공간의 벽·물건과 바탕화면의 기록을 연결한다. 인물과의 직접 대화는 전제하지 않는다.
- **[미정]** 엿보기 창에서 최대화·최소화·크기 조절을 어디까지 허용할지. 일반 창의 기본 기능과 구분해 결정하며, 특히 최대화로 방 전체와 순서가 한 번에 드러나지 않도록 검토한다.

#### 엿보기의 진행 보장 [제안]

- 기본 창 크기에서도 창 이동만으로 모든 필수 단서에 도달할 수 있게 배치한다. 리사이즈를 정답의 필수 조건으로 삼지 않는다.
- 처음 보이는 영역에 사진과 같은 물건을 두고, 한 번의 이동으로 새로운 벽면이 드러나게 해 공간이 고정되어 있음을 가르친다.
- 단서 클릭은 엿보기 본문에 실제로 보이는 부분에서만 받는다. 창 밖이나 다른 창에 가려진 단서를 클릭해 진행할 수는 없다.
- 시선 위협을 추가해도 안전하게 머무르거나 빠져나올 영역을 둔다. 글을 읽기 위해 반드시 오염을 받아야 하는 배치는 피한다.

## 6. 위협과 실패 [제안]

| 종류 | 조건 | 결과 |
|---|---|---|
| 즉사 함정 | 사전 경고가 있는 실행 중 WINDOW.exe 또는 하위 창의 X 버튼 | 바로 갇힘 (중간 게임 오버) |
| 누적 실패 | 엿보기 창으로 '그것'의 시선 영역을 일정 시간 노출 | 오염도 +1, **3회** 누적되면 갇힘 |

- 오염도는 게이지 UI 없이 **화면 변화로만** 전달한다 (10장 참고)
- 비밀번호 오답, 잠긴 파일 열기, 삭제 조건을 갖추기 전 휴지통에 드롭하기는 안내만 표시한다. 탐색과 가설 검증을 실패로 벌하지 않는다.
- 시선 위협을 채택한다면 엿보기 본문과 시선 영역이 겹치는 순간 시각 경고를 시작하고, 1초 연속 노출되면 오염을 1회 올린다. 1초 전에 벗어나면 노출 시간을 초기화한다. 소리를 쓰는 경우 시각 경고와 동시에 준다.
- 한 번 오염된 채 계속 노출되어도 추가 오염은 없다. 본문이 시선 영역에서 완전히 벗어난 뒤 다시 들어와야 다음 노출을 판정한다. 일반 창으로 엿보기 창을 덮는 행위는 시선 회피로 인정하지 않는다.
- 시선 위협을 제외한 버전에서는 오염도 0을 유지한다. 사진 변화·파일명 변화 등 분위기 연출만으로 오염이 오르지는 않는다.
- 중간 게임 오버와 두 엔딩 화면 모두 처음부터 다시 시작하는 버튼을 제공한다. 재시작하면 열린 창과 위치, 실행 상태, 비밀번호 해제, 단서 발견, 반환 진행, 파일 변형, 오염도를 초기화한다. 일반 기록 창의 닫기·재열기는 진행을 초기화하지 않는다.

## 7. 퍼즐 구성 [제안]

퍼즐마다 중심 행동과 배우는 규칙을 구분한다. 세 퍼즐은 파일에서 배운 정보를 공간에서 확인하고, 그 결과를 창 조작에 적용하는 하나의 흐름으로 연결한다.

| 순서 | 퍼즐 | 핵심 조작 | 배우는 규칙 |
|---|---|---|---|
| 1 | **전 사용자의 파일** | 파일 열기, 비밀번호 입력 | 이 컴퓨터엔 이전 피해자의 흔적이 있고, 그게 단서다 (튜토리얼 겸 첫 접촉) |
| 2 | **창 너머 엿보기** | 창 이동, 보이는 단서 클릭 | 창이 곧 시야다. 갇힌 사람의 공간에서 순서를 찾는다. 시선 회피·리사이즈 활용은 선택 확장 |
| 3 | **삭제** | 순서에 맞는 반환, 마지막 드래그 앤 드롭 | 그냥 지울 순 없다. 피해자의 기록에서 찾은 방법으로 하위 창을 **X 버튼 없이** 정리해야 삭제할 수 있다 |

### 7-1. 퍼즐 1: 전 사용자의 파일 [제안]

- **진입:** 시작 오류를 확인하면 바탕화면을 조작할 수 있다. 실행 전에도 메모와 설명서를 읽을 수 있다.
- **단서:** 메모.txt에 “사진을 잠갔다. 비밀번호는 마지막으로 사진을 찍은 날, 10월 30일. 네 자리로.”라고 적는다. 암호 `1030`은 초기 검증용이며 최종 서사에 맞춰 교체할 수 있다.
- **행동:** 사진 폴더 더블클릭 → 숫자 네 자리 입력 → 확인 또는 Enter.
- **정답 피드백:** 잠금이 해제되고 사진과 짧은 기록이 열린다. 기록에는 “사진 속 방은 움직이지 않았다. 움직이는 건 창이었다.”라는 엿보기 힌트가 있다.
- **오답 피드백:** 입력창 아래 “날짜를 네 자리로 입력하세요. 메모.txt를 확인하세요.”를 표시한다. 재시도 횟수 제한과 오염 증가가 없다.
- **완료:** 사진 폴더의 잠금 해제를 유지한다. 창을 닫고 다시 열어도 잠금 해제를 유지하며, 설명서에 창을 움직이라는 힌트가 나타난다. 이미 벽 단서를 확인했다면 퍼즐 2도 완료된다.

### 7-2. 퍼즐 2: 창 너머 엿보기 [제안]

- **진입:** WINDOW.exe를 실행하면 제목 표시줄과 경고가 있는 작은 창이 열린다. 실행 중 재열기는 같은 창을 앞으로 가져온다.
- **공간:** 방은 바탕화면과 같은 기준 좌표에 고정한다. 왼쪽에는 갇힌 사람, 오른쪽 벽에는 정리 순서 `기록 → 시선 → 연결`을 배치한다. 창을 끌면 배경이 함께 따라오지 않아야 한다.
- **행동:** 제목 표시줄로 창을 옮겨 벽의 단서를 찾고, 보이는 단서를 클릭해 기록한다. 우연히 창이 스친 것만으로 완료시키지 않는다.
- **완료 조건:** WINDOW.exe가 실행 중이며, 사진 폴더 해제와 벽 단서 클릭을 모두 충족한다. 벽 단서를 먼저 찾았다면 확인 사실을 저장하고 사진 기록을 안내한다. 이후 사진을 해제하면 자동으로 완료하며 같은 단서를 다시 클릭하게 하지 않는다.
- **피드백:** 반환 순서를 발견한 것으로 처리하고 설명서에 “X가 아니라 반환. 기록, 시선, 연결 순서로.”가 드러난다. 정리할 하위 창 3개가 한 번만 나타난다. 설명서가 닫혀 있으면 아이콘을 강조하고, 다시 열었을 때 발견한 문구를 유지한다.

### 7-3. 퍼즐 3: 삭제 [제안]

- **진입:** 순서를 찾으면 `기록`, `시선`, `연결` 하위 창에 각각 `반환` 버튼이 나타난다. 붉은 X는 강제 종료이고 `반환`은 프로그램이 허용한 연결 해제다.
- **행동:** 벽에서 찾은 순서대로 `반환`을 누른다. 아직 차례가 아닌 버튼은 “먼저 기록을 반환해야 합니다.”처럼 선행 조건을 알려주고 진행 상태를 유지한다.
- **반환 피드백:** 해당 연결의 해제 표시를 남기고 하위 창을 제거한다. 반환한 창은 재실행이나 단서 재확인으로 다시 생성되지 않으며, 메인 창 재선택도 반환 진행을 되돌리지 않는다.
- **삭제 조건:** 반환 순서를 발견했고 세 연결이 모두 해제된 경우에만 삭제할 수 있다. 창을 단순히 가리거나 일반 창을 닫는 것으로는 충족되지 않는다.
- **마지막 행동:** 바탕화면의 WINDOW.exe 아이콘을 휴지통에 드롭한다. 조건 미충족이면 “사용 중인 파일 — 남은 연결을 반환하세요.”를 띄운다.
- **결과 예고:** `연결` 창에는 “삭제하면 안쪽의 사용자와 기록도 함께 지워집니다”라는 문구를 반환 전에 읽을 수 있게 둔다. 세 연결 해제 후에도 설명서에서 다시 확인할 수 있다. 구출 분기를 추가할 때에는 선택 가능한 시점과 되돌릴 수 없는 행동을 함께 정한다 (9장).
- **완료:** 삭제 경로를 끝까지 수행하면 상대와 창을 모두 삭제하는 굿 엔딩으로 전환한다. 상대를 구하는 별도 경로와 그 분기 조건은 9장에서 정한다.

## 8. 바탕화면과 파일 구성

### 8-1. 바탕화면 [확정]

- 파란색 배경 + CRT 주사선 + VHS식 가로 노이즈
- 배치할 아이콘: WINDOW.exe, 폴더, 메모장, 문서, 이미지 등

### 8-2. 아이콘 구성안 [제안]

기본 구성은 아래 첫 5개 아이콘으로 한다. 새 파일은 선택 연출로 추가하며 총 6~8개 안에서 제한한다. 모든 아이콘은 반응해야 하고, 실제 사람이 붙인 것 같은 파일명을 사용한다.

| 아이콘 | 처음 상태 | 역할 / 연출 |
|---|---|---|
| 휴지통 | 처음부터 | WINDOW.exe 삭제의 드롭 대상. 열면 전 사용자의 삭제 실패 흔적을 읽을 수 있음. 파일 복원 기능은 구출 분기와 함께 결정하며 필수 단서를 여기에만 두지 않음 |
| WINDOW.exe | 처음부터, 살짝 엇나간 위치 | 실행하면 위험 규칙 적용. 실행 전 드롭은 조사 안내, 실행 후 조건 미충족 드롭은 "사용 중인 파일" 오류 |
| 메모.txt | 처음부터 | 전 사용자의 일지. 날짜별로 점점 이상해지다 문장 중간에 끊김. 퍼즐 1 비밀번호 힌트 |
| 사진 폴더 (잠김) | 처음부터 | 비밀번호로 열림. 한 장은 다시 열 때마다 조금씩 달라짐 |
| 문서 (사용 설명서) | 처음부터 | 핵심 줄이 검게 지워져 있음. 규칙을 알아낼 때마다 한 줄씩 드러남 |
| 새 폴더 / 숨김 파일 | 중반에 생성 | 진행 신호. "보고있어.txt"처럼 플레이어를 겨냥한 파일 |

### 8-3. 바탕화면 연출 목록 [제안]

- 열어본 파일의 이름이 바뀜 (메모.txt → 살려줘.txt)
- 파일 수정 시간이 '방금'으로 바뀜
- 창을 열었다 닫으면 아이콘 위치가 미묘하게 바뀌어 있음
- 같은 이미지를 다시 열면 다른 이미지
- 오염도가 오를수록 아이콘 이름 글자가 깨짐 (메모.txt → 메▒.t�t)
- 가짜 커서가 플레이어 조작을 벗어나 혼자 움직임
- 메모장에 글자가 저절로 타이핑됨

필수 비밀번호·순서·위험 경고는 파일명 변형이나 이미지 교체 뒤에도 다시 읽을 수 있어야 한다. 아이콘 위치 변화는 화면 안에서만 일어나며, 입력을 벗어나는 커서 연출은 위험한 X를 대신 누르거나 진행을 강제하지 않는다. 실시간 문구 변화는 소통 방식 결정 후 채택한다.

**[확정 — 사용자 지정] 아이콘끼리 겹치는 배치는 허용하지 않는다.** 초기 배치·사용자 드래그와 아이콘 생성·위치 변화 연출에도 같은 규칙을 유지한다.

## 9. 엔딩 [제안 — 사용자 구상 반영, 세부 조건 미정]

게임 도중의 실패와 끝까지 진행한 뒤의 두 엔딩을 구분한다.

| 구분 | 도달 행동 | 결과 | 필요한 설계 |
|---|---|---|---|
| 중간 게임 오버 | 위험한 강제 종료 또는 시선 위협 채택 시 오염도 한계 도달 | 플레이어가 창으로 빨려 들어감 | 경고 → 흡입 연출 → 재시작. 이 실패만으로 상대가 탈출했다고 보여주지는 않음 |
| 굿 엔딩 | 상대와 창을 모두 삭제하는 경로 완료 | 상대와 WINDOW.exe가 모두 삭제됨 | 삭제에 상대도 포함된다는 것을 마지막 행동 전에 추론할 수 있게 할 것 |
| 배드 엔딩 | 상대를 구하려는 경로 완료 | 상대는 빠져나오고 플레이어가 대신 창에 빨려 들어감 | 구출 시도가 자리 교환으로 이어진다는 복선과 분기 행동 필요 |

- **[미정]** 삭제와 구출의 분기를 명시적 선택지로 제시할지, 파일 복원·반환 같은 서로 다른 행동으로 나눌지.
- **[미정]** 상대가 자리 교환을 알고 유도했는지. 배드 엔딩의 결과만으로 고의적 배신을 확정하지 않는다.
- **[제안]** 파일에 “연결을 끊으면 안쪽의 기록도 지워진다”, “출구는 하나, 연결된 사용자는 하나”처럼 양쪽 결과를 암시하는 흔적을 배치한다. 최종 문구는 분기 방식과 함께 다듬는다.
- 중간 게임 오버의 흡입과 배드 엔딩의 자리 교환은 전후 장면을 다르게 하여 구분한다.

### 엔딩 분기를 정할 때 맞출 조건 [제안]

- 삭제 경로에서는 플레이어가 살아남고 갇힌 사람도 함께 삭제된다. 이 문서의 `굿`은 플레이어의 생존 결과를 가리키며, 상대의 구출을 뜻하지 않는다.
- 구출 경로를 넣을 경우, 마지막 `연결` 반환 전후 중 언제 갈라지는지 먼저 정한다. 7-3의 반환·삭제 조건과 구출 조건이 동시에 모순 없이 성립해야 한다.
- 분기 행동 전에 삭제의 대가와 자리 교환을 암시하는 기록을 읽을 수 있게 한다. 단서를 발견하는 순서만으로 엔딩이 잠기거나 바뀌지는 않는다.
- 삭제 경로만 제작할 경우에는 작동하지 않는 구출 버튼·복원 기능을 제시하지 않는다. 구출 배드 엔딩은 별도 경로와 결과까지 이어질 때 추가한다.

## 10. 비주얼과 사운드

### 10-1. 비주얼 [제안]

- 주사선·노이즈가 모든 UI 위에 겹쳐 보여, 창까지 CRT 화면 속에 있는 것처럼 보이게 한다 (콘셉트 통일성)
- 창 테두리: 회색 Win98풍
- 아이콘 이름: 흰 글씨 + 검은 그림자
- 주사선·글리치·오염 효과를 적용한 상태에서도 필수 단서와 위험 표시를 읽을 수 있게 한다. 화면 효과가 버튼 클릭을 가로막지 않게 한다.

### 10-2. 오염도 단계별 화면 [제안]

| 단계 | 화면 |
|---|---|
| 0 (정상) | 파란 배경 |
| 1 | 채도·밝기가 낮아지고 노이즈 줄이 늘어남 |
| 2 | 붉은 기가 돌고 화면이 찢어지는 글리치 |
| 3 (갇힘) | 블루스크린 → 중간 게임 오버 |

### 10-3. 사운드 [미정]

- 사운드 방향은 미정. 후보: CRT 험, 클릭음, 오류음, 글리치음, 앰비언트 BGM 1개.

## 12. 기획에서 결정이 필요한 것 [미정]

현재 2~10장의 세부 흐름과 해법에는 제안이 포함되어 있다. 아래 질문의 결론을 해당 장에 반영하며, 결정되지 않은 내용을 확정으로 취급하지 않는다.

| 주제 | 결정할 질문 |
|---|---|
| 한 판의 진행 | 2장의 권장 흐름과 3장의 실행 전후 규칙을 채택할 것인가? |
| 퍼즐 3개 | 7장의 단서·행동·완료 조건을 채택할 것인가? 단서를 먼저 찾거나 기록 창을 다시 열어도 진행이 막히지 않는가? |
| 간접 소통 | 과거 기록·공간 단서만 사용할지, 현재 시점의 문구 변화도 사용할지? |
| 위협·실패 | 위험한 X와 재시작 규칙을 채택할 것인가? 시선 위협을 사용할지, 사용한다면 6장의 노출·오염 규칙을 채택할 것인가? |
| 엿보기 창 | 최대화·최소화·크기 조절을 어디까지 허용할 것인가? 전체 공간을 한 번에 보거나 위협을 회피하는 방식과 충돌하지 않는가? |
| 엔딩 분기 | 삭제와 구출을 어떤 행동으로 나눌지? 마지막 연결 반환 전후 중 어디서 분기하고 어느 행동부터 되돌릴 수 없는가? |
| 갇힌 사람의 의도 | 자리 교환을 알고 유도했는가? 결과만으로 고의적 배신을 확정하지 않는다. |
| 사운드 | CRT 험·클릭·오류·글리치·앰비언트 BGM 중 어떤 방향을 채택할 것인가? |
