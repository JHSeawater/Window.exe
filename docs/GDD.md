# WINDOW.exe — Game Design Document

> 역할: 플레이어의 경험·세계관·규칙·콘텐츠를 다루는 순수 게임 기획 문서.
> 기준일: 2026-10-31. 확정·제안·미정 표기는 [README의 문서 규칙](../README.md#문서-관리-규칙)을 따른다.
> 작업 담당과 완료 상태는 [구현 체크리스트](IMPLEMENTATION_CHECKLIST.md), 기술 방식은 [개발 가이드](DEVELOPMENT.md), 일정·시연은 [제작 계획](PRODUCTION_PLAN.md)에서 관리한다.
> **[확정 — 사용자 지정] 현재 설정은 [보스전 기획](BOSS_FIGHT.md)을 기준으로 맞춘다.** 이 문서는 전체 흐름을 요약하고, 보스전의 상세 규칙·수치·유언·검증 기준과 내부 미결 쟁점은 보스전 기획에서 관리한다. 그 문서의 [제안]·[미정]을 이번 정합성 수정만으로 확정하지 않는다.

## 1. 개요 [확정]

- **제목:** WINDOW.exe
- **장르:** 아날로그 호러 · 미스터리 · 퍼즐 어드벤처
- **한 줄 소개:** 오래된 컴퓨터에 남겨진 이전 사용자의 흔적을 따라, 정체불명의 프로그램을 삭제하고 살아남는 호러 게임
- **주요 소재:** 오래된 컴퓨터, 가상 창, 오류 메시지, 정체불명의 프로그램, 눈이 된 이전 희생자와 유언
- **핵심 경험:** 익숙한 컴퓨터 화면이 점점 기괴하게 변하고, 플레이어가 직접 창을 조작하면서 공포와 미스터리를 겪는다
- **핵심 목표:** 프로그램 내부의 규칙과 단서를 알아내 WINDOW.exe를 삭제하고 살아남는다

### 기획 의도

평범한 컴퓨터 화면과 익숙한 운영체제 화면을 공포의 공간으로 바꾼다. 플레이어는 일반적인 게임 화면이 아니라 여러 개의 창과 오류 메시지를 직접 조작하며 컴퓨터 속 기이한 현상을 겪는다. 처음엔 단순한 오류처럼 보이던 현상이 점점 플레이어를 위협하고, **창을 열고 문제를 해결하는 행동 자체가 위험할 수 있다**는 불안감을 만든다.

## 2. 핵심 플레이 요약

| 항목 | 내용 | 상태 |
|---|---|---|
| 행동 | 탐색 + 회피 (전 사용자의 파일을 뒤지고, 위험한 창과 '그것'을 피함) | [제안] |
| 조작 | 파일 조사·엿보기 후, 보스전에서 창 이동·8방향 리사이즈·휴지통 끌기·Space 최소화/복원·보스 드롭 | 보스전 조작은 [확정], 앞 퍼즐 세부는 [제안] |
| 판정 | 보스 복원 취소·직접 휴지통 비우기는 삭제 엔딩 / 2페이즈 피격은 다운로드를 유지하는 즉시 리스폰 / 다운로드 완료는 리스폰 없는 별도 배드 엔딩 | [확정 — 보스전 기획] |
| 보상 | 새 규칙·단서 발견, 이전 피해자의 기억 조각, 설명서의 지워진 줄이 드러남 | [제안] |
| 한 판 | 앞 퍼즐에서 열쇠 획득 → 휴지통 열기 → 복원·강제 다운로드 → 눈알 연출 → 보스전 → 복원 취소·직접 휴지통 비우기 | [확정 — 보스전 기획], 앞 퍼즐의 해법은 [미정] |

### 시작 화면 [확정 — 사용자 답변]

시작 입력으로 인트로 영상을 재생한 뒤 바탕화면으로 들어간다. 영상 또는 필수 표시 자원이 없는 경우에만 영상을 건너뛰고 바탕화면으로 진입한다. 자원이 연결된 경우에는 기존 영상 연출을 유지한다.

### 2-1. 한 판의 진행 흐름

보스전 전후의 큰 흐름은 [보스전 기획 1-2장](BOSS_FIGHT.md#1-2-게임-안에서의-위치)의 확정 내용을 따른다. 기존 파일 조사·사진 비밀번호·엿보기는 앞 퍼즐의 제안으로 유지하되, 열쇠 획득까지의 구체적인 해법은 아직 확정하지 않는다.

| 단계 | 플레이어가 아는 것·하려는 일 | 핵심 행동 | 다음 단계로 이어지는 조건 |
|---|---|---|---|
| 도입 | 이상한 프로그램이 남아 있다 | 시작 오류 확인, 메모·설명서 열람 | 바탕화면 조작 가능. 오류 확인만으로 WINDOW.exe가 실행되지는 않음 |
| 파일 조사 | 전 사용자가 사진에 단서를 남겼다 | 메모의 날짜로 사진 폴더 잠금 해제 | 사진에서 방과 창 이동의 관계를 배움 |
| 엿보기·열쇠 획득 | 창을 움직이면 희생자들의 흔적을 조사할 수 있다 | 공간의 단서를 조사해 열쇠 획득으로 연결 | 열쇠를 앞 퍼즐에서 얻는 것은 확정. 조사 순서·해법은 미정 |
| 휴지통·복원 | 갇힌 사람을 구출할 수 있다고 믿는다 | 열쇠로 휴지통을 열고 복원 선택 | 강제 다운로드 시작. 구출 시도가 함정이었음이 드러남 |
| 눈알 연출 | 창 안의 사람들은 이미 모두 희생되었다 | 진실을 알리는 눈알과 다른 희생자들을 목격 | 연출 동안 다운로드 일시 정지, 이후 보스전 진입 |
| 보스전 | 복원을 취소해야 살아남는다 | 복제본 창 `WINDOW(1).exe`와 휴지통으로 진짜 `WINDOW.exe`를 포획·드롭 | 1페이즈 첫 삭제는 실패하고 2페이즈로 전환. 2페이즈 성공 시 복원 취소 |
| 삭제·엔딩 | 희생자들도 프로그램과 함께 삭제된다 | 복원 취소 뒤 플레이어가 직접 휴지통 비우기 | 희생자와 프로그램 삭제 → 정상 바탕화면 복귀. 프로그램은 재등장하지 않음 [확정] |

위험한 X는 강제 종료라는 뜻을 유지하고, 색상 외에도 위험을 알 수 있게 한다. 보스전에서는 시각 신호와 지정 이미지 연출로 규칙을 전달한다. 2페이즈 배경 문구는 표시하지 않고 Space 안내 이미지를 잠시 띄운다. 보스전 이전의 경고 방식과 퍼즐 세부는 별도로 정한다.

## 3. 세계관과 규칙

### 3-1. 설정 규칙 [확정]

1. 프로그램을 실행한 뒤 강제 종료하거나 컴퓨터를 부수려고 하면 사용자가 프로그램 안에 갇힌다.
2. 컴퓨터를 끄거나 물리적으로 부수는 것만으로는 해결되지 않는다.
3. 탈출하려면 WINDOW.exe 자체를 삭제해야 한다.
4. 삭제 방법은 처음엔 알 수 없고, 프로그램 안의 단서와 규칙으로 알아내야 한다.
5. 창 안의 세계에는 생존자가 없다. 눈은 이전 희생자들이며, 벽의 낙서는 그들이 남긴 유언이다.

### 3-2. 설정 원칙 [제안]

- 다음은 **정하지 않고 열어둔다** (설명되지 않은 부분이 더 무서움):
  - 프로그램이 다른 컴퓨터로 옮겨가도 살아남는지
  - 갇힌 사람의 현실 육체는 어떻게 되는지

### 3-3. 플레이 규칙 [제안]

설정 규칙을 플레이어가 **직접 겪으면서 알아내는 규칙**으로 바꾼다.
- **[확정]** 보스전의 `WINDOW(1).exe`에서 빨간 X를 누르면 즉시 갇힌다. 일반 메모·사진·설명서의 닫기와 구분한다.
- **[제안]** 보스전 이전에는 설명서 등에서 강제 종료의 위험을 알린다. 보스전에서는 시각 신호와 지정 이미지를 사용하고 2페이즈 배경 유언은 표시하지 않는다. 색상 외에도 위험을 구분할 수 있어야 한다.
- 작업 관리자·전원 버튼은 세계관상의 강제 종료 사례로만 언급한다.
- **[확정]** 보스전의 판정은 페이즈마다 다르다. 1페이즈는 본문 노출과 오염 누적, 2페이즈는 제목 표시줄을 포함한 프레임과 눈의 충돌을 사용한다. 보스전 이전 엿보기의 위협 채택 여부는 별도 미정이다.
- **[확정]** 1페이즈의 첫 삭제는 사용자 지정 `Cannot_Move` 오류 이미지로 실패를 알린다. 표시 리소스와 전환은 [보스전 기획 4-5·5장](BOSS_FIGHT.md)을 따른다. 2페이즈에서 보스를 휴지통에 넣으면 복원이 취소되고 다운로드가 멈춘다. 과거의 `기록 → 시선 → 연결` 반환을 현재 삭제의 선행 조건으로 사용하지 않는다.
- 위 규칙은 게임 속 가짜 데스크톱과 창에 적용한다. 실제 게임 앱의 종료를 함정으로 처리하지 않는다.

## 4. 등장인물

### 플레이어 [확정]

- 오래된 컴퓨터에서 WINDOW.exe를 실행해버린 사람
- 아직 **바깥에 있지만**, 잘못 행동하면 다음 피해자가 된다

### 이전 희생자와 눈 [확정]

- 이 컴퓨터의 전 사용자를 포함해 WINDOW.exe에 당한 사람들이다. 창 안에 살아 있는 구출 대상은 없다.
- 눈은 모두 이전 희생자들이다. 프로그램이 조종하여 보스전의 위협으로 사용한다.
- 벽 글은 희생자들이 살아남으려고 알아낸 것을 남긴 유언이며, 분위기와 공략 전달을 겸한다.
- 바탕화면에 메모·사진·문서·실패한 시도 같은 과거의 흔적이 남아 있다는 구성은 유지한다 [제안].
- 보스전 직전 눈알 하나가 괴로워하며 진실을 알린다. 살아 있는 인물과의 구출·자리 교환 경로로 해석하지 않는다.
- 보스전 이전 기록의 실시간 변화 여부와 전달 방식은 미정이다. 보스전의 안내는 [보스전 기획 8장](BOSS_FIGHT.md#8-화면-신호와-유언)을 따른다.

### WINDOW.exe / '그것' [제안]

- 정체를 설명하지 않는다. 말이 없거나 극히 적음 (포니 아일랜드의 수다스러운 루시퍼와 톤 차별화)
- 엿보기 공간 안에서 시선 규칙을 가진 존재로 등장

## 5. 핵심 메카닉

### 5-1. 조작 동사 [제안]

1. **창 조작:** 제목 표시줄 드래그, 클릭하면 맨 앞으로. 크기 조절·최대화·최소화의 퍼즐 허용 범위는 창 종류별로 정함
2. **파일 탐색:** 아이콘 더블클릭으로 열기, 비밀번호 입력
3. **규칙 실행:** 앞 퍼즐의 단서를 조사하고, 열쇠로 연 휴지통에서 `복원` 선택. 앞 퍼즐 세부는 [제안], 복원이 다운로드를 시작하는 흐름은 [확정]
4. **드래그 앤 드롭:** 보스전에서 창 안의 휴지통을 끌고 전진한 뒤, 포획한 진짜 WINDOW.exe를 휴지통에 넣기 [확정]

### 5-2. 엿보기 [확정: 여러 메카닉 중 하나로 포함]

- WINDOW.exe를 실행하면 뜨는 메인 창이 **뷰포트** 역할을 한다
- **[확정 — 사용자 지정]** 기본 바탕화면을 WINDOW.exe로 비추면 창 본문에 `Window_Desktop.png`의 붉은 바탕화면이 보인다. 이미지는 화면 좌표에 고정되고 창 바깥의 일반 바탕화면은 유지한다. 엿보기 대상이 있는 영역에서는 해당 숨은 콘텐츠가 이 배경 위에 보인다.
- **[확정 — 사용자 지정]** 휴지통·메모·엿보기 이미지·인터넷·key.txt 아이콘을 WINDOW.exe로 비추면 제공된 corrupted 버전 이미지가 보인다. 엿보기 아이콘은 평소 `Image.png`, 창 안에서는 `Image-corrupted-red.png`를 사용하며 key.txt도 창 안에서 같은 변형 이미지를 사용한다. 일반 바탕화면의 아이콘은 원본을 유지하며, 아이콘을 옮기면 창 안에서 보이는 변형 이미지도 같은 위치를 따라간다.
- 창 안의 콘텐츠는 창이 아니라 바탕화면 좌표에 고정 → 창을 움직이면 그 너머 공간의 다른 부분이 보임
- 창 크기를 키우면 더 넓게 보이지만 '그것'에게 들킬 위험도 커진다 [제안]
- 엿보기 공간의 벽·물건과 바탕화면의 기록을 연결한다. 인물과의 직접 대화는 전제하지 않는다.
- **[미정]** 보스전 이전 엿보기 창에서 최대화·최소화·크기 조절을 어디까지 허용할지. 보스전의 복제본 창 조작과 구분한다. 보스전에서는 창 이동·8방향 리사이즈와 Space 최소화/복원을 사용하며, 상세 제약은 보스전 기획을 따른다.

#### 엿보기의 진행 보장 [제안]

- 이 절은 보스전 이전 조사 퍼즐의 제안이다. 기본 창 크기에서도 창 이동만으로 모든 필수 단서에 도달할 수 있게 배치한다. 보스전 1페이즈의 모양 변경 조건에는 적용하지 않는다.
- 처음 보이는 영역에 사진과 같은 물건을 두고, 한 번의 이동으로 새로운 벽면이 드러나게 해 공간이 고정되어 있음을 가르친다.
- 단서 클릭은 엿보기 본문에 실제로 보이는 부분에서만 받는다. 창 밖이나 다른 창에 가려진 단서를 클릭해 진행할 수는 없다.
- 시선 위협을 추가해도 안전하게 머무르거나 빠져나올 영역을 둔다. 글을 읽기 위해 반드시 오염을 받아야 하는 배치는 피한다.

## 6. 위협과 실패

| 종류 | 조건 | 결과 |
|---|---|---|
| 강제 종료 | 보스전 창의 빨간 X 버튼 | 즉시 갇힘 |
| 1페이즈 누적 실패 | 본문이 눈의 시선 영역에 허용 시간 이상 노출 | 오염이 누적되고 한계에 도달하면 갇힘 |
| 2페이즈 충돌 | 눈이 제목 표시줄을 포함한 창 프레임에 닿음 | 다운로드를 유지하고 2페이즈 시작 순간으로 즉시 리스폰 |
| 다운로드 완료 | 2페이즈에서 다운로드가 다 참 | 별도 배드 엔딩으로 진입. 리스폰 없음 |

- **[확정 — 최신 사용자 지시]** 2페이즈 눈 접촉은 별도 재도전 화면·이유·버튼·대기 없이 시작 순간으로 즉시 리스폰한다. 창·휴지통·보스·눈·공격 진행·벽 기록·최소화·포획·드래그는 초기 전투 상태로 되돌리되 다운로드 진행도·누적 시간·남은 시간은 유지하고 계속 진행한다.
- **[확정]** 2페이즈 최초 진입만 다운로드 30%에서 시작한다. 여러 번 죽어도 한 판의 시간 제한을 공유하고, 다운로드가 100%가 되면 최종적으로 갇히는 별도 배드 엔딩으로 진입한다. 이 경우 자동 리스폰하지 않는다.
- 1페이즈 오염/X의 재시작 규칙은 유지한다. 2페이즈 X의 기존 시작 지점 복귀도 다운로드를 되돌리지 않는 일반 리스폰 규칙을 따른다. 구출·자리 교환 경로는 추가하지 않는다.
- **[확정]** 1페이즈에는 시간 제한이 없고 다운로드가 상한에서 멈춘다. 2페이즈에서는 최소화 중에도 다운로드가 진행된다.
- 검토 후 확정한 시간 우선순위·취소 복원·앱 비활성/좌표 공간 무효 정지는 [보스전 기획 3-5장](BOSS_FIGHT.md#3-5-갇힘과-재시작-확정)·[6-6장](BOSS_FIGHT.md#6-6-다운로드-타이머-확정--기획-흐름-세부-규칙은-1029-결정)을 따른다. 2페이즈의 정확한 동시 최소화는 눈 피격보다 우선하되 만료/X 우선은 유지한다. 취소 복원은 경로가 아닌 도착 상태만 판정하며 정지 중이면 복귀 후 검사한다. 좌표를 계산할 수 없거나 최소 창 제약을 수용하지 못하는 화면은 전투·다운로드를 함께 정지하고 유효 복구 뒤 이어 간다.
- 1페이즈 오염은 전용 누적 게이지 없이 화면 변화로 전달한다. 본문 아래의 노출 진행 막대는 현재 노출 시간을 알리는 별도 신호다. 굳음·노출·재노출·최소화와 수치의 원본은 [보스전 기획 4장](BOSS_FIGHT.md#4-1페이즈--눈을-피해-가는-공간), [6장](BOSS_FIGHT.md#6-2페이즈--장악), [7장](BOSS_FIGHT.md#7-수치-초기값-제안)이다.
- **[제안]** 보스전 이전의 비밀번호 오답·잠긴 파일 조사는 실패로 벌하지 않는다. 앞 퍼즐의 위협과 재시작 범위는 별도로 정한다. 보스전 저장 지점을 게임 전체 초기화로 대신하지 않는다.

## 7. 퍼즐 구성 [제안]

파일 조사·엿보기의 세부 해법은 제안으로 남기고, 앞 퍼즐에서 열쇠를 얻어 복원 함정과 보스전으로 이어지는 큰 흐름은 확정 내용으로 반영한다. 과거 반환 순서 퍼즐은 현재 삭제 경로에서 제외한다.

| 순서 | 퍼즐 | 핵심 조작 | 배우는 규칙 |
|---|---|---|---|
| 1 | **전 사용자의 파일** | 파일 열기, 비밀번호 입력 | 이 컴퓨터엔 이전 피해자의 흔적이 있고, 그게 단서다 (튜토리얼 겸 첫 접촉) |
| 2 | **창 너머 엿보기** | 창 이동, 보이는 단서 조사 | 창이 곧 시야다. 희생자들의 흔적을 조사하고 열쇠 획득으로 연결한다. 구체 해법은 미정 |
| 3 | **복원 함정·보스전·삭제** | 휴지통 복원, 창 모양 변경·전진·회피, 포획·드롭, 직접 휴지통 비우기 | 구출이라 믿은 복원이 함정이며, 복원을 취소하고 프로그램을 삭제해야 살아남는다 [확정] |

### 7-1. 퍼즐 1: 전 사용자의 파일 [제안]

아래 사진 잠금은 과거 제안이다. 최신 사용자 요청으로 독립된 앨범/사진 아이콘을 제거했으므로 현재 바탕화면 구성에는 적용하지 않는다.

- **진입:** 시작 오류를 확인하면 바탕화면을 조작할 수 있다. 실행 전에도 메모와 설명서를 읽을 수 있다.
- **단서:** 메모.txt에 “사진을 잠갔다. 비밀번호는 마지막으로 사진을 찍은 날, 10월 30일. 네 자리로.”라고 적는다. 암호 `1030`은 초기 검증용이며 최종 서사에 맞춰 교체할 수 있다.
- **행동:** 사진 폴더 더블클릭 → 숫자 네 자리 입력 → 확인 또는 Enter.
- **정답 피드백:** 잠금이 해제되고 사진과 짧은 기록이 열린다. 기록에는 “사진 속 방은 움직이지 않았다. 움직이는 건 창이었다.”라는 엿보기 힌트가 있다.
- **오답 피드백:** 입력창 아래 “날짜를 네 자리로 입력하세요. 메모.txt를 확인하세요.”를 표시한다. 재시도 횟수 제한과 오염 증가가 없다.
- **완료:** 사진 폴더의 잠금 해제를 유지한다. 창을 닫고 다시 열어도 잠금 해제를 유지하며, 설명서에 창을 움직이라는 힌트가 나타난다. 사진 해제와 벽 단서 확인을 열쇠 획득에 어떻게 연결할지는 퍼즐 2의 미정 사항으로 둔다.

### 7-2. 퍼즐 2: 창 너머 엿보기 [제안]

- **진입:** WINDOW.exe를 실행하면 제목 표시줄과 경고가 있는 작은 창이 열린다. 실행 중 재열기는 같은 창을 앞으로 가져온다.
- **공간:** 방은 바탕화면과 같은 기준 좌표에 고정하고 희생자들의 흔적과 단서를 배치한다. 살아 있는 구출 대상이나 과거 반환 순서를 현재 정답으로 두지 않는다. 창을 끌면 배경이 함께 따라오지 않아야 한다.
- **행동:** 제목 표시줄로 창을 옮겨 벽의 단서를 찾고, 보이는 단서를 클릭해 기록한다. 우연히 창이 스친 것만으로 완료시키지 않는다.
- **완료 조건 [미정]:** 앞 퍼즐에서 열쇠를 얻는다는 결과는 확정이다. 사진 해제·벽 단서와 열쇠의 구체적인 관계, 획득 행동은 앞 퍼즐 담당과 정한다. 기존의 사진 해제+벽 단서 확인 조건을 이번 수정만으로 확정하지 않는다.
- **진행 보장 [제안]:** 단서를 먼저 찾았거나 기록 창을 닫았다 다시 열어도 확인 사실을 유지한다. 열쇠 획득과 다음 단계 진입이 중복 실행되지 않아야 한다.

### 7-3. 복원 함정·보스전·삭제 [확정]

- **진입:** 열쇠로 휴지통을 열고 복원을 누르면 진짜 WINDOW.exe의 강제 다운로드가 시작된다. 눈알 연출 중에는 다운로드를 일시 정지한다.
- **1페이즈:** 복제본 창으로 숨은 층의 고정 눈을 피하며 자유롭게 이동한다. 회색 길이나 지정 경로 제한은 없으며, 숨은 층 배경에 유언·안내 글자를 표시하지 않는다. 창 밖의 어두운 배경 좌상단에는 시스템 오류 문구가 명령어 창처럼 한 줄씩 쌓인다. 문구와 연출은 [보스전 기획 3-1장](BOSS_FIGHT.md#3-1-화면-구성-제안)을 따른다. 창 이동으로 휴지통이 따라오지 않으며 창 안에서 따로 드래그한다. 최소 면적·모양 변경 횟수 제한 없이 작은 창으로도 완주할 수 있고, 긴 창은 더 멀리 옮기는 선택이다. 첫 삭제 시도는 사용 중인 파일 오류로 실패한다.
- 고정 눈은 사용자 지정 눈꺼풀·붉은 동공을 겹쳐 창의 중심을 바라본다. 별도 원형 시야 표시를 없애고 눈 그림을 키워, 본문이 실제 그림 외곽에 닿으면 기존 굳음·노출·오염 규칙을 적용한다. 아트 원본과 표시·접촉 기준은 [보스전 기획 4장](BOSS_FIGHT.md#4-1페이즈--눈을-피해-가는-공간)을 따른다.
- **보스전 화면:** 두 페이즈에서 평상시 가로 노이즈를 약하게 표시한다. 구체적인 비율과 전환 효과는 [보스전 기획 3-1장](BOSS_FIGHT.md#3-1-화면-구성-제안)을 따른다.
- **2페이즈:** 1페이즈 숨은 층의 Phase_1.png를 창 바깥 배경에 표시하고 창 본문은 파란 정상 바탕화면을 유지한다. 배경 문구를 제거하고 시작 후 상단에 지정 Spacebar 이미지 3개를 잠시 표시한다. 세부 시간과 표시 규칙은 보스전 기획 8-2장을 따른다. 크기가 조금씩 다른 눈과 중앙 직선 경로를 막는 눈을 포함해 제자리에 떠 있는 눈 4개를 피하면서 휴지통을 보스 쪽으로 옮긴다. 사용자 지정 흰자·붉은 동공을 겹쳐 창을 바라보는 눈 아트는 [보스전 기획 6-1장](BOSS_FIGHT.md#6-1-핵심-규칙-확정)을 따른다. 이미 발사된 일자 벽은 Space 최소화로 회피한다. 빠른 포획으로 벽 예고를 취소하는 플레이는 허용한다.
- **복원 취소:** 포획한 진짜 WINDOW.exe를 휴지통에 넣으면 다운로드가 멈추고 보스전이 끝난다.
- **마지막 행동:** 플레이어가 직접 휴지통 비우기를 실행한다. 희생자와 프로그램이 삭제되고 정상 바탕화면으로 돌아온다. 프로그램 재등장은 없다.
- **상세 원본:** 조작·두 페이즈·전환·다운로드·유언·수치·검증 기준은 [보스전 기획](BOSS_FIGHT.md)에서 관리한다. 앞뒤 연출의 표현 세부는 9장과 보스전 기획의 미정 사항을 따른다.

## 8. 바탕화면과 파일 구성

### 8-1. 바탕화면 [확정]

- 파란색 배경 + CRT 주사선 + VHS식 가로 노이즈
- 배치할 아이콘: WINDOW.exe, 폴더, 메모장, 문서, 이미지 등
- **[확정 — 사용자 지정]** 독립된 앨범/사진 아이콘은 제거한다. 현재 여섯 아이콘은 시작할 때 휴지통 → 메모 → 인터넷 → `뷁쀍꿻뛟.png` → key.txt → WINDOW.exe 순서로 왼쪽 위부터 세로로 정렬하고, 화면 높이에 맞지 않으면 다음 열에 배치한다. 이후 사용자의 자유 드래그를 허용한다.
- **[확정 — 사용자 지정]** 빈 바탕화면을 드래그해 여러 아이콘을 영역 선택하고, 선택된 아이콘들을 상대 간격을 유지한 채 함께 옮길 수 있다. 선택 자체로 파일을 실행하거나 삭제하지 않으며, 더블클릭은 누른 아이콘 하나만 연다.

### 8-2. 아이콘 구성안 [제안]

현재 바탕화면은 휴지통·메모·인터넷·`뷁쀍꿻뛟.png`·key.txt·WINDOW.exe의 여섯 아이콘이다. 아래는 역할의 제안이며 설명서와 새 파일은 후속 후보로 남긴다. 모든 아이콘은 반응해야 하고, 실제 사람이 붙인 것 같은 파일명을 사용한다.

| 아이콘 | 처음 상태 | 역할 / 연출 |
|---|---|---|
| 휴지통 | 열쇠 획득 전 잠금 | 열쇠로 열면 복원 가능. 복원은 강제 다운로드를 시작하는 함정. 보스전 휴지통과 일반 아이콘의 연결 방식은 개발 시 정리 |
| WINDOW.exe | 앞 퍼즐에서의 초기 표시 방식은 제안 | 진짜 프로그램이자 보스. 복제본 창 이름은 `WINDOW(1).exe`. 실행 전 아이콘 드롭의 의미는 앞 퍼즐과 함께 정함 |
| 메모.txt | 처음부터 | 전 사용자의 일지. 날짜별로 점점 이상해지다 문장 중간에 끊김. 퍼즐 1 비밀번호 힌트 |
| `뷁쀍꿻뛟.png` (기존 쌀쌀쌀) | 처음부터 | Image 아이콘으로 표시하고 WINDOW.exe 안에서 붉은 변형이 보임. 기존 엿보기 퍼즐 연결 유지 |
| 문서 (사용 설명서) | 처음부터 | 핵심 줄이 검게 지워져 있음. 규칙을 알아낼 때마다 한 줄씩 드러남 |
| 새 폴더 / 숨김 파일 | 중반에 생성 | 진행 신호. "보고있어.txt"처럼 플레이어를 겨냥한 파일 |

### 8-3. 바탕화면 연출 목록 [제안]

- 열어본 파일의 이름이 바뀜 (메모.txt → 살려줘.txt)
- 파일 수정 시간이 '방금'으로 바뀜
- 창을 열었다 닫으면 아이콘 위치가 미묘하게 바뀌어 있음
- 같은 이미지를 다시 열면 다른 이미지
- 오염도가 오를수록 아이콘 이름 글자가 깨짐 (메모.txt → 메▒.t�t)
- 가짜 커서가 플레이어 조작을 벗어나 혼자 움직임
- 메모장에 글자가 저절로 타이핑됨

필수 비밀번호·순서·위험 경고는 파일명 변형이나 이미지 교체 뒤에도 다시 읽을 수 있어야 한다. 아이콘 위치 변화는 화면 안에서만 일어나며, 입력을 벗어나는 커서 연출은 위험한 X를 대신 누르거나 진행을 강제하지 않는다. 실시간 문구 변화는 소통 방식 결정 후 채택한다.

**[확정 — 사용자 지정] 아이콘끼리 겹치는 배치는 허용하지 않는다.** 초기 배치·사용자 드래그와 아이콘 생성·위치 변화 연출에도 같은 규칙을 유지한다.

---

### 8-4. 간헐적인 마우스 끊김 [제외]

최신 사용자 지시에 따라 이 연출은 현재 제작 범위에서 제외한다. 게임의 핵심 요소가 아니며 입력 체계 변경과 검증 비용에 비해 이득이 작다. 게임은 정상적인 마우스 이동·클릭·드래그를 유지한다. 앞서 논의한 기본 On과 설정 메뉴 연결은 채택하지 않는다.

---

## 9. 엔딩

**[확정 — 최신 사용자 지시 반영]** 성공 엔딩은 프로그램과 희생자들의 삭제다. 2페이즈 다운로드 완료는 최종 갇힘을 보여 주는 별도 배드 엔딩이며 자동 리스폰하지 않는다. 눈 접촉에 의한 반복 재도전과 구분한다. 구출·자리 교환 경로는 없다.

| 구분 | 도달 행동 | 결과 | 필요한 설계 |
|---|---|---|---|
| 일반 실패·재도전 | 1페이즈 오염/X 또는 2페이즈 눈 접촉/X | 해당 페이즈 시작 상태로 복귀 | 2페이즈는 재도전 화면 없이 즉시 리스폰하며 다운로드 유지 |
| 다운로드 완료 배드 엔딩 | 2페이즈의 누적 다운로드가 100%에 도달 | 플레이어가 최종적으로 창 안의 세계에 갇힘 | 별도 배드 엔딩으로 종료. 자동 리스폰 없음. 장면·문구·연출과 이후 새 게임 UI는 미정 |
| 삭제 성공 엔딩 | 2페이즈에서 복원 취소 후 플레이어가 직접 휴지통 비우기 | 희생자와 WINDOW.exe가 함께 삭제되고 정상 바탕화면으로 복귀 | 프로그램 재등장 없음. 휴지통 비우기의 UI와 세부 연출은 앞뒤 연출 담당과 연결 |

- 복원은 별도 구출 분기가 아니라 강제 다운로드와 보스전을 시작하는 함정이다.
- 눈알 연출과 유언으로 희생자들의 정체와 삭제의 대가를 전달한다. 생존자를 구출하거나 희생자가 플레이어와 자리를 바꾸는 기존 안은 현재 설정에서 제외한다.
- 최종 확인창의 문구·배치·연출 길이 같은 표현 세부는 미정이다. `WINDOW(2).exe`가 생기는 후보는 채택하지 않는다.

### 엔딩에 연결할 때 맞출 조건

- **[확정]** 보스를 휴지통에 넣는 것은 복원 취소이며, 직접 휴지통 비우기까지가 삭제 엔딩의 흐름이다. 두 행동을 같은 것으로 처리하지 않는다.
- **[확정]** 희생자들도 프로그램과 함께 삭제된다. 플레이어의 생존을 희생자 구출 성공으로 표현하지 않는다. 정상 바탕화면 복귀나 보스전 정리 때문에 삭제된 프로그램 아이콘·창·버튼을 다시 나타나게 하지 않는다.
- 보스전 완료 뒤 새 공격·다운로드·실패 판정이 남아 엔딩을 방해하지 않아야 한다. 상세 종료 규칙은 보스전 기획을 따른다.

## 10. 비주얼과 사운드

### 10-1. 비주얼 [제안]

- 주사선·노이즈가 모든 UI 위에 겹쳐 보여, 창까지 CRT 화면 속에 있는 것처럼 보이게 한다 (콘셉트 통일성)
- 창 테두리: 회색 Win98풍
- 아이콘 이름: 흰 글씨 + 검은 그림자
- **글꼴 [확정 — 사용자 지정]:** 현재와 이후 게임 화면의 모든 글자에 제공된 NeoDunggeunmo를 사용한다. 적용 방식은 개발 가이드의 공통 게임 글꼴 규칙을 따른다.
- 주사선·글리치·오염 효과를 적용한 상태에서도 필수 단서와 위험 표시를 읽을 수 있게 한다. 화면 효과가 버튼 클릭을 가로막지 않게 한다.

### 10-2. 오염도 단계별 화면 [제안]

| 단계 | 화면 |
|---|---|
| 0 (정상) | 파란 배경 |
| 1 | 채도·밝기가 낮아지고 노이즈 줄이 늘어남 |
| 2 | 붉은 기가 돌고 화면이 찢어지는 글리치 |
| 3 (1페이즈 오염 한계) | 짧은 글리치나 암전 뒤 1페이즈 재시작. 블루스크린을 필수로 두지 않음 |

위 표는 1페이즈 오염의 시각 표현 제안이다. 오염은 2페이즈로 이어지지 않는다. 2페이즈 피격은 오염 누적이나 전환 연출 대기 없이 즉시 리스폰하고, 다운로드 완료는 별도 배드 엔딩으로 종료한다. CRT 프리셋 단계 자체가 실패나 엔딩을 발생시키는 것은 아니다.

### 10-3. 사운드 [미정]

- 사운드 방향은 미정. 후보: CRT 험, 클릭음, 오류음, 글리치음, 앰비언트 BGM 1개.

## 12. 기획에서 결정이 필요한 것 [미정]

보스전의 확정 흐름·실패·엔딩은 다시 미정으로 열지 않는다. 2026-10-31 사용자 답변과 보스전 내부 쟁점은 [보스전 기획 13장](BOSS_FIGHT.md#13-결정이-필요한-것-미정)에서 관리한다. 다음은 보스전 밖에 남아 있는 기획 질문이다.

| 주제 | 결정할 질문 |
|---|---|
| 앞 퍼즐의 해법 | 파일 조사·사진 해제·벽 단서를 열쇠 획득에 어떻게 연결하는가? 단서 발견 순서나 창 재열기로 진행이 막히지 않는가? |
| 기록 전달 | 보스전 이전 기록에 현재 시점의 문구 변화를 사용할 것인가? 생존자와의 실시간 구출 대화로 해석되지 않는가? |
| 보스전 이전 위협·재시작 | 조사 퍼즐에도 시선 위협을 둘 것인가? 그 구간의 실패와 복구 범위는 무엇인가? 보스전 페이즈 저장 규칙과 구분한다. |
| 보스전 이전 엿보기 창 | 최대화·최소화·크기 조절을 어디까지 허용할 것인가? 보스전 창에는 보스전 기획의 조작 규칙을 적용한다. |
| 앞뒤 연출의 표현 | 복원·눈알 연출, 직접 휴지통 비우기의 성공 엔딩, 다운로드 완료의 별도 배드 엔딩 화면·문구·길이를 담당자가 구체화한다. 배드 엔딩의 자동 리스폰 없음과 성공 후 프로그램 재등장 없음은 확정이다. |
| 사운드 | CRT 험·클릭·오류·글리치·앰비언트 BGM 중 어떤 방향을 채택할 것인가? |
