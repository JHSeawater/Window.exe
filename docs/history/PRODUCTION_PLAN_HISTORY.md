# WINDOW.exe — 초기 제작 순서

> 2026-10-31 문서 정리 시 보존한 과거 기록이다. 당시 계획·확인 결과이며 현재 구현 완료를 뜻하지 않는다.
> 현재 기준과 진행 상태는 [원본 문서](../PRODUCTION_PLAN.md)에서 관리한다. 체크 표시는 당시 스냅샷으로 보존하며 이 파일에서 갱신하지 않는다.

## 5. 10/30 사용자 담당 구현 순서 [제안]

오늘의 결과물은 **아이콘을 선택·실행·이동할 수 있고, 배치와 입력 충돌이 처리되며, 창 시스템에 열기 요청을 전달하는 데스크톱**이다. 계획 보고 후 구현·검증과 커밋·푸시까지 진행했다. 아래는 작업 순서를 보존한 계획이며, 실제 확인 결과와 완료 상태는 [체크리스트](../IMPLEMENTATION_CHECKLIST.md)의 8장에서 관리한다.

| 순서 | 진행할 작업 | 확인할 결과 |
|---|---|---|
| 0. 작업 경계 준비 | 코드·프리팹·데이터·검증 씬의 배치와 공유 경로를 정하고, 팀원과 고정 식별자·열기 요청·화면 기준을 맞춤 | 창이 없어도 임시 수신기로 개발 가능. 제외된 스크립트 없이 씬만 공유되는 상황 방지 |
| 1. 데스크톱 뼈대 | 바탕화면과 아이콘 영역 구성, 아이콘 공통 프리팹·데이터 준비, 테스트 아이콘 3개 이상 배치 | 데이터에 따라 이름·이미지·식별자가 다른 아이콘이 보이며 초기 배치가 겹치지 않음 |
| 2. 선택과 열기 | 선택·선택 변경·빈 공간 선택 해제, 더블클릭 시 식별자 전달 | 임시 수신기에서 올바른 식별자를 한 번 받음. 표시 이름을 바꿔도 연결 유지 |
| 3. 드래그와 배치 | 이동 시작 거리, 잡은 지점 유지, 화면 좌표 변환, 경계 제한, 겹침 검사와 위치 확정 | 드래그 후 실행 오인 없음. 화면 안의 유효한 위치만 확정. 원위치 복귀 방식은 개발 가이드의 제안 |
| 4. 입력 충돌 확인 | 먼저 입력을 가로막는 테스트 패널로 가림 동작 확인, 이후 실제 창으로 재확인 | 창 클릭이 뒤쪽 아이콘·바탕화면에 전달되지 않고 창 조작이 아이콘 위치를 바꾸지 않음 |
| 5. 실제 창 연결 | 임시 수신기 대신 팀원 창 시스템에 열기 요청 연결 | 새 창 열기·기존 창 앞으로 가져오기·최소화 복원·닫은 뒤 재열기를 함께 확인 |
| 6. 최종 확인 | 체크리스트 순서로 조작하고 서로 다른 해상도·UI 배율과 실행 빌드에서 확인 | 확인한 작업만 완료 체크. 창 통합을 못 했다면 데스크톱 단독 확인과 통합 미확인을 구분해 기록 |

후속 작업은 팀원과 열기 요청·화면 기준을 맞추고 실제 창 시스템을 연결한 뒤, 중복 방지·최소화 복원·재열기·아이콘 위치 유지·입력 가림을 함께 확인하는 순서로 진행한다. 통합 뒤에는 테스트를 마친 다음 빌드를 만들어 같은 항목을 확인한다. 구현 구조와 연결 경계는 [개발 가이드 7~8장](../DEVELOPMENT.md#7-데스크톱-구현-구조와-처리-순서)에서 관리한다.

위 표는 최초 단일 선택 구현의 순서다. 후속 요청인 다중 선택은 아래 6장 순서로 추가 구현했다. 격자 정렬·우클릭·앱 재실행 후 위치 저장·실제 삭제 판정과 게임 퍼즐은 이번 추가 작업에 포함하지 않는다. 제공된 배경·아이콘은 공통 프리팹과 데이터에 이미 연결했으며, 추가 게임 콘텐츠와 리소스는 기존 후속 범위를 따른다.

## 6. 추가 구현 — 드래그 영역 선택

10/30 사용자 요청으로 수립한 계획을 이후 구현 요청에 따라 진행했다. 아래는 구현한 작업 순서이며, 완료 여부와 검증 결과는 [체크리스트 2-1장](../IMPLEMENTATION_CHECKLIST.md#2-1-추가-구현--드래그-영역으로-여러-아이콘-선택)과 9장에서 관리한다. 추가 구현과 역할별 정리는 이번 공유 변경에 포함한다.

| 순서 | 작업 | 확인할 결과 |
|---|---|---|
| 1. 선택 상태 확장 | 컨트롤러의 단일 선택을 선택 집합과 대표 아이콘으로 확장. 누르기·클릭 완료·드래그 시작의 처리를 분리 | 기존 단일 클릭·더블클릭을 유지하고 여러 아이콘을 동시에 강조할 수 있음 |
| 2. 선택 상자와 판정 | 빈 바탕화면의 드래그 입력, 사방향 사각형 계산, 실시간 교차 판정, 입력을 막지 않는 표시 추가 | 작은 흔들림은 클릭, 충분한 이동은 영역 선택. 놓은 뒤 선택 유지 |
| 3. 입력 충돌·취소 처리 | 아이콘에서 시작한 드래그와 영역 선택을 구분. 클릭 연속 상태 초기화, 포커스 상실·Escape·비활성화 시 복원 | 선택 상자가 남지 않고 의도하지 않은 열기 요청이나 창 조작이 발생하지 않음 |
| 4. 선택 후 이동 보완 | 선택된 아이콘을 누를 때 집합 유지, 이동 없이 놓으면 단일 선택. 이어서 상대 간격을 유지하는 묶음 이동 구현 | 다중 선택이 드래그 시작과 동시에 풀리지 않음. 경계는 묶음 전체로 제한하고 충돌 시 전부 복귀 |
| 5. 확인과 문서 갱신 | 추가 테스트와 기존 14개 테스트 회귀 확인 후 Windows 빌드·수동 조작. 실제 팀원 창 연결 여부도 구분 | 1280×720·1920×1080에서 선택 상자·배율·묶음 배치 확인. 검증한 항목만 완료 표시 |

영역 선택과 묶음 이동을 연결하고, 공유 씬의 두 해상도 입력 시험까지 수행했다. 다음 우선순위는 7장의 최소 작업 표시줄과 실제 창 통합이다. Ctrl·Shift·Ctrl+A, 격자 정렬, 다중 실행·삭제는 별도 후속 범위로 둔다. 세부 입력·충돌 규칙과 변경 파일은 [개발 가이드 9장](../DEVELOPMENT.md#9-드래그-영역-선택-구현)을 따른다. 창 이동·크기 조절·최대화·최소화는 팀원 담당을 유지한다.

후속 사용자 요청으로 Assets 역할별 정리도 수행했다. 새 코드·에셋은 [개발 가이드의 폴더 배치](../DEVELOPMENT.md#assets-폴더-배치-확정--사용자-지정)를 따르며, 이동 재검증은 [체크리스트 10장](../IMPLEMENTATION_CHECKLIST.md#10-assets-역할별-정리와-재검증)에서 관리한다. 게임 기능의 우선순위와 담당은 유지한다.

## 8. 창·데스크톱 호환 구현 순서 [제안]

사용자의 계획 수립 요청으로 `0962ce4`를 기준으로 정리하고 2026-10-31 검수 반영 요청으로 순서·종료 기준을 보완했다. Git 병합을 다시 하는 작업과 실제 시스템을 연결하는 작업을 구분한다. 새 원격 변경이 추가되면 시작 전 차이만 확인하고, 이미 보존한 두 커밋의 기능을 다시 대체하지 않는다. 이후 사용자 착수 요청으로 구현했다. 아래 표는 진행 순서의 원안이며 실제 결과와 남은 검증은 체크리스트 12장에서 관리한다. 시간별 일정 확정을 뜻하지 않는다. 3장의 기존 10/30 시간표를 현재 범위의 마감으로 자동 적용하지 않는다.

| 순서 | 작업 묶음 | 다음 단계로 넘어갈 기준 |
|---|---|---|
| 0. 기준선 복구 | 병합 후 컴파일·씬·에셋·TMP 의존성과 리사이즈 핸들의 저장 참조 확인 | 실제 컴파일 오류와 도구 시간초과를 구분하고, 씬/프리팹을 다시 열어도 Missing Script 없이 검증 시작 가능 |
| 1. 창 하나의 표시 | Camera 데스크톱·월드 창 루트·Overlay 작업 표시줄 구성, 메모 검증 프리팹·본문·제목 준비 | 본문과 제목이 배경/아이콘보다 앞·바보다 뒤에 보임. 카메라와 Canvas 참조·동적 글꼴을 명시 |
| 2. 실제 최소 연결 | 관리자 인스턴스 ID·목록·활성 상태/기본 알림과 단일 런처·실제 어댑터 연결. 해당 흐름의 최소 입력 소유권 검사 적용 | 메모 아이콘 → 실제 창 → 버튼 하나 → 최소화 → 버튼/아이콘 복원 → 닫기 완주. Probe 직접 Open·DemoSource 중복 구독 없음 |
| 3. 입력 소유권 확장 | 두 번째 검증 창을 등록하고 관리자 순서와 실제 렌더러 순서를 연결해 최상위 판정. UI/Update 공통 승인·제목 버튼 영역 분리·해제 시 실행·취소 연결 | 앞 창과 입력 대상 일치, 뒤 UI 클릭 차단, 버튼 가장자리·드래그 통과·임계값·취소 후 해제/포커스 복귀 처리 확인 |
| 4. 좌표·리사이즈 제약 | 공통 월드 영역·카메라 변경 갱신, 반대편 경계를 고정하는 크기/위치 동시 계산, 최대화/복원·작은 화면 예외 | 8방향 크기 제한에서 점프 없고 해상도/투영 변경 후에도 새 경계·바 제한·저장한 복원 상태가 유효 |
| 5. 다중 창·수명 예외 | 네 ID·한글/본문 범위·Secondary 캡처, 정책·알림·재구독/파괴 정리 확장과 창별 정렬 회귀 | 두 창의 제목/본문이 섞이지 않고 캡처 기대 결과 확인. 같은 프레임 닫기/재열기의 이전 정리가 새 창을 제거하지 않음 |
| 6. 공유 씬·회귀 | 기존 자동 시험을 실제 창/어댑터에 맞추고 다중 창·입력·좌표·정책·수명 사례 회귀 | 두 해상도와 비율 변경에서 전체 핵심 흐름·가림·8방향 리사이즈·기존 아이콘 동작 확인. 테스트 설정 원복 |
| 7. 실행 파일·인계 | Windows 빌드·시작·직접 마우스 확인과 씬/메타/문서 마무리 | 검증한 내용과 남은 게임 통합을 구분해 인계하고 파일 조사/비밀번호 작업으로 진행 가능 |

첫 화면 확인은 메모장 본문·제목의 표시이며, 그 직후 **메모 아이콘 → 실제 창 → 실제 작업 표시줄 → 최소화/복원 → 닫기**의 작은 흐름을 완주한다. 단계 1에서 코드로 생성해 표시를 확인하더라도 단계 2는 실제 아이콘과 버튼 입력으로 확인한다. 이 연결의 관리자 상태·표시 순서를 뒤 입력 판정의 원본으로 사용하며 임시 모델로 이중 관리하지 않는다. 전체 완료는 3~7의 확장·예외·회귀·빌드 확인까지 마친 상태다.

변경은 기준선/직렬화 → 창 하나의 표시 → 실제 최소 연결 → 입력 → 좌표 제약 → 다중 창/수명 → 회귀/빌드/문서처럼 검토 가능한 단위로 나누는 안이다. 각 단위에서 관련 검증을 마치고 다음으로 진행하며, 커밋·푸시는 사용자 요청을 따른다. 작은 화면·창 겹침·소유 입력 문제가 남은 상태에서 퍼즐 로직을 먼저 얹지 않는다.

기술 설계와 예상 변경 파일은 [개발 가이드 10장](../DEVELOPMENT.md#10-창데스크톱-호환-구현-계획-제안), 실제 진행·완료 조건은 [체크리스트 12-1장](../IMPLEMENTATION_CHECKLIST.md#12-1-실제-호환-구현과-완료-조건-제안)을 원본으로 관리한다. 일반 창 검증에서의 최대화·최소화 허용을 엿보기 창의 게임 규칙으로 확정하지 않는다.

## 10. 전체 검수 문제 수정 순서 [제안]

2026-10-31 작성한 수정 순서의 원안이다. 후속 사용자 지시로 검토 보완을 포함해 이 순서에 따라 구현에 착수했고, 실제 완료·검증 결과는 체크리스트 15-4장에서 관리한다. 시간별 마감이나 시작 버튼/게임 콘텐츠의 영구 우선순위는 변경하지 않는다.

| 순서 | 작업 단위 | 다음 단계로 넘어갈 기준 |
|---|---|---|
| 0 | 기존 변경 보존·공유 회귀 사례 준비 | 현재 코드/씬을 보존하고 세 재현이 수정 전 코드에서 실패함을 확인. 이전 63개 통과와 새 실패를 구분 |
| 1 | QA-01 일반 크기·전체 취소 상태 보존 | 작은 영역의 이동/취소 뒤 일반 상태를 유지하고 명시적 리사이즈의 변경 축·최대화/최소화 결합 사례 통과 |
| 2 | QA-02 외형 재설정의 정렬·알림 보완 | 창의 활성/최근 순서를 유지한 채 실제 렌더링과 입력이 일치하고 작업 표시줄 메타데이터가 동기화됨 |
| 3 | QA-03 창 평면 갱신·조작 취소 | 평면 Z 단독 변경의 영역 일치와 입력 취소를 확인. 단계 1의 취소 상태 보존을 함께 회귀 검증 |
| 4 | 전체 시험·지정 씬 빌드·직접 조작·문서 반영 | 기존/신규 회귀, 두 해상도의 입력·기동, 실제 환경의 실행 파일 직접 조작을 확인하고 남은 검증을 구분해 보고 |

각 문제를 재현 사례 → 구현 변경 → 관련 검증의 단위로 진행하고 모두 모아 전체 회귀를 실행한다. QA-01에는 공개 절대/상대 리사이즈 계약, QA-03에는 유효 → 무효 → 복구의 취소·좌표 사용·알림 규칙도 포함한다. QA-02·03은 기본 UI에서 잘 드러나지 않더라도 이번 세 문제의 수정 결과에서는 제외하지 않는다. 코드 변경이 없는 문서 계획을 수정 완료로 표시하지 않는다.

기술 원본은 [개발 가이드 13장](../DEVELOPMENT.md#13-전체-검수-문제-수정-계획-제안), 담당 경계·작업·완료 조건은 [체크리스트 15-4장](../IMPLEMENTATION_CHECKLIST.md#15-4-수정-작업과-완료-조건-계획)을 따른다. 기본 SampleScene 설정은 기존의 Desktop 씬 명시 빌드 규칙으로 처리한다. 시작 버튼은 9장, 퍼즐·엔딩은 7장의 별도 범위로 유지한다.
