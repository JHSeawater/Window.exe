# WINDOW.exe — 보스전 개발 기획

> **역할:** 보스전의 규칙, 구성, 수치, 화면 신호, 완료 조건을 정의하는 개발 기획 문서. 구현 계획을 세우는 사람이나 AI가 **이 문서만 읽고도 보스전이 어떻게 동작해야 하는지** 이해할 수 있도록 쓴다.
> **기준일:** 2026-10-31 (2페이즈 즉시 리스폰·다운로드 유지·다운로드 완료 배드 엔딩 반영). **담당:** 정해수 (보스전 개발)
> **범위:** 무엇이 어떻게 동작해야 하는지만 정한다. 구현 방법, 구조, 코드는 다루지 않는다.
> 게임 전체 기획은 [GDD](GDD.md), 기술 방식은 [개발 가이드](DEVELOPMENT.md), 일정은 [제작 계획](PRODUCTION_PLAN.md)을 따른다.
> **[확정 — 사용자 지정] 설정 충돌 시 이 문서가 현재 기준이다.** GDD에 같은 설정을 맞추되, 이 문서 안의 제안 수치와 남은 미정 사항을 자동으로 확정하지 않는다.

### 표기 규칙 (GDD와 동일)

- **[확정]** 팀에서 합의했거나 보스전 담당자가 지정한 내용. 임의로 바꾸지 않는다.
- **[제안]** 프로토타입으로 검증했거나 기본값으로 제안하는 내용. 이 값으로 만들되 나중에 바꿀 수 있어야 한다.
- **[미정]** 아직 결정되지 않은 내용. 임의로 확정하지 않는다.

## 0. 이 문서로 구현 계획을 세울 때 지킬 것

1. **[확정]** 항목은 바꾸지 않는다. **[제안]** 항목은 적힌 기본값으로 구현한다. **[미정]** 항목은 스스로 결정하지 말고 계획에 "결정 필요"로 표시한 뒤, 13장의 "결정 전 임시 처리"를 따른다.
2. 7장의 수치와 8장의 유언 문구는 플레이 테스트를 하면서 자주 바뀐다. 수치나 문구를 바꾸려고 규칙이나 흐름을 다시 만들어야 하는 일이 없어야 한다.
3. 창의 이동, 크기 조절, 최소화, 작업 표시줄 복원, 닫기는 **다른 팀원이 담당하는 창 시스템**의 기능이다. 보스전에 필요한 변경(12장)은 창 담당자와 먼저 합의한다.
4. 보스 아이콘 아트와 사운드는 **따로 준비 중**이다. 들어오기 전에는 임시 이미지로 작업하고(사운드는 없이), 나중에 교체·추가만 하면 되게 한다.
5. **[확정 — 최신 사용자 지시] 2페이즈 배경의 안내·유언 문구는 표시하지 않는다.** 시각 신호와 지정된 Spacebar 이미지 안내(8-2)를 사용하며 기존 시스템 오류·진입 연출 이미지는 유지한다.
6. 9장의 우선순위대로, 매 단계가 **실제로 플레이 가능한 상태**가 되도록 작은 단위로 완성해 나간다.
7. 완료 여부는 11장의 검증 항목으로 판단한다.
8. 이 문서와 프로토타입(14장)이 다르면 **이 문서를 따른다.**

## 1. 개요

### 1-1. 한 줄 요약 [확정]

탈출한 **진짜 WINDOW.exe(보스)**를, 플레이어가 복제본 창 **WINDOW(1).exe**와 그 안의 **휴지통**을 이용해 다시 휴지통에 넣어 삭제하는 클라이맥스 전투.

### 1-2. 게임 안에서의 위치

**보스전 전후 흐름 [확정 — 기획 담당 흐름]:**

1. **열쇠 획득:** 앞 퍼즐에서 열쇠를 얻는다.
2. **휴지통 내부 WINDOW.exe 실행:** 파일을 더블클릭하면 `Warning/Lock` 권한 경고창이 열린다. 기존 복원 창은 사용하지 않는다.
3. **자물쇠 해제 → 버튼 확인 → 강제 다운로드 시작 [확정 — 최신 사용자 지시]:** 경고창의 자물쇠 그림에 열쇠를 사용하면 `Warning/Unlock`으로 전환된다. Lock의 확인/X는 창을 닫는다. Unlock의 확인/X를 누르면 창을 유지한 채 3초 기다린 뒤 기존 다운로드 진입 연출을 시작한다. 열쇠 사용만으로는 진입하지 않는다. 클릭 당시 화면을 다운로드·눈·오류·One_more까지 배경으로 보존한다. One_more가 끝나 1페이즈로 넘어갈 때 기존 검은 배경으로 바꾸고, 1초 대기 후 커맨드 문구를 출력한다. 포커스 이탈·앱 일시 중단 중에는 대기도 멈춘다. 이 3초는 다운로드 창 자체의 3초 표시와 별개다. 구현·확인 상태는 체크리스트 39장에서 관리한다.
4. **눈알 연출 (다운로드 일시 정지):**
   - 눈알 하나가 괴로워하며 진실을 알린다.
   - 화면이 확 축소되면서 갇혔던 사람들의 눈알이 전부 나열되고, 모두 피눈물을 흘린다.
   - 프로그램이 눈알들을 지지직거리며 지워 버린다. 연출적인 장면이며, 보스전의 눈은 그와 별개로 다시 생성된다.
5. **보스전:** 목표는 다운로드가 끝나기 전에 복원을 취소하고 휴지통을 비우는 것이다. 다운로드 규칙은 6-6.
   - 보스(진짜 WINDOW.exe)를 휴지통에 다시 넣는 것이 **복원 취소**다.
6. **엔딩:** 복원 취소 뒤 **플레이어가 직접 휴지통 비우기를 실행**한다. 이미 눈알이 된 희생자들과 프로그램이 전부 삭제되고 정상 바탕화면으로 돌아온다. **프로그램 재등장은 없다 [확정 — 사용자 답변].**

- 보스전 직전 연출(3~4)은 합쳐서 **20초 안팎**으로 짧게 한다 [제안]. 발표가 5분이기 때문이다.
- **[확정 — 최신 사용자 지시] 2페이즈의 눈 접촉은 재도전 화면 없이 시작 지점으로 즉시 리스폰한다. 다운로드 진행도·남은 시간은 유지하고 계속 진행한다. 다운로드가 100%가 되면 별도 배드 엔딩으로 진입하며 리스폰하지 않는다.** 피격 리스폰과 최종 배드 엔딩을 구분한다 (3-5, 6-6).
- 보스전 후 직접 휴지통 비우기와 정상 바탕화면 복귀·재등장 없음은 **[확정]**이다. 확인창·문구·연출 길이 같은 표현 세부만 **[미정]**이다 (13장).

### 1-3. 세계관 설정 (보스전 관련) [확정]

- **복제본의 이름은 `WINDOW(1).exe`다.** 파일을 복사했을 때처럼 이름 뒤에 `(1)`이 붙어 있어서, 복사본이라는 티가 난다. 보스는 진짜 `WINDOW.exe`다.
- **눈은 모두 WINDOW.exe에 당한 이전 희생자들이다.**
  - 창 안의 세계에는 **생존자가 없다.** 모두 죽었다.
  - 창 안 세계의 낙서는 모두 희생자들이 남긴 **유언**이다.
  - 희생자들은 살아남으려고 알아낸 것을 벽에 남겼다. 그래서 유언이 곧 플레이어를 위한 **안내** 역할을 한다 (8-2).
- **게임 오버는 플레이어가 창 안의 세계에 갇히는 것이다.**
- GDD와의 정합성: 사용자 지시에 따라 "생존자 없음"·기획 흐름(1-2)·실패/재시작·엔딩을 GDD에 맞췄다. 과거 구출·자리 교환 경로와 반환 순서를 현재 삭제 조건으로 사용하지 않는다.

### 1-4. 디자인 의도

- GDD의 차별화 포인트인 **"창이 곧 시야"**를 게임에서 가장 강하게 보여주는 구간이다.
- **핵심 갈등 [확정]:** 창이 클수록 한 번에 멀리 전진하지만 눈에 걸리기 쉽다. 창의 크기와 모양을 바꾸는 것이 곧 무기이자 약점이다.
- **두 페이즈 [확정]:**
  - **1페이즈:** 창 안에서만 보이는 고정된 눈 사이를 피해 휴지통을 끌고 가서 보스를 공격한다. **시간 제한이 없다.**
  - **2페이즈:** 보스가 직접 눈을 날려 공격한다.
- **두 페이즈의 성격:**
  - 1페이즈는 **정밀함**이다. 시간 압박 없이 창 크기와 이동 위치를 골라 고정 눈을 피하는 퍼즐이다.
  - 2페이즈는 **타이밍**이다. 같은 조작을 날아오는 공격을 피하면서 하고, 최소화로 회피한다.
  - 두 페이즈가 같은 조작을 반복하는 느낌이 나지 않도록 이 차이를 유지한다.
- **목표 길이 [제안]:** 처음 하는 사람 기준 1페이즈 약 1~1.5분, 2페이즈 약 1분이다. 전체 발표가 5분이므로 보스전 전체는 2분 30초 안쪽이어야 한다.

## 3. 공통 규칙 (두 페이즈 모두)

### 3-1. 화면 구성 [제안]

- 보스전이 시작되면 바탕화면 아이콘과 다른 창은 모두 사라진다.
- 화면에 남는 것:
  - 창 `WINDOW(1).exe` 하나와 그 안의 휴지통
  - 반대편 끝의 보스 아이콘
  - 작업 표시줄 (`WINDOW(1).exe` 버튼 하나만)
  - 작업 표시줄 오른쪽의 다운로드 칸 막대 (6-6). 보스전 중에는 다운로드 대화 상자를 화면에 띄우지 않는다.
- **[확정 — 사용자 지정] 페이즈별로 배경을 다르게 표시하며 `Phase_1.png` 원본을 함께 사용한다.**
  - **1페이즈 배경:** 어두운 바탕화면의 좌상단에 시스템 오류 명령 로그가 한 줄씩 쌓인다 [확정 — 사용자 지정]. 문구와 출력 방식은 아래를 따른다.
  - **2페이즈 배경:** 1페이즈 숨은 층에서 쓰던 `Assets/Art/Screen/Phase_1.png`를 WINDOW.exe 창 바깥의 배경에 표시한다. 원본 비율을 유지해 작업 영역을 덮고 화면에 고정한다. 창 본문은 파란 정상 바탕화면을 유지하며, 분위기 유언(8-2)은 별도로 겹쳐 표시한다.
  - 1페이즈에서 2페이즈로 넘어갈 때 배경이 바뀐다 (5장).
- **[확정 — 사용자 지정] 두 페이즈 모두 평상시 기본 가로 노이즈를 크게 줄인다.** 현재 보스전 수치는 가로 줄 밝기 20%·발생 빈도 25%·촘촘한 주사선 35%다. 피격·전환 순간의 짧은 Spike 효과는 유지하며, 보스전 종료·엔딩 인계 후에는 원래 기본 설정을 사용한다.
- 방향: 휴지통은 화면 왼쪽에서 시작하고, 보스는 오른쪽에 있다.
- **진행도 표시는 없다 [확정].** 플레이어가 얼마나 왔는지 보여 주는 막대는 없다. 작업 표시줄의 다운로드 칸 막대(6-6)는 남은 시간을 보여 주는 것이라 별개다.

**1페이즈 창 밖 명령 로그 [확정 — 사용자 지정]**

- 창 밖의 어두운 배경 좌상단에서 아래 순서대로 한 줄씩 출력한다. 실제 명령어 창처럼 왼쪽 정렬로 쌓고, 긴 항목은 현재 글자 크기로 화면 폭에 맞게 줄바꿈한다. 화면 높이를 넘으면 오래된 항목부터 위로 밀어 올리고, 출력 완료 후 마지막 화면을 유지한다. 창에 가려진 부분은 보이지 않는다.
- 현재 연출 수치는 좌상단 여백 32×28, 글자 크기 34(초기 26 대비 약 31% 확대), 줄 간격 추가 4, 출력 간격 0.65초다. 첫 줄은 즉시 출력하며 90개 항목의 마지막 문구는 약 57.85초에 나타난다. 이 수치는 조정 가능한 구현값이며, 1페이즈 재시작 때 첫 줄부터 다시 출력한다.

### 3-2. 전진 규칙 — 창으로 휴지통을 옮긴다 [확정]

- 휴지통은 **창 본문 안에서만** 끌 수 있다. 창 밖으로 끌어낼 수 없고, 본문 가장자리에 닿으면 거기서 멈춘다.
- 휴지통은 화면에 고정된 물체다. 창을 움직여도 휴지통은 따라오지 않는다.
- **창은 항상 휴지통을 품는다.**
  - 창의 이동과 크기 조절은, 휴지통이 본문 안에 7장의 여백을 두고 남아 있는 범위까지만 가능하다.
  - 그 범위를 넘으려는 이동이나 크기 조절은 경계에서 멈춘다.
  - 앞길을 미리 보고 싶으면 창을 앞쪽으로 **늘려서** 본다. 크게 늘릴수록 눈에 걸리기 쉬워지는 갈등이 그대로 유지된다.
- **전진 루프:**
  1. 창을 진행 방향으로 늘리거나 옮겨서, 휴지통이 본문의 뒤쪽 끝에 오게 한다.
  2. 휴지통을 본문의 앞쪽 끝까지 끈다.
  3. 반복한다.
- 창 이동은 제목 표시줄 드래그, 크기 조절은 가장자리와 모서리 드래그(8방향)다. 기존 창 시스템과 같다.
- **[확정 — 조작 피드백]** 보스전 창의 가장자리·모서리는 테두리 바깥에서도 여유 있게 잡을 수 있게 한다. 확대는 바깥쪽에 적용하고 제목 이동·버튼·본문 드래그의 안쪽 영역은 유지한다. 잡는 범위는 눈 충돌 판정이나 실제 창 크기에 포함하지 않는다. 적용 수치는 개발 가이드 17-10장에서 관리한다.
- 창의 크기는 7장의 최소·최대 범위 안에서만 바뀐다.
- **[확정 — 수동 플레이 후 사용자 결정] 두 페이즈 모두 최소 본문 면적 제한이 없다.** 각 축 최소 길이 90·최대 크기·휴지통 포함 조건만 적용하며, 한 축을 줄이기 위해 다른 축을 먼저 늘리지 않아도 된다. 1페이즈도 90×90 창으로 완주할 수 있고 모양 변경 횟수를 강제하지 않는다.
- 창 프레임 전체는 항상 화면 안(작업 표시줄 위 영역)에 있어야 한다.

### 3-3. 입력 우선순위 [제안]

누른 지점에 여러 대상이 겹치면 아래 순서로 하나만 반응한다.

1. 작업 표시줄의 `WINDOW(1).exe` 버튼 (최소화·복원)
2. *(창이 최소화된 상태라면 아래는 모두 무시한다)*
3. 빨간 X 버튼
4. 최소화(_) 버튼
5. 창 가장자리·모서리 (크기 조절)
6. 보스 아이콘 (포획 상태일 때만)
7. 휴지통
8. 제목 표시줄 (창 이동)

- 드래그를 시작하면 버튼을 놓을 때까지 같은 대상을 계속 조작한다.
- **Space 키**는 위치와 상관없이 최소화·복원을 토글한다. 두 페이즈 모두 같다 (6-2).
- 작업 표시줄의 다운로드 칸 막대는 입력을 받지 않는다 (6-6).
- 이 절의 순서는 같은 누름 지점에서 대상을 고르는 공간 우선순위다. 서로 다른 요청·충돌이 같은 시각에 발생한 경우의 시간 우선순위는 3-5를 따른다.

### 3-4. X 버튼 [확정 — GDD 3장]

- 창의 빨간 X는 강제 종료다. 누르면 즉시 갇힌다.
- 색상 외에도 위험하다는 것을 알 수 있어야 한다 (GDD 3-3). 2페이즈에는 경고하는 유언도 둔다 (8-2).

### 3-5. 갇힘과 재시작 [확정]

**[확정 — 최신 사용자 지시] 재도전 가능한 실패와 다운로드 완료의 최종 배드 엔딩을 분리한다.**

| 상황 | 처리 | 다운로드 |
|---|---|---|
| 1페이즈 오염 3 또는 X | 기존대로 1페이즈 시작 상태로 재시작. 짧은 전환은 1초 이내 [제안] | 1페이즈 저장 시점 값으로 복구 |
| 2페이즈 눈 접촉 | 별도 재도전 화면·이유·버튼·암전 대기 없이 2페이즈 시작 순간으로 즉시 리스폰 | 피격 직전 진행도와 남은 시간 유지, 리스폰 중에도 계속 진행 |
| 2페이즈 X | 기존 X 실패와 2페이즈 시작 지점 복귀를 유지. 일반 리스폰과 같은 다운로드 유지 규칙 적용 | 되돌리거나 일시 정지하지 않음 |
| 2페이즈 다운로드 완료 | 별개의 배드 엔딩으로 진입. 리스폰 없음 | 100%에서 종료 상태로 확정 |

- **2페이즈에서 리스폰해도 1페이즈를 다시 하지 않는다.** 죽음을 반복해도 새 제한 시간을 주지 않는다. 여러 번의 시도에 걸쳐 다운로드가 계속 쌓이고, 시간이 다 되면 배드 엔딩이다.
- **시작 상태로 되돌리는 전투 항목:** 창 위치·크기, 휴지통·보스 위치, 모든 눈, 공격 순서·진행·난수 상태, 벽 발생 기록·예고, 오염/노출, 최소화·포획·진행 중 드래그. 다운로드 진행도·누적 경과 시간은 2페이즈 전투 체크포인트의 복구 대상에서 제외한다.
- 2페이즈에서는 짧은 글리치·암전 연출을 기다린 뒤 리스폰하는 방식도 사용하지 않는다. 시작 지점과 공격의 초기 상태를 즉시 복구해 바로 다시 플레이할 수 있어야 한다.
- 리스폰 직후 이전 시도의 예고·연출·지연 콜백이 나타나면 안 된다. 반대로 다운로드의 세션 시간까지 초기화하거나 타이머를 중복 실행해서도 안 된다.
- 다운로드가 완료된 경우에는 피격 리스폰 경로에 들어가지 않는다. 완료와 피격이 겹쳐도 배드 엔딩을 한 번만 확정한다.
- **[확정 — 추가 검토 사용자 답변] 2페이즈에서 같은 판정 시각의 우선순위는 다운로드 만료 → 위험한 X → 유효한 최소화 → 눈 피격 → 성공 드롭이다.** Space 최소화와 눈 접촉이 정확히 동시이면 최소화하여 피한다. 최소화보다 먼저 일어난 피격까지 취소하지 않는다. 정확한 만료 시각의 드롭은 성공이 아니며 기존 만료/X 우선 규칙을 유지한다. 1페이즈에서는 해당하는 실패와 첫 드롭 사이에 실패를 우선한다. 서로 다른 시각은 발생 순서로 처리하고 먼저 확정한 성공/배드 엔딩은 뒤집지 않는다.
- 위 최소화 우선은 **표시 중인 창을 최소화하는 요청**에 적용한다. 이미 최소화된 창을 Space로 복원할 때에는 현재 눈과의 겹침을 즉시 검사하며 회피 판정으로 취급하지 않는다. 최소화가 성립하면 진행 중 드래그와 같은 시각의 드롭 후보는 취소되어 성공을 발생시키지 않는다.
- **[확정 — 추가 검토 사용자 답변] Escape·포커스 상실의 취소 복원은 순간 복원이다.** 기존 드래그 시작 상태 복원은 유지하되 되돌아가는 가상 경로의 눈은 검사하지 않고 도착 상태의 겹침만 판정한다. 2페이즈는 표시 중인 도착 프레임이 눈과 겹치면 즉시 피격한다. 1페이즈는 도착 본문에 기존 공통 노출·굳음 규칙을 적용하며, 취소 자체를 노출 시간 초기화로 사용하지 않는다.
- 앱 포커스 상실/일시 중단과 6-6의 좌표 공간 무효 정지 중에는 전투 판정도 정지한다. 취소로 위치가 복구되어도 정지 중 피격을 실행하지 않으며, 모든 정지 사유가 해제된 뒤 새 시간 진행 전에 도착 상태를 검사한다. 게임 속 창이 최소화된 동안에는 기존대로 눈 판정이 없다.
- 리스폰은 이전 조작을 끝낸다. 누른 채 유지한 마우스/Space나 이전 시도의 남은 해제가 새 시도의 드래그·드롭·최소화로 이어지지 않아야 하며, 해제 후 첫 새 누름부터 바로 플레이할 수 있어야 한다.
- 별도 배드 엔딩의 화면·문구·연출과 그 이후 새 게임을 시작하는 UI는 엔딩 담당과 정한다 (13장). **자동 리스폰 없음**은 확정이며, 배드 엔딩을 피격용 재도전 화면으로 대신하지 않는다.

### 3-6. 보스 아이콘

- **[확정] 아이콘 아트는 따로 제작 중이다.** 이 문서는 동작만 정한다.
- 아트에 바라는 조건 [제안]:
  - 플레이어의 `WINDOW(1).exe` 창과 한눈에 구별된다.
  - 작게 보여도 위치를 놓치지 않는다.
- 동작 [제안]:
  - 항상 보인다. 플레이어가 가야 할 목표다.
  - 붉은 빛이 맥동하고, 가끔 위치가 떨린다. 아트에 눈이 있다면 그 눈이 창 쪽을 본다.
  - 아이콘 이름이 글리치되며 바뀐다: `WINDOW.exe` → `W1ND0W.exe` → `WIN▒OW.exe`
- **포획:** 보스 아이콘의 중심이 창 본문 안(가장자리에서 7장의 여백만큼 안쪽)에 들어오면 포획 상태가 되고, 이때만 아이콘을 끌 수 있다.
- **휴지통에 넣기:** 끌어서 휴지통 위(7장의 판정 거리 이내)에 놓으면 삭제를 시도한다. 결과는 페이즈마다 다르다 (4-5, 6-5).
- **잘못 놓으면:** 다른 곳에 놓으면 보스 아이콘이 원래 자리로 미끄러지듯 돌아간다.

## 4. 1페이즈 — 눈을 피해 가는 공간

### 4-1. 목표와 분위기

- **목표:** 고정된 눈 사이의 빈 공간을 선택해 휴지통을 보스 앞까지 데려가고, 보스를 휴지통에 넣는 첫 번째 공격을 한다.
- **[확정] 시간 제한이 없다.**
- **[제안] 눈은 움직이지 않고, 날아오는 공격도 없다.** 플레이어가 창 늘리기, 휴지통 끌기, 창 모양 바꾸기를 처음 익히는 구간이다.

### 4-2. 보이는 것 [확정]

- **[확정 — 사용자 지정] 진입 연출:** 보스전 최초 진입 시 제공된 `Downloading.png` 창을 중앙에 표시하고, “다운로드 중입니다...” 아래에 작업표시줄과 같은 20칸 형태의 막대에서 첫 한 칸만 차오른 뒤 유지한다. 다운로드 창을 먼저 약 3초 보여 주고 그대로 남긴 상태에서 그 위에 제목바가 포함된 `Boss_Start_Eyes-title-bar.gif` 눈 이미지 창 15개가 화면 전반에 겹침을 포함해 빠르게 연속 등장하며 좌우 가장자리·상단 중앙·하단의 빈 공간도 덮는다. 15개가 모두 뜬 뒤 처음의 빨간 눈 화면을 함께 2초 유지하고, 모든 창의 GIF를 같은 시점·같은 프레임으로 한 번씩 재생한다. 재생이 모두 끝나면 기존처럼 생성 순서대로 같은 위치에서 `Error.png` 창으로 바뀐다. 마지막 오류 표시를 잠시 유지한 뒤 에러창 15개를 그 위치에 그대로 둔 상태에서 `One_more` 경고 이미지를 화면 중앙 맨 앞에 크게 표시한다. 약 1.5초 뒤 중앙 경고 이미지·에러창·다운로드 창을 함께 정리하고 1초간 기다린 다음 기존 어두운 배경의 커맨드 문구를 약 2초간 먼저 출력한다. WINDOW.exe 아이콘과 이름은 중앙 이미지가 사라지는 순간부터 표시하고, 2초가 지나면 복제본 창·휴지통을 표시하며 1페이즈 조작을 시작한다. 문구는 시작 후에도 이어서 출력한다. 연출 중에는 조작·오염·다운로드 진행을 막고 포커스 상실·일시 중단 중에는 연출도 멈춘다. 이미지 속 버튼은 연출이며 클릭을 기다리지 않는다. 1페이즈 재시도와 2페이즈 단독 진입에서는 반복하지 않는다.

- **창 본문 안:** 숨은 층이 보인다. **숨은 층 배경은 사용자 지정 [Phase_1.png](../Assets/Art/Screen/Phase_1.png)를 사용한다 [확정].** 원본 비율을 유지해 숨은 공간에 고정하고, 창으로 비추는 부분만 보여 준다. 그 위에 희미한 격자, 확대된 눈 그림, 휴지통을 그린다. 별도의 원형 시야 경계는 표시하지 않는다. **1페이즈 숨은 층에는 유언·조작 안내 등 글자를 표시하지 않는다 [확정 — 사용자 지정].** 이미지의 창 밖 부분은 보이지 않으며 창 밖의 기존 어두운 배경은 유지한다.
- **1페이즈 고정 눈 아트 [확정 — 사용자 지정]:** [눈깔풀.png](../Assets/Art/Screen/눈깔풀.png) 위에 [빨강이.png](../Assets/Art/Screen/빨강이.png)를 동공으로 겹친다. 눈의 자리는 고정하고 동공만 플레이어가 조작하는 창의 중심을 따라 움직인다. 두 파일의 실제 위치는 `Assets/Art/Screen/`이며 `Temp/` 하위가 아니다.
- **[확정 — 사용자 변경]** 원형 시야 경계를 없애고 눈 이미지를 기존 시야 지름만큼 키운다. 눈깔풀은 기존 192×128에서 250×166.67로, 동공은 72×48에서 93.75×62.5로 확대한다. 원본 비율을 유지하며 눈 그림의 실제 외곽에 본문이 닿으면 접촉으로 판정한다. 투명한 모서리와 별도의 보이지 않는 원은 접촉 범위가 아니다. 동공 추적은 유지하고, 보이는 크기와 접촉 범위가 달라지지 않도록 눈은 고정 크기로 완전히 열린 상태를 유지한다.
- **창 밖:** 명령 로그가 출력되는 1페이즈 배경(3-1)과 보스 아이콘이 보인다. **눈과 숨은 층 배경은 창으로 비춰야만 보인다.** 회색 길은 표시하지 않는다.
- **보스 아이콘은 1페이즈 내내 보인다 [제안].** 창 밖에서도, 창이 보스 위를 지날 때도 맨 위에 보인다. 플레이어는 목표의 위치를 처음부터 알고, 눈 사이의 빈 공간을 창으로 비춰 가며 골라서 보스를 창 안에 넣고 휴지통에 넣는다.
- 의도: 2페이즈로 넘어갈 때 처음으로 창 밖까지 눈이 드러나는 대비를 만든다 (5장).

### 4-3. 눈 규칙 [제안 — 첫 번째 프로토타입에서 검증]

- 각 눈은 중심 위치와 이미지 반너비를 가진다. 현재 반너비 125는 그림 전체 너비 250을 뜻하며 원형 접촉 판정에 사용하지 않는다. 눈꺼풀 아트의 실제 외곽을 따라 창 본문과 접촉을 판정한다.
- **판정 대상은 창 본문뿐이다.** 제목 표시줄과 테두리는 판정하지 않는다 (GDD 6장과 같다).
  - 이유: 1페이즈에서 창은 시야다. 보는 영역만 들킨다.
- **본문이 눈 그림의 실제 외곽과 겹쳐 있는 동안:**
  - **휴지통이 굳는다.** 잡으려 하면 창이 좌우로 짧게 흔들린다.
    - 이유: 이 규칙이 없으면, 큰 창으로 눈에 잠깐 겹친 채 허용 시간 안에 휴지통을 크게 끌어가는 꼼수가 통한다. 프로토타입에서 확인했다.
  - 노출 시간이 쌓인다. 허용 시간(7장)을 넘기면 오염이 1 오르고, 화면이 붉게 번쩍인다.
  - 휴지통을 끌던 중에 오염되면 휴지통을 놓친다.
- **[확정 — 검토 후 사용자 답변] 노출 시간과 오염 판정은 모든 눈에 공통으로 하나만 사용한다.** 여러 눈과 동시에 겹쳐도 시간이 배로 쌓이거나 오염이 눈 수만큼 오르지 않는다. 한 눈에서 다른 눈으로 옮겨도 어느 눈과든 계속 겹쳐 있으면 노출이 이어진다.
- 오염이 한 번 오른 뒤에는, 본문이 **모든 눈 그림에서 완전히 벗어났다가 다시 들어와야** 다음 오염을 판정한다.
- 허용 시간 전에 모든 눈에서 벗어나면 노출 시간은 0으로 돌아간다. 최소화로 노출 시간이 초기화되는 규칙은 6-2를 따른다.
- 노출 구간은 시간순으로 처리한다. 한 프레임 안이어도 모든 눈에서 완전히 이탈한 틈이 있으면 그 순간 노출 시간을 0으로 만들고 다음 겹침부터 새로 센다. 여러 눈의 겹침 중복을 제거하는 것과, 이탈 전후의 시간을 합쳐 누적하는 것은 구분한다. A에 0.4초 노출 → 완전 이탈 → B에 0.4초 노출은 연속 0.8초로 취급하지 않는다.
- **오염 3이면 갇힌다.**
- **시각 경고:**
  - 본문이 눈 그림에 가까워지면(7장의 근접 거리) 창 테두리가 **주황**이 된다.
  - 겹치면 창 테두리가 **빨갛게 깜빡이고**, 본문 아래쪽에 노출 진행 막대가 찬다. 본문에 붉은 기가 돈다.
  - 눈 그림은 실제 접촉 외곽을 항상 보여 주도록 크기·열림을 고정한다. 눈동자는 창의 중심을 따라 보되 눈 안에서만 작게 움직인다. 근접·접촉은 창 테두리와 기존 노출/오염 효과로 알리며, 노출 시간·오염은 공통 판정을 유지한다.
- 오염이 오를수록 화면 전체에 붉은 색조와 노이즈 줄이 늘어난다 (GDD 10-2와 같은 방향).
- **[확정 — 수동 플레이 후 추가 감소 요청]** 화면을 위아래로 흐르는 밝은 CRT 띠와 촘촘한 세로 줄무늬로 보이는 입자 노이즈는 글과 눈 판정을 가리지 않도록 아주 희미하게 표시한다. 오염에 따른 붉은 색조·주사선·가로 끊김 신호는 유지한다. 적용 강도는 개발 가이드 14장에서 관리한다.
- **[확정] 오염·굳음을 알리는 안내 문구는 없다.** 위의 시각 신호로만 전달한다. GDD의 "오염도는 게이지 UI 없이 화면 변화로만 전달한다"는 원칙과 같다.

### 4-4. 지형 — 눈을 피해 자유롭게 이동

**[확정 — 수동 플레이 후 사용자 결정] 최소 면적과 모양 변경 최소 3회 조건을 제거한다.** 90×90 창으로도 완주할 수 있다. 긴 창은 휴지통을 한 번에 더 멀리 옮기는 선택이며 모양을 강제하는 문은 없다.

**[확정 — 추가 사용자 지시] 회색 길과 휴지통의 지정 경로 제한을 제거한다.** 숨은 층은 한 공간이며, 눈 사이의 빈 곳을 플레이어가 골라 이동한다. 별도의 통로 밖 판정이나 보이지 않는 바닥 벽은 없다. 눈을 크게 돌아가는 경로도 허용한다.

- 창을 움직여도 휴지통의 화면 위치는 고정이다. 휴지통은 창 안에서 별도로 드래그해야 이동한다.
- 창은 휴지통을 여백 39만큼 품고 화면 안에 있어야 한다. 휴지통은 창 본문 안에서만 움직이며, 노출 중 굳는 규칙도 유지한다.
- 90×90 창은 안전한 작은 시야로 쓸 수 있지만 한 축의 전체 드래그 여유가 12다. 긴 창은 더 멀리 끌 수 있는 대신 넓은 시야가 눈에 노출될 수 있다.
- 희미한 격자는 공간을 읽는 배경이며 이동 가능 영역을 표시하지 않는다. 길찾기는 눈 그림과 창 테두리의 시각 신호로 안내한다.

## 5. 페이즈 전환 연출 [제안]

**순서:**

1. 사용자 지정 `Cannot_Move.png` 오류 이미지가 화면 중앙에 표시된다 (약 1.5초). 원본 스프라이트 비율과 투명을 유지한다. 이미지 속 X·버튼은 연출이며 별도 클릭을 기다리지 않는다.
2. 화면 전체 글리치와 붉은 섬광. **[확정 — 사용자 지정]** 이 점멸 구간에 `Assets/Art/Screen/Dos.png` 창 이미지가 좌상단 4개·우하단 4개, 총 8개 나타난다. 기존 좌상단 묶음은 오른쪽 아래로, 추가 우하단 묶음은 반대인 왼쪽 위로 겹치는 계단식이며 두 묶음은 같은 짧은 간격으로 연달아 뜬다. 2페이즈에 들어가면 모두 사라진다. 별도 클릭이나 닫기 조작을 요구하지 않는다.
3. 숨은 층에만 있던 희생자들의 눈이 **창 밖 화면 전체로 번져 나온다.** 장악을 알리는 장면이다. 이 중 7개가 그대로 남아 2페이즈의 첫 이동 공격이 되고, 공중 고정 눈 4개도 별도로 나타난다 (6-3).
4. 창이 충격으로 **시작 위치(왼쪽)까지 밀려나고**, 휴지통도 시작 위치로 돌아간다. 보스는 오른쪽 끝 원래 자리로 돌아간다.
5. 창 본문이 **파란 정상 바탕화면**으로 바뀐다. 장악된 화면 속 마지막 남은 정상 공간이라는 의미다.
6. 창 밖의 어두운 명령 로그 배경이 **2페이즈 배경**(1페이즈 숨은 층과 같은 `Phase_1.png`, 별도 문구 없음)으로 바뀐다. Spacebar 이미지 안내는 8-2의 지연 뒤 잠시 표시한다.
7. 짧은 유예(공격 순서의 첫 대기) 뒤 공격이 시작된다.

**규칙:**

- 전환 연출 중에는 입력을 받지 않는다.
- 1페이즈의 오염은 2페이즈로 이어지지 않는다. 2페이즈는 눈에 닿으면 다운로드를 유지한 채 즉시 시작 순간으로 리스폰한다.
- **전환이 끝난 시점이 2페이즈의 저장 지점이다 [확정 — 3-5].**

## 6. 2페이즈 — 장악

### 6-1. 핵심 규칙 [확정]

- 모든 눈이 창 없이도 화면 어디서나 보인다.
- **눈 아트 [확정 — 사용자 지정]:** `Assets/Art/creature/Iris.png` 흰자 위에 `Red_Pupil_2.png` 붉은 동공을 겹쳐 창 중심을 따라 움직인다. 시작 눈·일반 사격·일자 벽과 페이즈 전환의 눈에 같은 아트를 적용한다. 원본 비율·색·투명과 원형 판정 방식을 유지하며 눈별 크기 차이는 6-3의 규칙을 따른다. 1페이즈 고정 눈 아트는 별도로 유지한다.

- 눈이 창 **프레임 어디든**(제목 표시줄 포함) 닿으면 **즉시 피격 실패 후 시작 지점으로 리스폰한다.** 오염 누적은 없고 다운로드는 유지된다.
  - 이유: 2페이즈에서 창은 시야가 아니라 플레이어의 몸이다.
- 전진 방식은 3-2와 같다. 창 안의 휴지통을 끌어가며 보스 쪽으로 간다.
- 피할 틈이 없는 일자 공격은 **최소화**로 넘긴다.
- **최소화 중에는 뒤로 밀리지 않지만 앞으로도 갈 수 없다.**

### 6-2. 최소화

- **[확정] 최소화·복원은 Space 키로 한다.** Space를 누를 때마다 최소화와 복원이 번갈아 일어난다.
- **[확정] 1페이즈에서도 Space 최소화가 똑같이 동작한다.** 최대 유지 시간과 강제 복원도 같다. 1페이즈에서 최소화하면 눈 판정이 없고 노출 시간은 0으로 돌아간다. 1페이즈에는 위협이 없으므로 이득도 손해도 없다.
- **[제안]** 제목 표시줄의 `_` 버튼과 작업 표시줄의 `WINDOW(1).exe` 버튼으로도 똑같이 할 수 있게 둔다. 실제 OS를 조작하는 감각을 유지하기 위해서다.
- **[확정] 최소화하면** 창이 사라지고 눈에 맞지 않는다. 최소화 중에는 전진할 수 없다.
- **최소화 중 [제안]:**
  - 창과 휴지통은 최소화 직전의 유효한 위치·크기로 보관된다. 진행 중 창 이동/리사이즈를 누르기 시작 위치로 되돌리지 않는다.
  - 눈 판정이 없다.
  - 창과 휴지통을 조작할 수 없다.
  - 끌고 있던 것이 있으면 그 조작을 끝낸다. 최소화 자체나 남은 해제로 보스 드롭 성공이 발생하지 않으며, 잡은 보스는 포획 해제 규칙을 따른다.
- **복원 [제안]:**
  - 같은 위치와 같은 크기로 즉시 다시 나타난다.
  - **2페이즈에서 복원하는 순간 눈과 겹쳐 있으면 즉시 피격 리스폰한다. 다운로드는 유지한다.**
- **최대 유지 시간 [제안] (7장):**
  - 넘기면 강제로 복원된다. 무한정 숨는 것을 막기 위한 규칙이다.
  - 조건: **최대 크기의 창에서도 일자 벽이 다 지나갈 만큼** 길어야 한다. 프로토타입 실측으로 최대 크기 창은 약 3.0초, 기본 크기 창은 약 1.8초 숨어야 했다.
- **신호 [제안]:**
  - 최소화 중 작업 표시줄 버튼에 남은 시간 막대를 보여 준다.
  - 강제 복원 0.9초 전부터 버튼이 빨갛게 깜빡인다.
- 최소화 중에 발사되는 조준 공격은 **마지막으로 창이 있던 위치**를 노린다.
- 최소화와 Space는 지정된 **Spacebar 이미지 안내**로 알린다 (8-2). 배경 유언은 표시하지 않는다.

### 6-3. 공격 종류

모든 공격은 희생자들의 눈이다. 보스에게 조종당해 플레이어에게 몰려온다.

**크기 차이·공중에 떠 있는 눈 [확정 — 사용자 요청, 수치·배치는 조정 가능]**

- 시작 눈과 조준 사격은 기준 반경에서 약 ±12%로 크기를 다르게 한다. 흩뿌리기는 기존 반경 22~32의 차이를 유지한다. 표시 크기와 원형 충돌 반경은 함께 바뀐다.
- 일자 벽에도 크기 차이를 주되 세로 간격의 절반보다 큰 최소 반경을 보장하여 틈을 만들지 않는다. 가장 큰 눈이 화면 밖으로 나갈 때까지 벽의 수명을 유지한다.
- 중앙 구간에 **제자리에 떠 있는 눈 4개**를 둔다. 위치는 (790,310), (1120,720), (1450,330), (960,530), 기준 반경은 각각 34·30·38·70이며 같은 크기 변화를 적용한다. 공격처럼 날아오지 않고 동공만 창을 따라 움직인다. 접촉하면 다른 눈과 같이 즉시 리스폰한다.
- 추가 중앙 눈은 시작 창에서 WINDOW.exe 아이콘으로 곧바로 이동하는 경로를 막으며 위·아래로 우회할 수 있다.
- 떠 있는 눈은 시작 창·보스 위치를 가리지 않으며 위·아래로 우회할 공간을 둔다. 시작 눈 7개와 별도로 세고, 리스폰 때 같은 위치·크기로 돌아온다. 포획 중·최소화 중에도 표시하며 최소화 중에는 눈 접촉을 판정하지 않는다.

**시작 눈 [확정]**

- 2페이즈는 **움직이는 시작 눈 7개와 제자리에 떠 있는 눈 4개**가 화면에 있는 상태로 시작한다. 전환 연출(5장)에서 화면 전체로 번져 나온 눈들이 그대로 첫 공격이 되는 그림이다.
  - 이유: 처음에 화면이 비어 있으면 맵 절반을 공짜로 지나갈 수 있어 긴장감이 풀리고, 난이도가 뒤쪽에 몰렸다 (테스트 피드백).
- 배치 규칙 (1920×1080 기준, 7-3):
  - 시작 창 프레임에서 165 이상 떨어진 곳에만 둔다.
  - 시작 창과 같은 높이(창 중심에서 위아래 225 이내)라면 가로 1170 이상 떨어진 곳에만 둔다.
  - 눈끼리 165 이상 떨어뜨린다.
  - 그 밖에는 가로 510~1770, 세로 60~(작업 표시줄 위 60) 범위에서 무작위로 둔다.
- 흩뿌리기보다 느리게 왼쪽으로 흘러간다.
- 기준: 최초 진입 후 가만히 서 있어도 대부분 8초 넘게 버티고, 가장 빨리 맞는 경우도 약 7초다. 시작하자마자 피격 리스폰이 반복되는 배치는 피한다.

**A. 흩뿌리기 [제안]**

- 오른쪽 화면 밖에서 무작위 높이로 나타나, 왼쪽으로 날아간다. 위아래로 약간 흔들린다.
- 크기와 속도는 정해진 범위 안에서 무작위다.

**B. 조준 사격 [제안]**

- **화면 위쪽 또는 아래쪽 가장자리 밖**에서 나타나, 발사 순간의 창 중심을 향해 직선으로 날아간다.
- 출발 가로 위치: 창 중심의 가로 위치에서 일정 범위 안의 무작위 위치.
- 출발 세로 위치: 위와 아래 중, 창 중심과의 세로 거리가 최소 거리(7장) 이상인 쪽.
- 이유: 처음에는 보스 위치에서 발사했는데, 보스에 가까워질수록 눈이 코앞에서 튀어나와 피할 수 없었다. 보스가 창 안에 들어오면 아예 창 안에서 눈이 생겼다. 테스트 피드백으로 바꿨다.

**C. 일자 벽 [확정]**

- **화면 세로 전체를 빈틈없이 채운** 눈 한 줄이 오른쪽에서 왼쪽으로 지나간다.
- 피할 틈이 없으므로 **최소화가 유일한 회피 방법**이다.
- **[확정] 예고 시점은 시간이 아니라 휴지통의 진행 위치다.** 휴지통이 진행도 **30%와 70%** 지점을 처음 넘을 때 각각 한 번 예고한다. 2페이즈에서 예고 기회는 최대 두 번이며 빠른 포획으로 취소할 수 있다.
  - 이유: 시간 기반보다 진행 위치로 벽 예고 시점을 예측하기 쉽다. **[확정 — 사용자 답변] 빠른 포획으로 벽 예고를 취소하거나 벽이 도착하기 전에 클리어하는 플레이는 허용한다.** 최소화 두 번을 모든 플레이어에게 강제하지 않으며, 벽을 기다리게 하는 진행 제한도 넣지 않는다. 이미 발사되어 다가오는 벽을 넘겨야 할 때에는 최소화로 회피한다.
  - 진행도: 휴지통의 2페이즈 시작 위치를 0%, 보스 바로 앞(보스 x − 90)을 100%로 하는 가로 거리 비율이다. 화면에 표시하지 않는 내부 값이다.
  - 같은 지점을 다시 넘어도 다시 나오지 않는다. 전투 리스폰 때 벽 기록은 초기화되지만 다운로드는 유지한다.
  - **예고 순서 [제안 — 검토 반영]:** 한 번에 하나만 예고한다. 한 이동/프레임에 두 임계값을 넘거나 30% 벽 처리 중 70%를 넘으면 30% → 70% 순서로 예약한다. 다음 벽은 앞 벽이 완전히 지나가고 발사 후 공격 정지 구간도 끝난 뒤 예고하는 안으로 검증한다. 이 대기열 때문에 휴지통 전진이나 포획을 제한하지 않는다.
  - **첫 번째 일자 벽은 25% 느리게** 온다. 최소화를 처음 배우는 순간이기 때문이다.
  - **예고가 시작되면 다른 공격(흩뿌리기, 조준 사격, 보스 직접 사격)이 멈추고, 벽 발사 후 2.5초 동안도 멈춘다.** 벽 하나에만 집중하게 하기 위해서다. 이미 화면에 있는 눈은 계속 움직인다.
  - **[확정 — 검토 후 사용자 답변] 보스를 포획하면 미발사 예고와 예약을 취소하고, 해당 시도의 기회는 소모한다.** 포획이 풀려도 취소한 벽을 다시 예고하지 않는다. 이미 발사한 벽은 유지한다.
  - **세부 경계 처리 [제안]:** 포획한 상태에서 처음 넘은 임계값도 새 예고 없이 소모하며, 아직 넘지 않은 임계값은 포획 해제 후 처음 넘을 때 사용할 수 있다. 발사 시점과 포획이 같으면 아직 발사하지 않은 벽의 취소를 먼저 적용한다.
- **예고 [제안]:**
  - 발사 1.8초 전부터 화면 오른쪽 끝의 세로 띠가 빨갛게 깜빡이고 "!!"가 표시된다.
  - 같은 시간 동안 기존 오른쪽 예고 띠와 위험 시각 신호를 표시한다. 배경 유언의 맥동은 제거한다.

**D. 보스 직접 사격 [제안]**

- 휴지통이 보스에서 일정 거리(7장) 이내로 가까워지면, 일정 주기마다 조준 사격(B와 같은 출발 규칙) 1발이 추가된다.

**제외:**

- **틈이 있는 벽은 쓰지 않는다.** 일자 벽과 헷갈린다는 테스트 피드백이 있었다.

### 6-4. 공격 순서 [제안]

아래 순서를 한 바퀴로 하여 반복한다. 한 단계가 끝나면 다음 단계로 넘어간다.

| 순서 | 단계 | 내용 |
|---|---|---|
| 1 | 대기 | 2.2초 (2페이즈 시작 직후의 유예도 겸함) |
| 2 | 흩뿌리기 | 4.5초 동안 1.1초마다 1개 |
| 3 | 대기 | 1.6초 |
| 4 | 조준 사격 | 3발, 0.45초 간격 |
| 5 | 대기 | 2.0초 |
| 6 | 흩뿌리기 | 3.5초 동안 1.1초마다 1개 |
| 7 | 대기 | 1.8초 |

- **일자 벽은 이 순서에 들어 있지 않다.** 진행 위치로만 나온다 (6-3 C). 일자 벽 예고부터 발사 후 2.5초까지는 이 순서가 멈췄다가, 멈춘 곳에서 이어진다.

- 한 바퀴가 끝날 때마다 움직이는 눈의 속도가 5%씩 빨라진다. 최대 +25%까지며 공중 고정 눈은 계속 제자리에 머문다.
- 보스 직접 사격(D)은 이 순서와 별개로, 거리 조건을 만족하는 동안 계속 작동한다.
- 화면 밖으로 완전히 나간 눈은 사라진다.
- 프로토타입의 일반 공격은 동시에 화면에 있는 눈이 최대 9개 정도, 대부분 3~7개였다는 기록을 참고한다. **[제안 — 검증 범위 보완] 약 9개 기준은 움직이는 시작 눈·흩뿌리기·조준 사격·보스 직접 사격의 합계에 적용하고 일자 벽과 공중 고정 눈 4개는 별도로 센다.** 일자 벽은 현재 화면 높이와 간격에서 약 21개가 필요하므로 총 눈 수 9개 제한과 동시에 적용하지 않는다.

### 6-5. 포획과 마무리

- **보스가 포획되면 [제안]:**
  - 새 공격이 즉시 멈추고, 일자 벽의 미발사 예고·예약은 6-3의 소모 규칙으로 취소된다. 이미 발사한 벽은 사라지지 않는다.
  - 이미 날아오던 눈은 계속 움직이며, 맞으면 다운로드를 유지한 채 시작 순간으로 즉시 리스폰한다.
  - 의도: 창에 가둬서 무력화한다는 그림이다. 마지막 드래그를 할 수 있는 기회가 된다.
- 창이 보스를 놓치면(보스가 본문 밖으로 나가면) 공격이 다시 시작된다. 최소화 중에는 포획 상태로 치지 않는다.
- **삭제 성공 = 복원 취소:** 보스 아이콘을 휴지통 위에 놓으면 복원이 취소되고 다운로드가 멈추며 보스전이 끝난다.
- 이후 **플레이어가 직접 휴지통 비우기**를 실행해 엔딩에 들어간다 [확정 — 사용자 답변]. 희생자들의 눈도 프로그램과 함께 모두 삭제되고 정상 바탕화면으로 돌아온다. 프로그램은 재등장하지 않는다.
- **[미정]** 휴지통 비우기의 UI·문구·연출 길이는 앞뒤 연출 담당이 구체화한다 (13장). 직접 조작 여부는 더 이상 미정이 아니다.
- **보스전 담당과 엔딩 담당의 연결:** 복원 취소 순간 새 공격·다운로드·실패 판정을 중단하고 완료를 한 번 전달한다. 이미 존재하던 눈은 정지시켜 더 이상 위협이 되지 않게 한다. 희생자들의 최종 삭제 표현은 엔딩 담당의 직접 휴지통 비우기 뒤에 맞춘다 [제안 — 구현 경계]. 통합 전에는 완료 상태에서 전투 입력을 잠그고 기다리며, "보스전 완료" 안내창·문구를 새로 띄우지 않는다. 통합 후에는 엔딩 담당의 지정된 직접 비우기 조작을 허용한다. 기술 계약과 자원 정리 시점은 개발 가이드 17-2장을 따른다.

### 6-6. 다운로드 타이머 [확정 — 기획 흐름, 세부 규칙은 10:29 결정]

- **의미:** 복원으로 시작된 진짜 WINDOW.exe의 강제 다운로드다. 다 차기 전에 보스를 휴지통에 다시 넣어야(복원 취소) 한다.
- **보스전 직전 연출 중:** 일시 정지 상태다.
- **[확정 — 검토 후 사용자 답변] 게임 앱이 포커스를 잃거나 일시 중단되면 전투와 다운로드를 모두 정지한다.** 눈 이동·노출·공격/예고·최소화 유지 시간·다운로드를 함께 멈춘다. 진행 중 입력은 취소하고, 포커스와 실행 상태가 모두 돌아온 뒤 정지된 전투 시간부터 이어 간다. 복귀할 때 비활성 기간을 몰아서 진행하거나 시간을 새로 지급하지 않는다. 이 정지는 아래 일반 진행 규칙의 공통 예외이며, 게임 속 창을 Space로 최소화하는 것과 구분한다. Space 최소화 중에는 기존대로 전투 시간이 진행된다.
- **[확정 — 호환성 보완 사용자 답변] 해상도·카메라·작업 영역 변경으로 좌표를 안전하게 계산할 수 없거나 화면이 창의 최소 제약을 수용하지 못하면 전투와 다운로드를 함께 정지한다.** 입력·피격 판정과 눈 이동·노출·공격/예고·최소화 유지 시간도 멈춘다. 유효한 화면과 제약이 복구되면 현재 상태를 재투영하고, 다른 정지 사유까지 해제된 뒤 새 시간 진행 전에 도착 상태를 검사하여 이어 간다. 정지 기간을 몰아서 진행하거나 시간을 초기화하지 않으며, 최소 제약을 임의로 완화해 계속 플레이시키지 않는다. 이 정지는 두 페이즈에 공통이며 Space 최소화만으로 시간을 멈추지는 않는다.
- **1페이즈 [확정]:** 다운로드가 아주 천천히 차서 사실상 멈춘 것처럼 보인다. **1페이즈 동안에는 절대 다 차지 않는다.**
  - 일정 수치(7장)까지 차면 거기서 멈춘다. 1페이즈의 "시간 제한 없음"을 지키기 위해서다.
- **2페이즈 [확정]:** 본격적으로 찬다. 플레이어가 시간 제한을 가장 크게 느끼는 구간이다.
  - **[확정] 의도적으로 천천히 찬다.** 타임어택이지만 너무 어렵지 않게, 천천히 플레이해도 깰 수 있어야 한다. 전체 시간은 7장을 따른다.
  - **최소화 중에도 계속 찬다.** 최소화는 안전하지만 시간을 내주는 선택이 된다.
  - 보스를 포획한 동안에도 계속 찬다 [제안].
- **실패/리스폰 [확정 — 최신 사용자 지시]:** 1페이즈는 기존 저장 시점의 다운로드 값으로 복구한다. **2페이즈에서는 죽어도 다운로드 진행도·누적 경과 시간·남은 시간을 되돌리지 않는다.** 리스폰 중에도 계속 차므로, 여러 번 죽어 시간이 오래 걸리면 다운로드 완료 배드 엔딩에 도달한다. 3-5를 따른다.
- **2페이즈 최초 진입 [확정]:** 1페이즈 종료가 빠르더라도 전환이 끝나 2페이즈에 **처음 들어갈 때 한 번만 30%**로 맞춘다. 30%에서 100%까지의 초기 제한 시간은 240초이며, 리스폰 횟수와 무관하게 한 판의 모든 시도가 이 시간을 공유한다. 피격 후에는 현재 다운로드 값을 그대로 이어 간다.
- **표시 — 칸 막대 [확정: 형태와 위치 / 제안: 세부]:**
  - **[확정]** 옛 Windows의 다운로드 막대처럼 **칸이 하나씩 차는 막대**를 쓴다. 매끄럽게 차지 않고 한 칸 단위로 끊어서 찬다.
  - **[확정] 보스전 중에는 작업 표시줄에만 표시한다.** 화면에 다운로드 대화 상자를 띄워 두지 않는다. 플레이 화면을 가리거나 시선을 빼앗지 않기 위해서다.
  - **작업 표시줄 표시 [제안]:**
    - 위치: 작업 표시줄 오른쪽, 시계 왼쪽. 왼쪽의 `WINDOW(1).exe` 버튼과 확실히 떨어뜨린다.
    - 구성: 작은 다운로드 아이콘 + 칸 막대 + 퍼센트 (예: `▮▮▮▮▮▮▯▯▯… 30%`).
    - 크기: 작업 표시줄 높이 안에서 가로 약 260 (1920×1080 기준).
    - 눌러도 아무 반응이 없다. 작업 표시줄의 `WINDOW(1).exe` 버튼(최소화·복원)과 헷갈리지 않게 버튼 모양으로 만들지 않는다.
  - **보스전 직전 연출의 대화 상자 [제안]:**
    - 최신 진입 계기는 1-2의 Unlock 전환 후 3초 대기다. 그 뒤 기존 **옛 Windows식 다운로드 대화 상자**가 뜬다. 강제 다운로드가 시작됐다는 충격을 주는 장면이다.
    - 구성: 제목 `10% / WINDOW.exe 다운로드` / 받는 중 `WINDOW.exe` / 칸 막대 / 남은 시간 / 저장 위치 `C:\…\휴지통\WINDOW.exe` / "다운로드가 끝나면 이 대화 상자 닫기" 체크 상자(체크된 채 회색) / [열기] [폴더 열기] [취소]
    - **[취소] 버튼은 회색으로 비활성화되어 눌리지 않는다.** 글 없이도 "직접 취소할 수 없다"는 것을 보여 준다.
    - 눈알 연출(1-2의 4번) 동안 다운로드는 일시 정지 상태로 대화 상자에 남아 있다.
    - **보스전이 시작되면 대화 상자가 작업 표시줄의 칸 막대 자리로 최소화되듯 줄어들며 들어간다.** 그 뒤로는 작업 표시줄에서만 찬다.
  - **신호 [제안]:**
    - 한 칸이 찰 때마다 칸 막대가 아주 짧게 깜빡인다. 사운드가 들어오면 칸마다 짧은 틱 소리를 낸다.
    - 막바지(80% 이상)에는 칸 막대가 붉게 물들고 천천히 깜빡인다.
    - 1페이즈 상한에 닿아 멈춰 있을 때는 퍼센트 옆에 `계산 중…`이 깜빡인다. 멈췄지만 끝난 게 아니라는 불안을 준다.
  - 삭제 성공(복원 취소) 순간 칸 막대 자리에 `다운로드 취소됨`이 잠깐 표시된 뒤 사라진다.
- **다 차면 [확정 — 최신 사용자 지시]:** 주인공이 최종적으로 갇히는 **별도의 배드 엔딩**으로 진입한다. 공격·조작·다운로드를 종료 상태로 확정하고 배드 엔딩 담당에게 한 번 인계한다. **리스폰하거나 30%로 돌아가지 않는다.** 구체적인 장면·문구·연출은 13장의 미정 사항이다.

### 8-2. 유언 — 2페이즈 문자 안내

**원칙 [확정]:**

**쓰는 방식 [제안]:**

- 플레이어에게 명령하는 시스템 안내처럼 쓰지 않는다. 희생자 자신의 경험과 후회로 쓰되, **무엇을 해야 하는지는 분명히 읽히게** 쓴다.
- 손으로 쓴 듯한 붉은 글씨로 기울어지게 쓴다.
- CRT 효과, 글리치, 오염 색조가 걸려도 **읽을 수 있어야 한다** (GDD 10-1).

| **Could** | 후반 눈 2개, 보스 직접 사격, 바퀴당 속도 증가, 분위기 유언, 배드 엔딩 연출 다듬기, 오염 화면 효과 세부, 사운드 |

- **일정이 밀릴 때:** 1페이즈를 빼고 2페이즈만으로 보스전을 구성한다. 두 번째 프로토타입이 바로 이 형태였고, 팀 시연에서 호응을 얻었다. 이 경우 필요한 전진 안내는 2페이즈 유언에서 전달한다.
- **권장 진행 순서:**
  1. 2페이즈 최소 루프 (창이 휴지통을 품는 전진, 흩뿌리기, 다운로드를 유지하는 즉시 리스폰, 다운로드 완료의 종료 분기, 포획과 삭제)
  2. 일자 벽과 Space 최소화, Spacebar 이미지 안내
  3. 1페이즈 (자유 이동 공간과 고정 눈·시각 신호)
  4. 전환 연출과 페이즈별 저장·재시작
  5. 나머지 Should·Could

- **[확정 — 사용자 답변] 첫 구현 완료 목표는 1·2페이즈 모두다.** 위 순서대로 2페이즈를 먼저 확보하고, 일정이 부족하면 기존 축소안을 적용한다. 이후 별도 착수 명령에 따른 진행 상태는 체크리스트 18장에서 관리한다.

## 10. 시연·개발용 기능

| 기능 | 상태 | 내용 |
|---|---|---|
| 무적 켜기·끄기 | [확정] | 눈에 닿아도 갇히지 않는다. 켜져 있으면 화면 한쪽에 작게 표시한다. 발표장에서 반드시 끝까지 보여줘야 할 때 쓴다. |
| 현재 페이즈 재시작 | [제안] | 전투를 저장 지점으로 즉시 복구한다. 2페이즈에서는 일반 리스폰과 같이 다운로드를 유지한다. 배드 엔딩 진입 뒤에는 이 조작으로 리스폰하지 않는다. |
| 페이즈 건너뛰기 | [제안] | 1페이즈를 건너뛰고 바로 2페이즈를 시작한다. |
| 보스전 바로 시작 | [제안] | 게임 앞부분을 거치지 않고 보스전부터 시작한다. 개발과 리허설용이다. |
| 다운로드 멈춤 | [제안] | 다운로드가 더 차지 않게 멈춘다. 다운로드 완료는 리스폰 없는 배드 엔딩이므로, 무적과 별개의 발표장 안전장치로 쓴다. 켜져 있으면 화면 한쪽에 작게 표시한다. |

- 키 배정은 팀의 다른 디버그 기능과 겹치지 않게 정한다.
- **Space는 최소화 전용이므로 다른 기능에 쓰지 않는다.**
- 프로토타입에서는 G가 무적, R이 재시작이었다.

## 11. 완료 조건 — 검증 항목

이 장은 기획상의 검증 기준이다. 실제 구현 진행·통과 근거·미검증 기록과 완료 체크는 [체크리스트 18장](IMPLEMENTATION_CHECKLIST.md#18-보스전-구현-계획--2026-10-31)에서만 관리한다.

모든 항목은 실제 마우스·키보드 조작으로 확인하고, 빌드에서도 한 번 이상 확인한다.

### 11-1. 공통

- [ ] 휴지통은 창 본문 밖으로 끌려 나가지 않는다.
- [ ] 창을 움직이거나 크기를 바꿔도 휴지통이 본문 밖으로 벗어나지 않는다. 경계에서 창이 멈춘다.
- [ ] 창 늘리기 → 휴지통 끌기 → 창 옮기기를 반복해 보스까지 갈 수 있다. 2페이즈에서는 최대 크기 창으로도 최소 3번 이상 반복해야 한다.
- [ ] X를 누르면 즉시 갇힌다.
- [ ] 1페이즈 실패는 기존 시작 상태로 복구하고, 2페이즈 피격은 재도전 화면·암전 대기 없이 시작 순간으로 즉시 리스폰한다. 전투 항목은 복구하되 2페이즈 다운로드는 유지한다. 1페이즈로 돌아가지 않는다.
- [ ] 재시작 직후 이전 상태의 연출·충돌·남은 클릭이 적용되지 않고, 해제 후 첫 새 누름을 바로 받는다.
- [ ] 겹친 대상을 누르면 3-3의 우선순위대로 하나만 반응한다.
- [ ] 화면에 보이는 창 이름이 `WINDOW(1).exe`다. 제목 표시줄과 작업 표시줄 모두 확인한다.
- [ ] 2페이즈 배경에 별도 문구가 없고 지정된 Spacebar 이미지 안내만 잠시 표시한다. 기존 시스템 오류·진입 연출 이미지는 유지한다.
- [ ] 진행도 표시가 없다.

### 11-2. 1페이즈

- [ ] 시간 제한이 없다. 오래 머물러도 아무 일도 일어나지 않는다.
- [ ] Space로 최소화·복원이 되고, 최소화 중에는 오염 판정이 없다.
- [ ] 창 밖 배경의 좌상단부터 지정된 명령 로그 90개 항목이 순서대로 출력되고 창 뒤에 가려진다. 보스 아이콘은 처음부터 보인다.
- [ ] 회색 길·통로 충돌 영역이 없고, 예전 길 밖에서도 안전한 본문 안에서 휴지통을 별도로 드래그할 수 있다.
- [ ] 시작 시 창은 어떤 눈에도 닿아 있지 않다.
- [ ] 눈에 접근할 때 창 크기에 따라 노출 범위가 달라지고 안전한 빈 공간을 선택할 수 있다.
- [ ] 4-4 배치에 작은 창과 긴 창을 활용하는 안전 경로가 모두 있다.
- [ ] 90×90으로 줄인 뒤 모양 변경 없이 눈을 피해 보스를 포획·드롭할 수 있다.
- [ ] 각 축 최소 길이·휴지통 여백·화면 경계를 지키는 작은 창 경로와 긴 창 경로가 있다. 가로를 줄여도 세로를 늘릴 필요가 없고 그 반대도 같다. 긴 창은 휴지통을 한 번에 더 멀리 옮긴다.
- [ ] 눈을 크게 돌아가는 경로를 허용하며 별도의 보이지 않는 길 경계로 막지 않는다.
- [ ] 본문이 눈에 겹친 동안 휴지통을 잡을 수 없다.
- [ ] 여러 눈의 겹침에도 공통 노출 시간으로 오염이 한 번만 오른다. 눈 사이를 빈틈 없이 옮기면 노출이 이어지고 모든 눈에서 완전히 벗어나야 다음 노출을 판정한다. 한 프레임 안의 완전 이탈도 그 순간 초기화하며 이탈 전후 노출을 합산하지 않는다. 취소 복원도 도착 상태에 따라 기존 공통 누적/초기화 규칙을 적용한다.
- [ ] 오염 3에서 갇힌다.
- [ ] 제목 표시줄만 눈에 겹치면 아무 일도 일어나지 않는다.
- [ ] 눈과 숨은 층 배경은 창 본문을 통해서만 보인다.
- [ ] 1페이즈 숨은 층에 유언·조작 안내 글자가 표시되지 않는다.
- [ ] 보스를 포획해 휴지통에 넣으면 삭제 실패 오류 뒤 2페이즈로 넘어간다.

### 11-3. 2페이즈

- [ ] 눈이 창 밖에서도 보인다.
- [ ] 눈이 제목 표시줄을 포함한 프레임 어디든 닿으면 즉시 시작 지점으로 리스폰한다. 창·휴지통·보스·시작 눈·공격 순서·벽 기록·최소화/포획/드래그는 초기 전투 상태이며 다운로드는 피격 직전 값에서 이어진다.
- [ ] 2페이즈 시작 때 이동 눈 7개와 공중 고정 눈 4개가 화면에 있고, 시작 창 근처에는 없다.
- [ ] 최초 진입 후 아무것도 하지 않으면 약 7~10초 안에 처음 피격되어 리스폰한다. 공격이 위협적이면서 시작하자마자 피격되는 배치는 아닌지 확인한다. 이때 다운로드는 계속 진행한다.
- [ ] 휴지통이 진행도 30%와 70%를 넘으면 순서대로 벽 예고가 한 번씩 예약된다. 두 임계값을 빠르게 넘어도 예고가 중첩되지 않는다. 포획으로 취소한 예고/예약과 포획 중 넘은 임계값은 소모되며 재발동하지 않는다. 이미 발사한 벽은 유지되고 첫 벽은 두 번째 벽보다 느리다.
- [ ] 일자 벽 예고 중과 발사 후 2.5초 동안 새 공격이 생기지 않는다.
- [ ] 빠른 포획으로 벽 예고 취소·최소화 생략이 가능하며, 이를 막는 진행 제한이 없다. 이미 다가오는 일자 벽을 통과해야 할 때에는 최소화가 유일한 회피 방법이다.
- [ ] Space로 최소화와 복원이 번갈아 된다. 버튼을 둔다면 버튼으로도 같은 결과가 나온다.
- [ ] Spacebar 이미지 3개가 2페이즈 시작 1초 후 상단에 계단식으로 뜨고 2초 후 자동으로 사라지며, 배경 유언 문구는 표시되지 않는다.
- [ ] 일자 벽은 화면 세로 전체를 빈틈없이 덮는다. 전투가 계속되는 동안 벽이 표시 중인 프레임을 통과하면 피격 리스폰하며 다운로드는 유지한다. 그 벽을 넘기려면 최소화해야 한다. 벽 도착 전 클리어는 허용한다.
- [ ] 최대 크기 창에서도, 벽이 창에 닿기 직전에 최소화하고 지나간 직후 복원하면 살아남는다. 강제 복원이 그보다 먼저 일어나지 않는다.
- [ ] 이동·리사이즈·휴지통/보스 드래그 도중 최소화해도 직전의 유효한 창/휴지통 상태를 보관하고 시작 geometry로 되돌리지 않는다. 최소화 중 조작이나 드롭 성공이 없고 복원하면 같은 자리로 돌아온다.
- [ ] 최대 유지 시간을 넘기면 강제로 복원된다.
- [ ] 이미 최소화된 창을 복원하는 순간 눈과 겹치면 다운로드를 유지한 채 즉시 피격 리스폰한다. 같은 시각의 최소화 우선 규칙을 복원에 적용하지 않는다.
- [ ] 같은 시각의 Space 최소화/눈 접촉은 최소화로 회피하고, 그보다 앞선 접촉은 피격으로 처리한다. 만료/X 우선은 유지하며 같은 시각의 드롭이 최소화로 취소되면 성공하지 않는다.
- [ ] Escape 취소 복원은 중간 눈/벽을 가상으로 통과해도 경로 피격이 없고, 표시 중인 도착 프레임이 현재 눈과 겹칠 때만 즉시 피격한다. 포커스 정지에서는 복귀 후 같은 도착 검사를 적용한다.
- [ ] 조준 사격은 항상 화면 위나 아래 가장자리 밖에서 나오고, 생성 순간 창 중심에서 최소 세로 거리 이상 떨어져 있다. 보스 바로 앞에서도 마찬가지다.
- [ ] 보스를 포획하면 새 눈이 생기지 않는다. 포획 상태를 유지한 채 몇 초가 지나도 새 눈이 없다.
- [ ] 보스를 휴지통 위에 놓으면 삭제에 성공한다. 다른 곳에 놓으면 원래 자리로 돌아간다.
- [ ] 처음부터 끝까지 한 판을 했을 때 일반 공격 눈의 합계가 대략 9개를 넘지 않는다. 일자 벽의 눈 수와 총 눈 수는 별도로 기록한다.
- [ ] 복원 취소 순간 다운로드·공격·실패 판정이 멈추고 완료가 한 번 전달된다. 직접 휴지통 비우기와 최종 삭제 표현은 엔딩 담당과 통합하여 별도로 확인한다.

### 11-3a. 다운로드 타이머

- [ ] 1페이즈에서 아무리 오래 머물러도 다운로드가 상한에서 멈추고 다 차지 않는다.
- [ ] 2페이즈에서는 최소화 중에도 다운로드가 계속 찬다.
- [ ] 2페이즈 최초 진입만 30%다. 한 번 또는 여러 번 피격되어도 다운로드 진행도·누적 시간·남은 시간이 되돌아가지 않고, 리스폰 처리 중에도 계속 진행한다.
- [ ] 보스를 휴지통에 넣으면 다운로드가 멈춘다.
- [ ] 다운로드 막대가 한 칸씩 끊어서 찬다.
- [ ] 보스전 중에는 다운로드가 작업 표시줄에만 표시되고, 화면에 대화 상자가 없다.
- [ ] 작업 표시줄의 칸 막대를 눌러도 아무 일이 없고, `WINDOW(1).exe` 버튼과 헷갈리지 않는다.
- [ ] (직전 연출에 대화 상자를 쓴다면) [취소]는 회색으로 눌리지 않고, 보스전이 시작되면 대화 상자가 작업 표시줄로 줄어들며 사라진다.
- [ ] 1페이즈 상한에서 멈춘 동안 `계산 중…`이 깜빡인다.
- [ ] 처음 하는 사람이 천천히 플레이해도 다운로드가 다 차기 전에 2페이즈를 깰 수 있다.
- [ ] 다운로드가 다 차면 별도 배드 엔딩으로 한 번만 진입한다. 리스폰·30% 복구·새 제한 시간 지급이 없다. 피격과 완료가 같은 프레임이어도 피격 리스폰이 배드 엔딩을 취소하지 않는다.
- [ ] 배드 엔딩 진입 뒤에는 눈·입력·디버그 현재 페이즈 재시작·오래된 콜백이 보스전을 다시 시작시키거나 성공으로 덮어쓰지 않는다.

### 11-4. 시연

- [ ] 무적을 켜면 한 번도 갇히지 않고 보스전을 끝까지 진행할 수 있다.
- [ ] 시연 노트북의 해상도와 화면 배율에서 판정과 표시가 어긋나지 않는다.

## 변경 이력

과거 결정은 당시 기록이다. 현재 규칙과 충돌하면 최신 사용자 지시를 반영한 본문을 따른다.

- 2026-10-31 — 전체 기능 호환성 검토 후 사용자 답변으로 좌표 공간이 무효이거나 최소 창 제약을 수용하지 못하는 동안 전투와 다운로드를 함께 정지하도록 확정했다. 유효 복구·다른 정지 사유 해제 후 새 시간 진행 전에 도착 상태를 검사하며 Space 최소화 중 시간 진행은 유지한다. 기존 기능과의 기술 계약은 개발 가이드 17-9장, 완료 조건과 기존 씬 연결 불일치는 체크리스트 18장·17-2장에 분리했다. 구현은 미착수다.

- 2026-10-31 — 추가 보완 질문에 대한 사용자 답변 반영. 2페이즈에서 정확히 같은 시각의 유효한 최소화는 눈 피격보다 우선하며 만료/X 우선은 유지한다. Escape·포커스 취소는 시작 상태로 순간 복원하고 경로가 아닌 도착 겹침만 판정한다. 앱 정지 중 도착 검사는 복귀 후 수행한다. 공통 노출의 한 프레임 중간 이탈, 종료 사유별 정리·입력 시간축·충돌 정밀도/상한 처리와 관찰 가능한 완료 조건을 관련 계획에 반영했다. 기하 오차 수치는 제안이며 구현·플레이 검증하지 않았다.
