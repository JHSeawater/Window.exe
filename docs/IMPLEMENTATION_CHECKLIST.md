# WINDOW.exe — 구현 체크리스트

> 역할: 구현할 작업, 담당, 완료 조건과 진행 상태를 관리한다.
> 기준일: 2026-10-30. 사용자 담당 데스크톱 기능을 구현·검증하고 커밋 대상으로 정리했다. 결과와 남은 항목은 8장, 구현 순서는 [제작 계획 5장](PRODUCTION_PLAN.md#5-1030-사용자-담당-구현-순서-제안)을 참고한다.
> 게임 규칙은 [GDD](GDD.md), 기술·연결 방식은 [개발 가이드](DEVELOPMENT.md), 일정은 [제작 계획](PRODUCTION_PLAN.md)을 따른다.

## 1. 체크 기준과 현재 범위

- `[ ]`는 이 문서에서 완료를 확인하지 않은 항목이다. 로컬에 시험 구현이나 리소스가 있어도 공유 프로젝트에서 확인하기 전에는 완료로 표시하지 않는다.
- `[x]`는 해당 동작과 완료 조건을 확인한 항목이다. 기획의 **[확정]**과 구현의 **완료**는 별개다.
- **[확정 — 사용자 지정]** 문서를 먼저 정리한 뒤 구현한다. 오늘 사용자 담당은 데스크톱·아이콘, 팀원 담당은 창 기본 기능이다.
- 아래 2장은 사용자 요청으로 정한 오늘의 작업이다. 3장의 최대화·최소화·크기·위치 조절은 사용자에게 공유된 팀원 범위이며, 나머지 창·통합 동작은 연결 제안이다.
- 메모장·WINDOW.exe는 통합 확인용 예시 콘텐츠 **[제안]**이다. 개별 콘텐츠 제작 담당은 미정이다.

## 2. 오늘 — 데스크톱·아이콘 / 사용자 [확정]

- [x] 바탕화면에 아이콘 이미지와 이름을 표시한다.
- [x] 한 번 클릭하면 아이콘 하나가 선택된다.
- [x] 다른 아이콘을 클릭하면 선택이 바뀌고, 빈 바탕화면을 클릭하면 선택이 해제된다.
- [x] 같은 아이콘을 더블클릭하면 고정 식별자를 포함한 열기 요청을 한 번만 전달한다.
- [x] 표시 이름이 바뀌어도 같은 식별자로 같은 콘텐츠를 요청한다.
- [x] 작은 포인터 흔들림은 클릭으로 처리하고, 일정 거리 이상 이동했을 때 드래그를 시작한다. 거리·더블클릭 시간 값은 구현 시 조정한다.
- [x] 드래그를 끝냈을 때 클릭·더블클릭으로 오인해 열기 요청을 보내지 않는다.
- [x] 드래그 중 처음 잡은 지점을 유지하며, 시작 순간 아이콘 중앙이 포인터로 이동하지 않는다.
- [x] 해상도·UI 배율이 달라도 포인터와 아이콘 위치가 어긋나지 않는다.
- [x] 아이콘 이미지와 이름이 바탕화면 밖으로 사라지지 않게 한다.
- [x] 초기 배치와 드롭 결과에서 아이콘끼리 겹치지 않게 한다.
- [ ] 창을 열고 닫아도 옮겨 놓은 아이콘 위치를 유지한다. 데스크톱 위치 상태는 구현했으며 팀원 창 연결 후 최종 확인한다.
- [x] 창에 가려진 아이콘은 클릭·드래그 입력을 받지 않는다. Play Mode의 가림 패널로 확인했다.
- [x] 창을 클릭한 입력이 뒤쪽 아이콘의 선택·실행이나 바탕화면의 선택 해제로 함께 처리되지 않는다. Play Mode의 가림 패널로 확인했다.

겹친 위치에 드롭했을 때 드래그 전 위치로 돌리는 방식은 **[제안]**이다. 판정 영역과 처리 순서는 [개발 가이드 4장](DEVELOPMENT.md#4-아이콘-겹침-처리-제안)에서 관리한다.

## 3. 오늘 — 창 기본 기능 / 팀원

### 공유된 작업 범위 [확정 — 사용자 공유]

- [ ] 제목 표시줄 드래그로 창 위치를 옮긴다.
- [ ] 창 가장자리·모서리 드래그로 크기를 조절한다.
- [ ] 창을 최대화한다.
- [ ] 창을 최소화한다.

### 창·통합 동작 보완 [제안]

- [ ] 최대화를 해제하면 이전 위치와 크기로 돌아간다.
- [ ] 최소화한 창을 복원할 수 있다.
- [ ] 창을 클릭하면 앞으로 가져오고 창 앞뒤 순서를 관리한다.
- [ ] 창을 화면 가장자리로 옮겨도 제목 표시줄을 잃어버리지 않는다.
- [ ] 기본 기능 검증에서는 X로 일반 닫기하고 다시 열 수 있다. 게임 오버는 연결하지 않는다.
- [ ] 이후 위험한 X를 연결할 수 있도록 닫기 동작과 게임 규칙을 분리한다.

## 4. 오늘 — 두 시스템 연결 / 사용자·팀원 [제안]

- [ ] 기준 해상도·Canvas 배율, 아이콘과 창의 표시 순서를 맞춘다.
- [ ] 고정 식별자와 열기 요청의 함수·이벤트·데이터 형식을 맞춘다.
- [x] 팀원 창이 준비되기 전에는 임시 수신기로 식별자가 한 번 전달되는지 확인한다.
- [ ] 창이 없으면 생성하고, 이미 열렸으면 같은 창을 앞으로 가져온다.
- [ ] 최소화된 창의 아이콘을 다시 더블클릭하면 복원하고 앞으로 가져온다.
- [ ] 같은 아이콘을 반복 실행해도 창이 중복 생성되지 않는다.
- [ ] X로 닫은 뒤 같은 아이콘으로 다시 열 수 있다.
- [ ] 창 이동·크기 조절·최대화·복원이 아이콘 위치를 바꾸지 않는다.
- [ ] 메모장·WINDOW.exe 등 예시 콘텐츠로 위 동작을 함께 확인한다.
- [x] 사용자 커밋·푸시 요청에 따라 구현·아트·관련 `.meta`의 공유 경로와 Git 제외 규칙을 정리한다. 현재 규칙은 [개발 가이드 2장](DEVELOPMENT.md#2-git-공유-규칙-확정)을 따른다.

## 5. 이후 — 게임 플레이 / 담당 미정 [제안]

오늘 범위에 포함하지 않는다. 게임 내용의 합의 여부는 GDD를 따르며, 아래 항목은 목표 기능을 작업으로 나눈 목록이다.

### 파일 조사와 엿보기

- [ ] 시작 오류·실행 전 경고와 WINDOW.exe 실행 상태를 연결한다.
- [ ] 메모와 사용 설명서 콘텐츠를 준비한다.
- [ ] 사진 폴더·네 자리 비밀번호 입력·오답 안내를 연결한다.
- [ ] 사진 잠금 해제와 설명서 문구 변화를 유지한다.
- [ ] 엿보기 창을 옮겨도 방은 바탕화면 좌표에 고정되도록 한다.
- [ ] 기본 창 크기의 이동만으로 필수 단서에 도달할 수 있게 배치한다.
- [ ] 실제로 보이는 벽 단서를 클릭했을 때만 확인 상태를 저장한다.
- [ ] 벽 단서를 먼저 찾은 뒤 사진을 해제해도 다시 클릭할 필요 없이 진행되게 한다.
- [ ] 조건 충족 시 하위 창 세 개를 한 번만 생성한다.

### 반환·삭제·게임 오버

- [ ] `기록 → 시선 → 연결` 순서의 반환, 잘못된 순서 안내, 해제 상태 유지를 연결한다.
- [ ] 반환한 창이 단서 재확인·프로그램 재선택으로 다시 생기지 않게 한다.
- [ ] 연결 해제 전 휴지통 드롭은 오류 안내, 해제 후 드롭은 삭제 엔딩으로 연결한다.
- [ ] 최종 삭제 전에 상대도 함께 삭제된다는 단서를 제공한다.
- [ ] 위험한 X의 표시·경고·중간 게임 오버를 연결한다.
- [ ] 중간 게임 오버의 흡입 연출과 삭제 굿 엔딩을 준비한다.
- [ ] 재시작 시 창·실행·비밀번호·단서·반환·파일 변형·오염 상태를 초기화한다.
- [ ] 시작부터 삭제 엔딩까지 한 판을 완주하고 빌드에서 확인한다.

### 추가 기능 — 선택·후속 결정

- [ ] 구출 분기 행동을 정한 뒤 자리 교환 배드 엔딩까지 연결한다.
- [ ] 엿보기 창의 최대화·최소화·리사이즈 허용 범위를 정한 뒤 적용한다.
- [ ] 시선 위협을 채택하면 경고·연속 노출·재노출 판정과 오염도 3의 게임 오버를 연결한다.
- [ ] 오염도 화면 변화와 바탕화면 연출 3~4개를 적용한다.
- [ ] 실시간 문구 변화는 간접 소통 방식 결정 후 적용한다.

## 6. 이후 — 자료·리소스 / 담당 미정

체크는 제작과 게임 적용 확인이 끝난 뒤 표시한다. 배경만 원문에 제작 기록이 있으며, 나머지 목록은 **[제안]**이다.

- [ ] 원래 기획안의 등장인물 자료를 받아 GDD에 반영한다. 기존 기록상 아직 미공유 상태다.
- [ ] 바탕화면 배경의 해상도·주사선을 정리하고 적용한다. 원문에는 제작 완료, 현재 이미지 1672×941, 1920×1080 재작업 필요로 기록되어 있다.
- [ ] 아이콘 세트(휴지통·exe·폴더·txt·이미지·문서)를 제작·적용한다.
- [ ] 창 테두리 9-slice 이미지를 제작·적용한다.
- [ ] 엿보기 공간의 큰 방 이미지, 갇힌 사람과 '그것' 이미지를 제작·적용한다.
- [ ] 사진과 같은 구도의 변형본 2~3장을 제작·적용한다.
- [ ] 블루스크린과 오류 팝업을 준비한다.
- [ ] 사운드 방향 결정 후 클릭·오류·글리치·CRT 험·앰비언트 BGM 후보를 제작·적용한다.

## 7. 오늘의 필수 범위와 구분할 항목

격자 정렬, 여러 아이콘 선택, 드래그 선택 영역, 우클릭 메뉴, 앱 재실행 후 아이콘 위치 저장, 휴지통 삭제 판정은 후순위·별도 결정 사항이다. 게임 전체에서 줄일 범위와 우선순위는 [제작 계획](PRODUCTION_PLAN.md)에서 관리한다.

## 8. 10/30 구현·검증 결과와 공유 범위

사용자 요청으로 구현에 착수했고, 이후 커밋·푸시 요청에 따라 `Assets/Desktop`, `Assets/Art/Icon`, `Assets/Art/Screen`과 관련 `.meta`를 공유 대상으로 정리했다. 확인한 데스크톱 동작을 완료 체크하고, 실제 팀원 창이 필요한 통합 항목은 남겨 두었다.

| 항목 | 로컬 확인 결과 | 남은 사항 |
|---|---|---|
| 배경·아이콘 | 제공된 배경과 휴지통·메모·사진·인터넷 4종을 데이터와 프리팹에 연결하고 플레이 화면에서 확인 | WINDOW.exe 등 추가 콘텐츠의 아이콘·파일 정의는 후속 작업 |
| 선택·열기 요청 | 선택 변경·빈 곳 선택 해제, 고정 ID·더블클릭 1회 요청, 이름 변경 후 ID 유지 확인 | 실제 창 시스템 수신기 연결 |
| 드래그·배치 | 작은 흔들림과 드래그 구분, 잡은 지점·배율 대응, 화면 경계, 초기 겹침 정리, 겹친 드롭의 원위치 복귀 확인 | 팀원 창 연결 후 위치 유지 재확인 |
| 입력 가림 | 실제 플레이 모드의 UI 레이캐스트에서 가림 패널이 뒤쪽 아이콘·바탕화면 입력을 차단함을 확인 | 팀원의 실제 창으로 재확인 |
| 자동 검증 | `WindowExe.Desktop.Tests` 14개 통과. 실제 Input System 입력 모듈을 통한 작은 이동·드래그도 포함 | 실제 창 열기·복원·재열기는 미검증 |
| 빌드 | Windows 빌드 경고·오류 0. 1280×720·1920×1080 실행 시 시작 오류 없음 확인 | 팀원 창의 빌드 내 동작은 연결 후 확인 |

실행 씬과 연결 방법은 [개발 가이드 8장](DEVELOPMENT.md#8-데스크톱-실행과-연결)을 따른다. 세션 내 아이콘 위치는 창 생성과 독립적으로 유지하도록 구현했지만, 팀원 창을 열고 닫는 최종 통합 확인은 남아 있다.
