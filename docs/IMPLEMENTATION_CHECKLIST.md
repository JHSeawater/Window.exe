# WINDOW.exe — 구현 체크리스트

> 역할: 구현할 작업, 담당, 완료 조건과 진행 상태를 관리한다.
> 기준일: 2026-10-30. 기본 데스크톱은 `fab196a`, 영역 선택·묶음 이동과 Assets 역할별 정리는 `9808e7b`로 공유했다. 작업 표시줄은 이번 공유 변경에 임시 제공자 기준의 구현·검증을 포함하며 11장에서 관리한다. 기존 결과는 8~10장, 후속 순서는 [제작 계획 7장](PRODUCTION_PLAN.md#7-데스크톱-이후의-다음-작업-제안)을 참고한다.
> 게임 규칙은 [GDD](GDD.md), 기술·연결 방식은 [개발 가이드](DEVELOPMENT.md), 일정은 [제작 계획](PRODUCTION_PLAN.md)을 따른다.

## 1. 체크 기준과 현재 범위

- `[ ]`는 이 문서에서 완료를 확인하지 않은 항목이다. 로컬에 시험 구현이나 리소스가 있어도 공유 프로젝트에서 확인하기 전에는 완료로 표시하지 않는다.
- `[x]`는 해당 동작과 완료 조건을 확인한 항목이다. 기획의 **[확정]**과 구현의 **완료**는 별개다.
- **[확정 — 사용자 지정]** 문서 정리 후 구현에 착수했다. 10/30 사용자 담당은 데스크톱·아이콘, 팀원 담당은 창 기본 기능이다.
- 아래 2장은 사용자 요청으로 정한 오늘의 작업이다. 3장의 최대화·최소화·크기·위치 조절은 사용자에게 공유된 팀원 범위이며, 나머지 창·통합 동작은 연결 제안이다.
- 메모장·WINDOW.exe는 통합 확인용 예시 콘텐츠 **[제안]**이다. 개별 콘텐츠 제작 담당은 미정이다.

## 2. 오늘 — 데스크톱·아이콘 / 사용자 [확정]

- [x] 바탕화면에 아이콘 이미지와 이름을 표시한다.
- [x] 한 번 클릭하면 아이콘 하나가 선택된다.
- [x] 다른 아이콘을 클릭하면 선택이 바뀌고, 빈 바탕화면을 클릭하면 선택이 해제된다.
- [x] 같은 아이콘을 더블클릭하면 고정 식별자를 포함한 열기 요청을 한 번만 전달한다.
- [x] 표시 이름이 바뀌어도 같은 식별자로 같은 콘텐츠를 요청한다.
- [x] 작은 포인터 흔들림은 클릭으로 처리하고, 일정 거리 이상 이동했을 때 드래그를 시작한다. 현재 설정값은 개발 가이드 7장에서 관리한다.
- [x] 드래그를 끝냈을 때 클릭·더블클릭으로 오인해 열기 요청을 보내지 않는다.
- [x] 드래그 중 처음 잡은 지점을 유지하며, 시작 순간 아이콘 중앙이 포인터로 이동하지 않는다.
- [x] 해상도·UI 배율이 달라도 포인터와 아이콘 위치가 어긋나지 않는다.
- [x] 아이콘 이미지와 이름이 바탕화면 밖으로 사라지지 않게 한다.
- [x] 초기 배치와 드롭 결과에서 아이콘끼리 겹치지 않게 한다.
- [ ] 창을 열고 닫아도 옮겨 놓은 아이콘 위치를 유지한다. 데스크톱 위치 상태는 구현했으며 팀원 창 연결 후 최종 확인한다.
- [x] 창에 가려진 아이콘은 클릭·드래그 입력을 받지 않는다. Play Mode의 가림 패널로 확인했다.
- [x] 창을 클릭한 입력이 뒤쪽 아이콘의 선택·실행이나 바탕화면의 선택 해제로 함께 처리되지 않는다. Play Mode의 가림 패널로 확인했다.

아이콘 겹침 금지는 **[확정]**이다. 현재 구현은 겹친 위치의 드롭을 거부하고 드래그 전 위치로 복귀한다. 이 처리 방식의 팀 합의 상태는 **[제안]**으로 유지하며, 판정 영역과 처리 순서는 [개발 가이드 4장](DEVELOPMENT.md#4-아이콘-겹침-처리-제안)에서 관리한다.

### 2-1. 추가 구현 — 드래그 영역으로 여러 아이콘 선택

사용자가 계획대로 구현하도록 요청하여 영역 선택과 묶음 이동을 구현·검증하고 이번 공유 변경에 포함한다. 아래 완료 표시는 동작 확인이며 원격 동기화 상태는 Git으로 확인한다. 구현 순서는 [제작 계획 6장](PRODUCTION_PLAN.md#6-추가-구현--드래그-영역-선택), 기술 방식은 [개발 가이드 9장](DEVELOPMENT.md#9-드래그-영역-선택-구현)에서 관리한다.

- [x] 빈 바탕화면에서 왼쪽 버튼을 누르고 드래그하면 반투명 선택 상자와 테두리를 표시한다. 작은 흔들림은 기존의 빈 곳 클릭으로 처리한다.
- [x] 어느 방향으로 드래그해도 선택 상자와 겹치는 아이콘을 실시간으로 선택 표시하고, 버튼을 놓으면 선택을 유지한다.
- [x] 영역 선택 후 빈 곳 클릭은 전체 해제, 다른 아이콘의 일반 클릭은 해당 아이콘 하나 선택으로 처리한다.
- [x] 선택된 아이콘을 누른 뒤 드래그할 때 기존 다중 선택을 유지한다. 이동 없이 클릭을 마치면 해당 아이콘 하나만 선택한다.
- [x] 영역 선택·이동 직후 더블클릭으로 오인하지 않는다. 정상 더블클릭은 누른 아이콘의 ID만 한 번 요청하며 여러 창을 일괄 실행하지 않는다.
- [x] 묶음 이동: 선택 아이콘의 상대 간격을 유지하고 묶음 전체를 화면 안으로 제한한다. 하나라도 비선택 아이콘과 겹치는 드롭은 전부 시작 위치로 복귀한다.
- [x] 창에서 시작한 드래그는 영역 선택을 시작하지 않는다. 선택 상자는 입력을 가로막지 않으며 창보다 뒤에 표시한다. 가림 패널로 확인했고 실제 팀원 창 확인은 남아 있다.
- [x] 포커스 상실·Escape·비활성화·화면 크기 및 배율 변경 시 선택 상자를 제거하고 이전 선택으로 복원한다. 진행 중인 묶음 이동도 전체 취소한다.
- [x] 사방향 드래그·교차 판정·클릭과 드래그 구분·묶음 충돌·배율·창 입력 가림을 검증하고 기존 14개 테스트의 단일 선택·이동 동작을 회귀 확인한다.

### 2-2. 다음 착수 — 최소 작업 표시줄 [제안]

사용자 착수 요청으로 작업 표시줄 UI·잠정 계약·임시 상태 제공자·데스크톱 작업 영역을 구현했다. 실제 창 상태·최소화·복원·활성화는 팀원 시스템에 연결해야 한다. 추가 구현은 이번 작업 표시줄 공유 변경에 포함한다.

아래 완료 표시는 임시 제공자 기준의 동작 확인이며 실제 창 통합 완료와 구분한다. 기술 계약·표시 정책·초기 수치의 원본은 [개발 가이드의 작업 표시줄 연결 계약](DEVELOPMENT.md#작업-표시줄-연결-계약-제안)에서 관리한다. 팀원 API의 실제 이름·형식은 연결 전에 대조하고, 엿보기의 조작 허용 범위는 GDD의 미정 사항으로 유지한다.

일반 창 기준의 작업 표시줄 통합을 먼저 진행한다. 게임 재시작·종료 화면·반환·엿보기 관련 조건은 해당 게임 기능을 연결할 때 추가로 확인하며, 확인 전에는 관련 항목을 완료로 표시하지 않는다.

팀원 창 구현이 완료되기 전에도 임시 제공자로 UI·상태 동기화·요청 전달·데스크톱 작업 영역을 구현할 수 있다. 실제 창의 상태 전환·복원·최대화 영역과 실행 빌드 통합 조작은 팀원 구현 후 확인한다. **[확정 — 사용자 지정]** 별도 창 숨김은 첫 구현에서 보류하고, 모달 소유 창의 활성화 전달·최소화 거부 예외는 개발 가이드의 계약에 따른다.

**연결 준비와 상태 동기화**

- [ ] 콘텐츠 ID와 창 인스턴스 ID의 대응, 현재 창 목록 조회, 상태 알림, 조작 요청을 팀원 시스템과 맞춘다. 잠정 계약과 같은 계약의 임시 제공자는 구현했으며 실제 API 대조는 남아 있다.
- [ ] 창 종류별 작업 표시줄 표시 여부·최소화 허용 여부를 실제 데이터로 전달한다. 임시 모델의 모달·허용 조작은 확인했으며 게임용 창 종류별 연결은 남아 있다.
- [x] 화면 하단에 바를 표시하고, 임시 제공자의 표시 대상마다 아이콘·제목 버튼을 하나씩 등록한다. 최소화는 유지하고 실제 제거 상태 알림은 버튼을 제거한다. 실제 X·반환 연결은 후속 통합에서 확인한다.
- [x] 작업 표시줄보다 먼저 열린 상태도 초기 목록에서 등록한다. 재활성화·재바인딩의 중복 버튼·구독을 막고, 닫고 재생성·모델 초기화 후 이전 요청을 거부한다.
- [ ] 게임 재시작·씬 전환·종료 화면의 초기화·잠금을 연결한다. 소스 Reset과 컴포넌트 비활성화·재활성화, 임시 전체 잠금은 확인했으며 실제 게임 이벤트 연결은 남아 있다.

**버튼 조작과 표시**

- [x] 클릭 전에 대상을 자동 활성화하지 않고 확정 상태에 따라 요청한다. 공유 씬의 실제 입력 모듈에서 한 버튼 클릭당 한 번만 임시 상태가 변경됨을 확인했다.
- [x] 임시 제공자의 확정 상태로 강조하고 모달 차단·전체 잠금·만료된 ID의 요청을 거부한다. 소유 창 활성화는 모달로 전달하고 소유 창 최소화는 거부한다. 실제 창 관리자의 정책 연결은 별도다.
- [x] 임시 상태의 최소화·제거 후 최근 활성 대상 또는 활성 없음으로 전환하며 최대화 플래그를 보존한다. 실제 창의 위치·크기 복원은 후속 통합 확인 대상이다.
- [x] 아이콘 재실행과 버튼이 같은 임시 인스턴스를 조작하고 반복 실행해도 중복 등록되지 않는다.
- [x] 생성 순서·144~240 UI 단위 폭·제목 말줄임·가로 스크롤·좌우 버튼·대체 아이콘과 동적 한글 글꼴을 적용했다. 19~20개 상태의 초과 배치와 접근을 확인했다.

**작업 영역과 입력**

- [ ] 공통 작업 영역을 실제 창의 이동·크기·최대화·복원 제약에 연결한다. 공통 영역 조회·변경 알림과 데스크톱 적용은 완료했으며 바 48·여백 20 UI 단위의 중복 차감이 없음을 확인했다.
- [ ] 실제 창의 영역 변경 후 접근성과 위치·크기 복원을 확인한다. 데스크톱 조작 취소·유효 아이콘 위치 유지·필요 위치 보정은 임시 단계에서 확인했다.
- [x] 바에서 시작한 클릭·드래그의 입력 누출을 막고, 바탕화면에서 시작해 바에서 끝난 영역 선택·이동은 원래 조작으로 유지한다. 버튼 드래그는 스크롤로 전달하고 클릭을 억제한다.
- [ ] 바는 창보다 앞에서 실제 바 영역만 입력을 받는다. 모달·게임 종료 화면을 사용하는 경우 해당 화면의 차단 규칙을 우회하지 않는다.
- [x] 생성 도구와 기존 공유 대상 `Desktop.unity`의 바·프리팹·참조·메타를 갱신했다. 아이콘·아트와 기존 역할별 공유 경로를 유지했다.

**검증 단계와 완료 조건**

- [x] 임시 상태의 초기 목록·등록·변경·제거·요청 거부·재구독·초기화를 확인했다. 실제 창 통합 완료와 구분한다.
- [ ] 실제 창으로 열기 → 비활성 창 활성화 → 최소화 → 버튼 및 아이콘으로 복원 → 닫기 → 재열기를 확인한다. 최대화 복원·최소화 불가·모달 사용 시 차단도 확인한다.
- [x] 임시 제공자의 공유 씬에서 두 해상도 버튼·초과 배치·긴 한글 제목·입력 방향·바 높이 변경을 확인하고 기존 배율 조건을 포함한 33개 회귀와 신규 12개, 전체 45개를 통과했다.
- [ ] 실제 창 통합 후 Windows 실행 파일에서 두 해상도 직접 조작을 확인한다. 현재 빌드는 경고·오류 0, 두 해상도 시작 예외 0을 확인했으나 직접 마우스 검증은 computer-use 앱 실행 승인 시간초과로 미완료다.

시작 메뉴·시스템 트레이·시계·앱 고정은 첫 구현의 후속 범위다. 작업 순서는 [제작 계획 7장](PRODUCTION_PLAN.md#7-데스크톱-이후의-다음-작업-제안)을 따른다.

**보류 기록 — 별도 창 숨김:** 최소화와 구분되는 숨김 상태와 관련 작업 표시줄 동작은 구현하지 않는다. 추후 채택 시 가시성 정보·상태 알림·숨긴 창의 버튼 클릭·활성 창 전환 조건을 함께 계획한다. 이 보류는 버튼 표시 여부(`ShowInTaskbar`) 정책과 구분한다.

## 12. 팀원 창 구현 원격 검토와 표시 문제

2026-10-30 `origin/main`을 fetch하여 팀원 커밋 `977c0110d08e68268f1ce48d1548dcbb29963a6a`를 확인했다. `Window`·`WindowTitleBar`·`WindowResizeHandle`·`WindowManager`·`NotepadWindow`·`ImageWindow`가 추가되어 있다. 이번 확인은 원격 코드와 직렬화된 씬의 검토다. 원격 씬의 Play Mode·빌드 검증은 하지 않았으며 로컬의 미커밋 작업 표시줄·씬·문서를 보존하기 위해 병합하지 않았다. 이전 45개 테스트 결과는 팀원 창을 포함하지 않는다.

| 확인 사항 | 근거와 영향 |
|---|---|
| 데스크톱이 창을 가림 | 원격 `Desktop.unity`의 Canvas는 `m_RenderMode: 0`(Screen Space Overlay), Sort Order는 -1이다. 창은 SpriteRenderer·2D TextMeshPro로 카메라에서 그린다. Overlay UI가 카메라 화면 위에 그려지므로 창의 Sorting Layer나 Canvas Sort Order만 바꾸어 해결할 수 없다. [Unity Canvas 문서](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/class-Canvas.html#screen-space---overlay) |
| 열기 요청의 씬 연결 누락 | `DesktopOpenRequestProbe.Record`는 `WindowManager.Instance.Open(itemId)`를 바로 호출하지만, 원격 Desktop·SampleScene에는 WindowManager 스크립트 GUID 참조가 없다. 공유 트리에도 창 프리팹은 없다. 관리자 배치·콘텐츠 ID별 프리팹 등록·null 처리 없이는 아이콘 열기가 완성되지 않는다. |
| 예시 메모장 본문 누락 | 원격 Desktop의 독립 NotepadWindow 오브젝트는 `backgroundSprite`·`secondarySprite`가 null이고 `text`가 비어 있다. 배경은 null일 때 꺼지며 Secondary는 실행 시 오류를 출력하고 투명 스프라이트를 사용한다. 렌더링 수정 후에도 본문 표시용 데이터가 필요하다. |
| 창 사이 앞뒤 순서 미완성 | `WindowManager.FocusWindow`는 `SetAsLastSibling()`만 호출한다. 렌더러는 같은 Sorting Layer와 고정 Order를 사용하므로 창 전체를 앞으로 가져오는 정렬이 구현되어 있지 않다. Primary·제목·본문·Secondary 관계를 보존하는 별도의 정렬 정책이 필요하다. |
| 입력 가림 미연결 | 제목 표시줄·각 리사이즈 핸들은 Update에서 마우스와 Collider.OverlapPoint를 직접 검사한다. 최상위 창 판정과 UI 차단 검사가 없어 겹친 창·뒤쪽 데스크톱·작업 표시줄 간 입력 소유를 연결해야 한다. 기존 UI 패널의 입력 가림 테스트로 이 경로를 검증했다고 볼 수 없다. |
| 작업 표시줄 계약 차이 | 원격 관리자는 콘텐츠 ID를 WindowId로 재사용하며 현재 활성 ID·최근 활성 대체·모달·전체 잠금 정책을 제공하지 않는다. 어댑터에서 인스턴스별 ID 대응과 알림을 연결하고 필요한 정책을 관리자로 보완해야 한다. |

**수정 방향 [제안]:** 팀원 2D 렌더러와 WindowBack/WindowFront 구조를 유지한다. 배경·아이콘·영역 선택을 Camera 방식 Canvas로 전환하여 창보다 뒤에 그리도록 카메라·Sorting Layer·평면 거리를 맞추고, 작업 표시줄은 별도 Overlay Canvas로 분리한다. 창은 UI 픽셀 크기의 WindowLayer 아래에 그대로 넣지 않고 월드 좌표 루트에 둔다. Canvas 작업 영역을 창 월드 좌표로 변환하고, 가장 위의 창·작업 표시줄·데스크톱 중 한 곳이 새 입력을 받도록 연결한다. Camera 전환 시 기존 `pressEventCamera` 경로와 UI 배율을 다시 검증해야 한다. 모든 창을 UI로 재작성하는 방식은 별도 대안이며 이번 검토에서 채택하지 않았다.
