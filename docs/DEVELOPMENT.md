# WINDOW.exe — 개발 가이드

> 역할: 실행 환경, 저장소 규칙, 시스템 연결과 기술 구현 방식을 관리한다.
> 기준일: 2026-10-30. **[확정]**과 **[제안]**은 [README의 문서 규칙](../README.md#문서-관리-규칙)을 따른다.
> 작업 담당·완료 여부는 [구현 체크리스트](IMPLEMENTATION_CHECKLIST.md), 플레이 규칙은 [GDD](GDD.md)에서 관리한다.
> 기본 데스크톱 공유 기준: `fab196a`. 이후 영역 선택·묶음 이동과 역할별 폴더 정리를 이번 공유 변경에 포함한다. 현재 폴더 배치는 2장, 선택 구현은 9장에서 관리한다.

## 1. 개발 환경과 프로젝트 열기

공유 프로젝트 기준은 Unity **6000.6.7f1**, URP 2D, Input System이다. 데스크톱 실행 씬은 `Assets/Scenes/Desktop.unity`, 기존 템플릿 씬은 `Assets/Scenes/SampleScene.unity`다.

1. 저장소를 클론한다.
2. Unity Hub의 **Add → Add project from disk**로 저장소 폴더를 등록한다.
3. Unity **6000.6.7f1**로 열고 패키지 설치·에셋 임포트가 끝날 때까지 기다린다.
4. `Assets/Scenes/Desktop.unity`를 열고 Play Mode를 시작한다.

**[확정] 가짜 데스크톱 방식**을 사용한다. 실제 OS 다중 창 대신 Unity 화면 안의 UI로 표현하여 발표 환경의 차이를 줄이고 전체 화면 연출을 다룬다.

## 2. Git 공유 규칙 [확정]

- 사용자 폴더 정리 요청에 따라 `Assets/Scripts/Desktop`, `Editor/Desktop`, `Tests/Editor/Desktop`, `Prefabs/Desktop`, `Data/Desktop`과 `Assets/Scenes/Desktop.unity`, 관련 `.meta`를 Git 공유 대상으로 관리한다. 기존 `Settings`, `Welcome`, 씬도 유지한다.
- 데스크톱의 코드·에디터 도구·테스트·프리팹·데이터·씬과 참조 아트를 함께 공유한다. `Assets/Art/Icon`, `Screen`, `Fonts`를 아트의 공유 범위로 관리한다.
- 나머지 에셋 폴더와 `.meta`는 로컬에 보존하되 `.gitignore`로 제외한다. 새 범위의 파일을 공유할 때에도 필요한 의존성과 `.meta`를 함께 확인한다.
- `Assets/Scenes/DesktopPrototype.unity`와 해당 `.meta`는 공유되지 않는 스크립트를 참조하므로 제외한다.
- 로컬 에디터 도구가 생성한 `ProjectSettings/Packages/com.unity.pipeline/`과 `ProjectSettings/SceneTemplateSettings.json`은 제외한다.
- `Library`, `Temp`, `Logs`, `UserSettings`, IDE 생성 파일은 각 환경에서 재생성한다.
- 공유하는 Unity 에셋에는 해당 `.meta`를 함께 포함한다.

`fab196a`로 공유한 기본 구현은 당시 `Assets/Desktop` 구조였다. 이후 영역 선택·묶음 이동과 역할별 이동, 제공된 배경·폰트는 사용자 요청에 따라 이번 공유 변경에 포함한다. 앞서 만든 프로토타입 보관본과 빌드·로그는 로컬에만 있으며 클론에 포함되지 않는다. 실제 창 시스템의 연결은 별도 작업이다.

### Assets 폴더 배치 [확정 — 사용자 지정]

최상위는 리소스 역할, 그 아래는 기능별로 나눈다. 게임잼 작업 중 새 파일을 추가할 때에도 같은 기준을 따른다.

| 위치 | 넣을 내용 |
|---|---|
| `Assets/Scripts/Desktop` | 데스크톱 런타임 코드와 `DesktopItemDefinition.cs` 같은 데이터 타입 정의 |
| `Assets/Scripts/Desktop/Debug` | 임시 열기 요청 수신기 `DesktopOpenRequestProbe.cs` |
| `Assets/Editor/Desktop` | 씬 생성·갱신 등 에디터 전용 도구 |
| `Assets/Tests/Editor/Desktop` | EditMode 테스트 어셈블리. 일부 테스트가 내부에서 Play Mode에 진입 |
| `Assets/Prefabs/Desktop` | 공통 아이콘 등 재사용 UI 프리팹 |
| `Assets/Data/Desktop` | 고정 ID·이름·아이콘을 지정한 ScriptableObject `.asset` 인스턴스 |
| `Assets/Scenes` | 실행·검증 씬 |
| `Assets/Art/Icon`, `Screen`, `Fonts` | 아이콘·화면 배경·폰트 파일 |
| `Assets/Settings` | 기존 렌더링·프로젝트용 설정 에셋 |

창 시스템이 들어오면 `Scripts/Windowing`, `Prefabs/Windowing` 등 같은 역할 아래에 기능 폴더를 만들고, 퍼즐·진행 코드는 `Scripts/Gameplay`로 나눈다. 파일이 생길 때 폴더를 만든다. 현재 Git 규칙은 각 역할의 데스크톱 하위 폴더만 허용하므로 새 기능의 공유 경로와 `.meta`도 함께 추가한다.

이동 시 Unity AssetDatabase를 사용해 `.meta`와 GUID를 유지한다. 기존 `WindowExe.Desktop`, `WindowExe.Desktop.Editor`, `WindowExe.Desktop.Tests` 어셈블리 이름·참조와 네임스페이스는 유지한다. 폴더명과 어셈블리 이름을 일치시키기 위한 추가 변경은 필요하지 않다.

루트의 사용자 제공 `neodgm.ttf`는 `Assets/Art/Fonts/neodgm.ttf`로 옮겼다. 파일 분류만 수행했으며 현재 화면의 OS 글꼴 적용 방식은 그대로다. 실행 글꼴 교체는 별도 작업이다.

## 3. 데스크톱과 창 시스템의 연결 [제안]

고정 식별자로 열기 요청을 전달한다는 요구는 확정되어 있다. 데스크톱 쪽 이벤트는 7~8장에 기록한 형태로 구현했다. 아래 창 생성·선택·복원 처리와 팀원 시스템의 최종 연결 형식은 연결 제안이다.

| 경계 | 처리 방식 |
|---|---|
| 데스크톱 → 창 시스템 | 표시 이름과 별도의 고정 식별자를 담아 `열기 요청(식별자)` 전달 |
| 새 창 | 식별자에 해당하는 창이 없으면 생성 |
| 이미 열린 창 | 새로 만들지 않고 기존 창을 앞으로 가져오기 |
| 최소화된 창 | 같은 창을 복원하고 앞으로 가져오기 |
| 최대화 해제 | 창 시스템이 이전 위치·크기로 복원 |
| 콘텐츠 이름 변경 | 표시 이름만 바뀌며 식별자와 연결 대상은 유지 |

- 기본 파일·프로그램은 식별자당 창 하나를 사용한다.
- 창의 생명주기·앞뒤 순서·최소화·복원·위치·크기는 `WindowManager`가 총괄한다:
  - `Open(id)`: 창이 없으면 프리팹 생성, 이미 있으면 맨 앞으로 포커스 및 최소화 해제(`Enshow`).
  - `Minimize(id)`: 창 `SetActive(false)` 및 상태를 `Minimized`로 보관.
  - `Enshow(id)`: 최소화된 창 복원, `SetActive(true)` 및 최상단 포커스.
  - `Close(id)`: 창 GameObject 파괴 및 프로세스 목록에서 제거.
  - `ActiveProcesses`: 현재 열려 있는 `WindowProcess` 리스트를 노출하여 작업 표시줄에서 상태 조회 및 상호작용 지원.
- 최소화 복원은 같은 아이콘의 더블클릭과 작업 표시줄 버튼을 같은 창에 연결한다. 작업 표시줄은 임시 상태 제공자 기준이며 실제 창 어댑터 연결은 남아 있다.
- 팀원 창이 준비되기 전에는 임시 수신기로 전달된 식별자와 호출 횟수를 확인할 수 있다.
- 통합 시 Canvas 기준 해상도·배율과 아이콘·창 영역의 표시 및 입력 순서를 맞춘다.
- 작업 표시줄은 창 시스템의 확정 상태를 표시하고 조작 요청을 보낸다. 아래 계약을 임시 수신기와 실제 창 어댑터가 함께 사용하며, 창 상태를 별도 원본으로 중복 관리하지 않는다.

### 작업 표시줄 연결 계약 [제안]

검수 후 보완한 안을 `ITaskbarWindowSource`, `TaskbarWindowSnapshot`, `TaskbarWindowInfo`, `TaskbarWindowAction`의 잠정 계약으로 구현했다. 실제 팀원 API의 이름·형식과 대응은 아직 확인하지 않았으며 어댑터로 연결한다. 작업과 검증의 완료 상태는 [체크리스트 2-2장](IMPLEMENTATION_CHECKLIST.md#2-2-다음-착수--최소-작업-표시줄-제안)과 11장에서 관리한다.

**[확정 — 사용자 지정]** 첫 구현에서는 최소화와 별개의 창 숨김 기능을 보류한다. 살아 있는 창의 화면 상태는 표시 중 또는 최소화로 구분하고 실제 제거는 목록에서 빠지는 생명주기 변경으로 처리한다. `ShowInTaskbar = false`는 버튼을 만들지 않는 표시 정책이며 창 자체를 숨기는 상태가 아니다. 별도 숨김을 채택할 때에는 가시성 데이터·조회·알림·버튼 조작·다음 활성 창 규칙을 함께 확장한다.

팀원 창 구현이 완료되기 전에도 아래 계약 초안에 따른 임시 상태 제공자로 작업 표시줄을 개발할 수 있다. 임시 제공자는 검증용 상태·알림·요청 처리만 제공하고 창 이동·크기 조절 등 실제 창 시스템을 별도로 구현하지 않는다. 실제 API와 아직 대조하지 못한 항목은 기록하고, 준비된 뒤 어댑터에서 연결한다. 임시 제공자의 결과는 실제 창 동작 확인과 구분한다.

**식별자·조회·알림**

| 데이터·연산 | 계약 |
|---|---|
| `ItemId` | 데스크톱 콘텐츠의 고정 ID. 기본 콘텐츠는 이 ID로 창 하나를 조회·생성하며 아이콘 재실행은 기존 창을 복원·활성화한다 |
| `WindowId` | 살아 있는 창 인스턴스의 고유 ID. 버튼과 조작 요청의 키이며 닫고 재생성하면 새 ID를 사용한다. 바탕화면 아이콘이 없는 하위 창도 식별할 수 있어야 한다 |
| 창 정보 | `WindowId`, 연결된 경우 `ItemId`·`OwnerWindowId`, 제목·아이콘, `ShowInTaskbar`, `CanMinimize`, `IsMinimized`, `IsMaximized`, `IsModal`, `CreationOrder`를 불변 객체로 제공한다. 제목·아이콘·허용 조작 변경도 알린다 |
| 전체 상태 조회 | `GetSnapshot()`은 현재 창 정보 목록 `Windows`, `ActiveWindowId`, 전체 요청 잠금 `IsLocked`를 반환한다. 최소화한 창도 목록에 포함하며, 활성 창이 없으면 null이다 |
| 상태 알림 | Unity 메인 스레드에서 `Changed`를 알리고 UI는 전체 스냅샷을 다시 조회해 생성·변경·제거·활성 변경·초기화를 반영한다. 최소화와 실제 제거를 구분하고 X·반환 등 실제 제거 경로가 같은 갱신 경로를 사용해야 한다. 별도 숨김 알림은 첫 구현에 넣지 않는다 |
| 조작 요청 | `WindowId`를 대상으로 활성화, 복원 후 활성화, 최소화를 요청한다. 이미 닫힌 창·전체 조작 잠금·허용하지 않는 조작·모달에 막힌 대상은 거부하며 새 창을 만들지 않는다. 아래 모달 소유 창 활성화 예외를 우선 적용하되 전체 잠금·제거를 우회하지 않는다 |

- 작업 표시줄 활성화 시 알림을 한 번만 구독한 뒤 현재 전체 상태를 조회해 버튼을 맞춘다. 초기 동기화는 같은 UI 처리 흐름에서 수행하고 ID 기준으로 중복 등록을 막는다. 비동기 어댑터를 사용한다면 조회와 알림 사이의 변경 누락·오래된 상태 덮어쓰기도 방지한다.
- 작업 표시줄은 상태 사본을 표시 목적으로만 보관한다. 요청 직후 예상 상태로 버튼을 바꾸지 않고, 창 시스템이 확정한 상태를 조회하거나 알림으로 반영한다.
- 비활성화·파괴 시 구독을 해제한다. 재활성화는 전체 목록으로 다시 맞추며, 재시작·씬 전환은 이전 버튼·활성 표시·구독을 정리한다. 이전 세션의 알림·요청을 새 창에 적용하지 않는다.
- 기존 `OpenRequested`와 `OnOpenRequested` 중 한 경로만 창 수신기에 연결한다. 작업 표시줄 요청은 같은 창 관리자를 사용하되 창 인스턴스를 대상으로 하며 콘텐츠 열기 요청으로 우회하지 않는다.

**버튼 조작과 창별 정책**

| 클릭 직전 대상 상태 | 요청과 결과 |
|---|---|
| 제거됨 또는 전체 조작 잠금 | 요청을 거부하고 확정 상태에 맞춰 표시한다 |
| 활성 모달의 소유 창 버튼 | 활성화 요청을 해당 모달로 전달해 앞으로 가져온다. 소유 창을 최소화하지 않는다 |
| 최소화 | 복원 후 활성화. 최소화 전 최대화 여부와 일반 창 위치·크기를 창 시스템이 보존한다 |
| 비활성·표시 중 | 활성화하여 앞으로 가져온다 |
| 활성·최소화 허용 | 최소화한다 |
| 활성·최소화 불가 | 상태를 유지한다 |
| 위 예외 외에 모달로 조작 불가 | 요청을 거부하고 확정 상태에 맞춰 표시한다 |

- 작업 표시줄의 PointerDown·UI 선택이 대상 창을 먼저 활성화해서 클릭 판정을 뒤집지 않도록 한다. 창 관리자가 클릭 직전 상태와 허용 조작을 확인해 요청을 처리한다. 한 클릭은 요청 한 번으로 처리한다.
- 활성 창을 최소화·제거하면 창 시스템이 가장 최근에 활성화했던 남은 표시 창을 선택한다. 적격 창이 없으면 활성 창 없음으로 알리고 모든 버튼의 활성 표시를 해제한다. 모달 사용 시에는 소유 창과 모달의 활성 제한을 우선한다.
- 일반 파일 창은 표시·최소화를 허용하는 안이다. 프로그램 메인 창과 `기록·시선·연결` 하위 창은 각각 표시 여부·최소화 허용 여부를 명시한다. 엿보기의 최대화·최소화·리사이즈는 [GDD 5-2장](GDD.md#5-2-엿보기-확정-여러-메카닉-중-하나로-포함)의 미정 범위를 유지하며 통합 전에 결정한다.
- 오류·경고 팝업은 별도 버튼을 만들지 않고 소유 창에 연결하는 안이다. 버튼을 만들지 않는 팝업이 활성일 때에는 표시 대상인 소유 창의 버튼을 강조하고, 해당 소유 창이 없으면 활성 버튼을 두지 않는다. 이 대리 강조를 소유 창의 실제 활성 상태로 판단해 최소화하지 않는다.
- **[확정 — 사용자 지정] 모달 예외:** 모달의 소유 창에 대한 활성화 요청은 거부하지 않고 그 모달로 전달해 앞으로 가져온다. 소유 창 최소화 요청은 거부하며 모달과 무관한 차단 대상의 요청도 거부한다. 이 판정은 창 관리자가 수행한다. 전체 데스크톱 조작 잠금이나 제거된 창에 대해서는 이 예외를 적용하지 않는다. 모달을 사용하는 통합 단계에서 확인하며, 별도 모달 시스템의 신규 제작을 뜻하지 않는다.
- 게임 종료 화면에서 데스크톱을 잠그면 작업 표시줄도 잠근다. 이 계획이 게임 종료 화면의 제작 완료를 뜻하지는 않는다.

**공통 작업 영역·입력·배치**

- 한 곳에서 Canvas 로컬 좌표의 작업 영역을 계산한다. 초기 바 높이는 48 UI 단위로 두며 Canvas Scaler의 1920×1080 기준을 따른다. 물리 화면 픽셀을 그대로 차감하지 않는다. 아래 수치는 첫 구현용 제안값이며 가독성·조작 검증 후 조정한다.
- 작업 영역은 전체 Canvas에서 하단 바 높이만 제외한다. `IconArea`는 그 안에서 기존 20 UI 단위 여백을 적용하고 창 최대화는 작업 영역 자체를 사용한다. 바 높이와 여백을 중복 차감하지 않는다.
- 창 이동·크기 조절·최대화 해제·최소화 복원에도 같은 영역을 각 부모 좌표로 변환해 사용한다. 일반 창의 제목 표시줄·필수 조작부는 접근 가능하게 보정하며 최대화 창은 새 영역에 맞춘다. 표시 부모나 엿보기 방의 고정 좌표를 단순히 축소·이동시키지 않는다.
- 영역·해상도·배율 변경 시 조작을 취소한 뒤 아이콘 배치를 재검사하고 유효 위치는 유지한다. 창 위치·복원 영역도 재검사한다. 엿보기 통합 시 줄어든 작업 영역에서 기본 크기·창 이동만으로 모든 필수 단서에 도달하는지 확인한다.
- 표시 순서는 배경 → 아이콘 → 선택 표시 → 창 → 작업 표시줄을 기본으로 하며, 모달 차단 화면·게임 종료 화면은 작업 표시줄 위에 둔다. 바 배경은 실제 바 영역만 입력을 받고 전체 화면에 투명 차단 영역을 만들지 않는다.
- 바에서 시작한 조작은 바가 처리한다. 바탕화면에서 시작한 영역 선택·아이콘 드래그는 바를 지나도 원래 조작을 유지한다. 선택은 작업 영역 안으로 제한하고 아이콘 이동은 기존 경계·겹침 규칙을 적용한다. 바 위에서 놓아도 작업 표시줄 버튼을 실행하지 않는다. 버튼에서 시작한 드래그는 창 조작이나 버튼 클릭으로 확정하지 않는다.
- 버튼은 생성 순서의 한 줄로 배치하고 활성화로 순서를 바꾸지 않는다. 초기 폭은 가용 폭에 따라 144~240 UI 단위, 간격은 4 UI 단위로 둔다. 최소 폭으로도 넘치면 가로 스크롤과 좌우 이동 버튼을 제공하며 숨겨진 버튼에도 접근할 수 있게 한다. 활성화된 버튼은 보이는 범위로 이동한다.
- 긴 제목은 한 줄 말줄임으로 표시하고 아이콘 미지정 시 공통 대체 표시를 쓴다. 동적으로 생성한 제목에도 한글 글꼴을 적용한다. 현재 `DesktopFont`는 Awake 시 기존 Text만 처리하므로 생성 이후 글꼴 연결도 필요하다.
- 역할별 Desktop 하위에 바 코드·프리팹·테스트를 배치하는 안이다. 생성 도구뿐 아니라 기존 공유 `Desktop.unity`에도 바와 참조를 저장해야 한다. 기존 씬은 자동 재생성하지 않고 필요한 구성만 추가하며 `.meta`·새 공유 경로와 의존성을 함께 확인한다.

### 현재 작업 표시줄 구현과 실제 창 연결

`Assets/Scripts/Desktop`의 `TaskbarController`가 스냅샷과 버튼을 동기화하고 `TaskbarButtonView`가 표시·클릭·드래그 억제·말줄임을 처리한다. `TaskbarUiFactory`는 바와 스크롤 구성을 만들며 공통 버튼은 `Assets/Prefabs/Desktop/TaskbarButton.prefab`이다. 작업 표시줄은 기존 런타임·Editor·Tests 어셈블리를 사용한다.

빈 작업 표시줄도 배경과 구분되도록 바탕색을 청회색으로 밝히고 상단에 2 UI 단위 경계선을 둔다. 경계선은 입력을 받지 않는다. Play 상태에서 아이콘을 더블클릭하면 임시 인스턴스 버튼이 생긴다. `Add Taskbar to Open Desktop` 메뉴는 기존 바의 외형도 갱신한다.

`DesktopWorkArea.Area`는 Canvas 로컬 좌표에서 하단 48 UI 단위만 제외한 영역이다. `BoundsIn(parent)`로 창 부모 좌표의 영역을 조회하고 `Changed`로 영역 변경을 받을 수 있다. `IconArea`에는 바 높이와 20 UI 단위 여백을 각각 한 번 적용했다. `WindowLayer`의 크기·원점은 변경하지 않았다. 실제 창 시스템에서 이동·크기·최대화·복원 제약에 이 영역을 반영하는 작업은 남아 있다.

씬의 `TaskbarDemoSource`와 `Debug/TaskbarDemoModel`은 검증용 상태 제공자다. 아이콘 열기 요청을 한 번 구독해 콘텐츠 ID당 임시 인스턴스 하나를 등록하고, 작업 표시줄 요청으로 상태와 강조를 바꾼다. 실제 창 본문·이동·리사이즈·위치 복원을 만들지는 않는다. 모델의 `Close`, `Reset`, `SetAppearance`, `SetMaximized`, `SetLocked`는 검증용 변경 경로다. 에디터에서는 소스 컴포넌트의 컨텍스트 메뉴로 활성 임시 상태 닫기·전체 초기화를 호출할 수 있다.

실제 창이 준비되면 `ITaskbarWindowSource`를 구현하는 어댑터에서 스냅샷·확정 알림·요청을 같은 창 관리자로 연결하고 `TaskbarController.Bind(adapter)` 또는 Inspector의 Source Behaviour 참조를 사용한다. `TaskbarDemoSource`는 끄고 기존 `OpenRequested`·`OnOpenRequested` 중 한 경로를 실제 창 수신기에 연결한다. 창 제거·소유 관계·모달 차단·최대화 상태 및 원래 위치·크기의 보존은 실제 창 시스템이 관리한다.

2026-10-30 원격 `977c011`의 창 구현을 코드·씬 기준으로 검토했다. `WindowManager`의 조회·상태 이벤트·조작 API는 존재하지만 아래의 UI 기반 창 구상과 달리 SpriteRenderer·2D TextMeshPro를 사용한다. 현재 Overlay 데스크톱과 바로 혼합할 수 없으며, 씬의 관리자·프리팹 등록과 실제 작업 표시줄 연결도 남아 있다. 원인·수정 제안·검증 경계는 [체크리스트 12장](IMPLEMENTATION_CHECKLIST.md#12-팀원-창-구현-원격-검토와-표시-문제)에 기록했다. 검토 당시에는 병합하지 않았으며 이후 작업 표시줄 공유를 위해 원격 변경을 함께 병합했다. 렌더링·입력·실제 창 어댑터 연결은 후속 작업으로 유지한다.

신규 씬 생성에는 바가 포함된다. 기존 씬에는 **WINDOW.exe → Desktop → Add Taskbar to Open Desktop** 메뉴로 필요한 구성만 추가·저장한다. Play Mode·미저장 씬은 변경하지 않고, 바가 이미 있으면 중복 생성하지 않는다. 공유 대상 `Desktop.unity`에는 바·프리팹 참조·임시 소스·공통 영역을 저장했다.

동적 버튼 제목은 `DesktopFont.Apply(Text)`로 OS 한글 글꼴을 적용한다. `DesktopInputTestScope`는 자동 검증 동안만 별도의 Input Settings를 사용해 에디터 포커스에 따른 가상 입력 누락을 방지하고 원래 설정을 복원한다. 실행 파일의 입력 정책을 바꾸는 코드는 아니다. 검증 결과와 실제 창·실행 파일 직접 조작의 미확인 범위는 체크리스트 11장에서 관리한다.

## 4. 아이콘 겹침 처리 [제안]

아이콘이 겹치지 않아야 한다는 요구와 관련 확인 항목은 [구현 체크리스트 2장](IMPLEMENTATION_CHECKLIST.md#2-오늘--데스크톱아이콘--사용자-확정)을 따른다. 아래는 아직 합의 전인 처리 방식이다.

현재 `DesktopController.EndDrag`는 아래 원위치 복귀 방식을 구현하고 테스트했다. 구현 결과와 팀의 최종 기획 합의 상태는 구분한다.

- 아이콘 이미지와 이름을 포함하는 배치 영역으로 겹침을 판정한다.
- 드래그 시작 시 원래 위치를 보관한다. 드래그 중에는 다른 아이콘 위를 지날 수 있다.
- 놓을 위치가 다른 아이콘과 겹치면 배치를 확정하지 않고 원래 위치로 돌린다.
- 정상적인 위치에 놓았을 때만 새 위치를 확정한다. 자동 정렬이나 다른 아이콘 밀어내기는 적용하지 않는 안이다.

## 5. UI·데이터 구조 [제안]

- 창 시스템은 순수 2D(`SpriteRenderer` 및 2D `TextMeshPro`) 기반으로 구현한다. Canvas 의존성을 없애고 2D Sorting Layer를 직접 제어한다.
- 공통 창 부모 클래스(`Window`)에서 위치 이동(`MoveTo`, `Translate`), 크기 조절(`Resize`, `ResizeDelta`), 최소/최대 크기 클램핑을 처리한다.
- 상단 메뉴 바(`WindowTitleBar`)와 8방향 리사이즈 핸들(`WindowResizeHandle`)이 자동 부착된다:
  - 메뉴 바 드래그: 마우스로 상단 메뉴 바를 잡고 끌어 창 전체를 부드럽게 이동.
  - 8방향 테두리/모서리 드래그: 상/하/좌/우 4개 변 및 4개 꼭짓점을 마우스로 잡고 끌어 실제 OS 창처럼 반대편이 고정된 채 자연스러운 리사이즈 지원 (최소/최대 크기 클램핑 포함).
  - 조작 상호 배제 및 모서리 우선권: 모서리/변 판정이 메뉴 바 판정보다 우선순위를 가지며, 겹치는 경계 클릭 시 이동과 크기 조절이 동시 발생하는 현상을 차단한다.
- 창 내부는 `Primary`와 `Secondary`가 1:1 동일 위치·크기로 겹쳐지는 오버레이 구조를 갖는다:
  - `Primary`: 자식 클래스에서 내용 자유 구현. Sorting Layer `WindowFront`, Order 0으로 렌더링.
  - `Secondary`: 스프라이트(`SpriteRenderer`) 전용 영역. Sorting Layer `WindowBack`, Order 0으로 렌더링. 특수 셰이더로만 보여지므로 항상 렌더링되며, 스프라이트 누락 시 투명 스프라이트 fallback 및 에러를 출력한다.
- `Window` 파생 기본 클래스:
  - `ImageWindow`: Primary에 `SpriteRenderer`를 두어 메인 스프라이트를 렌더링 (`SetPrimarySprite(Sprite)`).
  - `NotepadWindow`: Primary에 배경 `SpriteRenderer`(Order 0)와 2D `TextMeshPro`(Order 1)를 두어 배경 이미지와 텍스트를 함께 렌더링 (`SetBackgroundSprite(Sprite)`, `SetText(string)`).
- 빈 GameObject에 스크립트(`ImageWindow`, `NotepadWindow`)를 추가하면 `Primary` 및 `Secondary` 자식 오브젝트와 렌더러가 자동으로 생성 및 세팅된다.
- 공통 창 프리팹에서 제목 표시줄 이동, 앞뒤 순서, 최대화·최소화·복원·크기 조절을 처리한다. 닫기 이벤트는 게임 규칙을 연결할 수 있도록 분리한다.
- 기본 창 검증에서는 X를 일반 닫기로 사용한다. 목표 게임의 위험한 X는 이후 게임 상태와 경고를 연결할 때 적용한다.
- 아이콘·파일 정보는 ScriptableObject로 분리하는 안이다. 이름·고정 식별자·아이콘·콘텐츠 종류·내용·상태별 변형을 관리한다.
- GameState 플래그를 통해 파일 생성·이름 변경·내용 교체와 GDD의 바탕화면 연출을 연결한다.
- 진짜 커서를 숨기고 가짜 커서를 그리는 방식은 커서 연출을 위한 안이다. 플레이어 입력 없이 위험한 X를 누르거나 진행을 강제하지 않는다.

### 진행 상태의 예시 [제안]

| 상태 이름 | 의미 |
|---|---|
| `PhotosUnlocked` | 사진 폴더 잠금 해제. 일반 창 재열기로 초기화하지 않음 |
| 벽 단서 확인 상태 | 사진 조사 전에 발견해도 확인 사실을 보관 |
| `SequenceFound` | 실행 중이며 사진 해제와 벽 단서 확인을 모두 충족 |
| 반환 진행 상태 | 기록·시선·연결 해제 순서와 이미 반환한 창을 보관 |
| `CanDelete` | 순서를 발견했고 세 연결을 모두 해제함 |

플래그 이름과 자료구조는 구현 제안이다. 플레이어가 겪는 완료 조건은 GDD를 따른다. 조건 재평가로 하위 창이 중복 생성되거나 반환한 창이 복구되지 않게 한다.

## 6. 엿보기·이미지·화면 효과 [제안]

- 엿보기 본문은 RectMask2D 등으로 잘라 표시하고, 안쪽 공간은 바탕화면 좌표에 고정하는 안이다. 기존 제안은 LateUpdate에서 고정 좌표를 유지하는 방식이다.
- 먼저 창 이동과 공간 고정을 확인하고, 크기 조절·최대화·최소화는 GDD에서 허용 범위를 정한 뒤 연동한다.
- 주사선·노이즈는 배경에 박지 않고 모든 UI 위의 반투명 오버레이로 분리한다. 비정수 배율 확대 시 주사선·모아레 문제를 줄이는 목적이다.
- 창 테두리는 AI로 만든 9-slice 이미지 한 장을 사용하는 안이다.
- 같은 구도의 이미지 변형본 2~3장으로 재열기 변화를 표현한다.
- 오염도 단계별 화면은 색조와 오버레이 값을 바꾸는 안이다. 추가 배경 이미지를 단계마다 만들 필요는 없다.
- 화면 효과가 필수 문구를 가리거나 UI 입력을 막지 않게 한다.

리소스별 제작 기록과 적용 확인은 [구현 체크리스트 6장](IMPLEMENTATION_CHECKLIST.md#6-이후--자료리소스--담당-미정)에서 관리한다.

## 7. 데스크톱 구현 구조와 처리 순서

10/30에 구현한 데스크톱 구조다. 기본 구현은 `fab196a`로 공유했으며, 후속 영역 선택·묶음 이동도 이번 공유 변경에 포함한다. 팀원 창과의 최종 연결 형식은 여전히 제안이며, 후속 순서는 [제작 계획 5장](PRODUCTION_PLAN.md#5-1030-사용자-담당-구현-순서-제안), 완료 상태는 구현 체크리스트에서 관리한다.

### 기존 파일의 취급

공유 씬 `SampleScene.unity`는 기본 카메라·조명 상태를 유지한다. 기존 `DesktopIcon.cs`의 입력 처리 방식과 프로토타입의 UI 구성 방식을 참고하고, 창 생성에 묶여 있던 데스크톱 책임을 분리해 초기에는 `Assets/Desktop`에 구현했다. 현재는 2장의 역할별 위치로 이동했다.

대체된 프로토타입 코드·테스트·씬·데이터와 각 `.meta` 30개는 `Assets`에서 제거하고 작업 환경의 `Builds/PrototypeArchive/Assets/`에 원래 상대 경로로 보존했다. 당시 열려 있던 프로토타입 씬의 미저장 변경도 저장한 뒤 보관했다. 이 보관본은 Git 공유 대상이 아니며, 새 구현은 과거 프로토타입 어셈블리에 의존하지 않는다.

### 구성 요소

런타임 코드는 `Assets/Scripts/Desktop`, 생성 도구는 `Assets/Editor/Desktop`, 검증 코드는 `Assets/Tests/Editor/Desktop`에 둔다. 다른 에셋의 위치는 2장의 Assets 폴더 배치를 따른다.

| 요소 | 책임 |
|---|---|
| `DesktopItemDefinition` | 고정 식별자·표시 이름·아이콘 이미지의 ScriptableObject 데이터 |
| `DesktopIconView` | 아이콘·이름·선택 표시, 포인터 입력을 받아 컨트롤러에 전달 |
| `DesktopController` | 선택 집합·대표 선택, 영역 선택·묶음 이동·클릭 상태, 열기 요청 관리. 아이콘 위치는 씬 인스턴스의 RectTransform에 유지 |
| `DesktopLayout` | 바탕화면 좌표·선택 사각형·묶음 경계 계산, 화면 경계 제한, 다른 아이콘과의 겹침 판정 |
| `DesktopBackground`·`DesktopSelectionBox` | 빈 바탕화면의 클릭·드래그 입력 전달과 입력을 가로막지 않는 선택 상자 표시 |

Canvas는 `Wallpaper`, `IconArea`, `SelectionLayer`, `WindowLayer`, `Taskbar` 순서로 구성했다. 배경만 빈 바탕화면 클릭·드래그를 받고, 선택 표시와 빈 `WindowLayer` 자체는 입력을 막지 않는다. 작업 표시줄은 실제 하단 영역만 입력을 받는다. 실제 창의 입력을 받는 UI가 창 영역에 들어오면 뒤쪽 아이콘보다 먼저 입력을 받는다. 제공 아트와 이름은 공통 프리팹·데이터에 연결되어 있으며, 이후 콘텐츠 데이터와 이미지를 교체할 수 있다.

아이콘의 초기 위치는 씬이나 별도 배치 설정에서 지정하고, 이동 후 위치는 실행 중 상태로 보관한다. 창을 열고 닫는 동작이 아이콘을 다시 생성하거나 초기 위치로 되돌리지 않게 한다. 디스크 저장은 별도 후순위다.

### 입력과 배치 처리

1. 왼쪽 버튼을 누르면 대상 아이콘과 포인터 시작 위치를 기록한다. 작은 움직임은 클릭으로 남긴다.
2. 선택된 아이콘을 누르면 집합을 유지하며, 이동 거리가 기준을 넘으면 원래 위치들을 보관하고 묶음 드래그로 전환한다. 이동 없이 클릭을 마치면 해당 아이콘 하나만 선택한다.
3. 포인터를 아이콘 부모의 좌표로 변환해 후보 위치를 계산한다. 화면 픽셀 이동량을 UI 위치에 그대로 더하지 않는다.
4. 묶음 전체의 이미지·이름 영역이 바탕화면 안에 있도록 이동량을 한 번 제한하고, 놓을 때 다른 아이콘과의 겹침을 검사한다.
5. 유효한 위치만 확정한다. 하나라도 겹친 위치에 놓으면 묶음 전체를 드래그 전 위치로 복귀한다.
6. 드래그로 처리한 입력은 클릭·더블클릭 처리에서 제외한다. 같은 아이콘에 대한 정상적인 더블클릭만 열기 요청을 한 번 보낸다.

더블클릭 판정은 한 곳에서 처리하여 기본 클릭 횟수와 별도 타이머가 중복으로 실행 요청을 만들지 않게 한다. 창이 가로챈 입력은 아이콘 컨트롤러가 다시 처리하지 않는다.

현재 씬·코드의 초기 설정은 다음과 같다. 값 변경 시 완료 조건에 맞는 입력 검증을 다시 한다.

| 설정 | 현재 값·관리 위치 |
|---|---|
| 기준 화면·배율 | Canvas Scaler 1920×1080, 화면 크기에 따른 배율, 가로·세로 일치 비중 0.5 |
| 드래그 시작 거리 | 씬의 EventSystem `pixelDragThreshold = 8` 화면 픽셀 |
| 더블클릭 시간·이동 허용 | DesktopController `doubleClickSeconds = 0.3`, `doubleClickDistance = 12` 화면 픽셀 |
| 아이콘 배치 영역 | 루트 144×152 UI 단위. 이미지·이름과 선택 표시를 함께 이동 |
| 바탕화면 여백 | IconArea는 공통 작업 영역에서 20 UI 단위 안쪽. 하단 작업 표시줄은 48 UI 단위 |
| 조작 취소 | Escape·포커스 상실·비활성화 시 영역 선택은 이전 선택으로, 묶음 이동은 이전 위치로 복귀. 화면 크기·영역 크기·배율 변경 시에도 취소 후 배치를 재검사 |

### 창 시스템 연결과 확인

열기 요청은 `DesktopController.OpenRequested` C# 이벤트와 Inspector용 `OnOpenRequested`의 `UnityEvent<string>`으로 제공한다. 한 수신기는 둘 중 한 경로만 구독해 같은 요청을 중복 처리하지 않는다. 아이콘에 창 생성 코드를 직접 넣지 않는다. `DesktopOpenRequestProbe`는 식별자·전달 횟수와 Console 로그를 확인하는 임시 수신기다. 가림 확인용 패널은 테스트에서만 생성하며 창 이동·최소화 기능은 제작하지 않았다.

배치·클릭 상태와 배율 변환은 자동 검증했고, Play Mode에서 가림·빈 배경·Input System 입력을 확인했다. 실제 팀원 창을 통한 위치 유지·복원·재열기는 미검증이다. 검증 범위와 결과는 [체크리스트 8장](IMPLEMENTATION_CHECKLIST.md#8-1030-구현검증-결과와-공유-범위)에서 관리한다.

데스크톱의 코드·프리팹·데이터·검증 씬은 역할별 위치에 나누고 참조 아트와 함께 공유 대상으로 관리한다. 공유 범위의 원본 규칙은 2장에서 관리한다.

## 8. 데스크톱 실행과 연결

1. `Assets/Scenes/Desktop.unity`를 연다. 메뉴 **WINDOW.exe → Desktop → Create or Open Desktop**으로도 열 수 있다.
2. Play Mode를 시작한다. 배경과 휴지통·메모·사진·인터넷 아이콘이 표시된다.
3. 더블클릭은 Console에 `Desktop open requested: 식별자`를 기록하고 임시 소스에 상태 하나를 등록해 작업 표시줄 버튼을 표시한다. 버튼으로 활성·최소화·복원 상태를 확인할 수 있으며, 실제 창 본문은 팀원 시스템을 연결한 뒤 열린다.

| 파일·요소 | 용도 |
|---|---|
| `Assets/Prefabs/Desktop/DesktopIcon.prefab` | 공통 선택 표시·이미지·이름·입력 처리 |
| `Assets/Prefabs/Desktop/TaskbarButton.prefab` | 작업 표시줄의 동적 창 버튼 |
| `Assets/Data/Desktop/*.asset` | `recycle-bin`, `memo`, `photos`, `internet`의 4개 콘텐츠 정의 |
| 씬의 `DesktopCanvas/IconArea` | 아이콘 배치 영역 |
| 씬의 `DesktopCanvas/WindowLayer` | 팀원 창을 배치할 상위 UI 영역. 빈 영역 자체는 입력을 막지 않음 |
| `DesktopController.OpenRequested` | 창 수신기에 전달할 고정 식별자 이벤트 |
| `Builds/Desktop/Desktop.exe` | Windows 검증 빌드 |

데이터를 추가하려면 **Create → WINDOW.exe → Desktop Item**으로 고정 ID·이름·이미지를 지정하고 공통 프리팹의 `DesktopIconView.Configure`로 연결한다. 이 메서드는 표시 갱신과 컨트롤러 등록을 함께 수행하므로 데이터 에셋을 만들기만 해서는 씬에 아이콘이 추가되지 않는다. ID는 서로 달라야 한다. 표시 이름만 바꿀 때는 `SetDisplayName`을 사용한다.

생성 도구는 기존 씬이 있으면 그대로 열며 자동으로 씬을 다시 만들지 않는다. 기존 프리팹·데이터도 재사용한다. 기존 씬에 아이콘을 추가하려면 프리팹 인스턴스와 컨트롤러 등록을 별도로 연결한다.

기존 데스크톱 씬에 선택 상자만 추가하려면 변경을 저장하고 Play Mode를 종료한 뒤 **WINDOW.exe → Desktop → Add Selection Box to Open Desktop**을 실행한다. 기존 표시가 있으면 재사용하며, 다른 씬 구성은 재생성하지 않는다. 공유 `Desktop.unity`에는 이미 선택 상자와 컨트롤러 참조를 저장했다.

### 창 시스템 연결 시의 경계

| 데스크톱에서 전달하는 ID | 현재 표시 이름 | 팀원 수신기에서 연결할 대상 |
|---|---|---|
| `recycle-bin` | 휴지통 | 휴지통 콘텐츠 |
| `memo` | 메모.txt | 메모장 콘텐츠 |
| `photos` | 사진 | 사진·앨범 콘텐츠 |
| `internet` | 인터넷 | 해당 콘텐츠 또는 안내 반응 |

현재 데이터에는 WINDOW.exe가 없다. 이를 게임 시작 아이콘으로 연결할 때에는 별도 ID·데이터·이미지와 대상 창을 추가한다.

팀원 시스템은 하나의 이벤트 경로를 구독하고, 요청받은 ID에 대해 새 창 생성·기존 창 선택·최소화 복원을 처리한다. 창은 `WindowLayer` 아래에 배치하고, 배경·제목 표시줄·본문 중 필요한 영역이 입력을 받도록 구성한다. 빈 레이어 전체를 투명한 입력 차단 패널로 덮지 않는다. 실제 수신기를 연결한 뒤에는 임시 로그 수신기 `DesktopOpenRequestProbe`를 끌 수 있다.

아이콘 PNG는 전체 파일이 한 이미지로 보이도록 Sprite Single 모드로 사용한다. 자동 분할된 앨범·인터넷 이미지의 그림자 조각만 연결되는 문제를 수정했다. 원본 PNG 픽셀은 변경하지 않았다. 한글 이름은 실행 시 OS 한글 글꼴을 사용하며, 배경은 제공된 1672×941 파일을 그대로 사용한다. 1920×1080 배경 재제작은 별도 리소스 작업이다.

### 테스트·빌드 재현

Test Runner에서 EditMode의 `WindowExe.Desktop.Tests`를 선택한다. 테스트 일부가 내부적으로 Play Mode에 진입하므로 테스트가 끝난 뒤에 빌드를 시작한다. Windows 빌드 시 Build Profiles의 씬 목록에는 `Assets/Scenes/Desktop.unity`를 지정한다. 템플릿 씬인 SampleScene을 데스크톱 실행 씬으로 대신 사용하지 않는다. 기존 EditorBuildSettings는 SampleScene을 가리키므로 빌드 대상 씬을 명시한다.

`Builds/Desktop/Desktop.exe`, `Builds/DesktopValidation/player-*-final.log`, 검증 JSON은 작업 환경의 로컬 결과물이다. 새로 클론한 저장소에는 들어 있지 않다. 기존 테스트·빌드의 확인 결과는 체크리스트 8장에서 관리하고, 새 환경에서 확인한 결과는 실제 검증 후 갱신한다.

## 9. 드래그 영역 선택 구현

사용자의 계획대로 구현하라는 요청에 따라 단일 선택 코드를 확장했다. 아래 동작은 `fab196a` 이후 구현·검증해 이번 공유 변경에 포함한다. 단일 선택 API와 열기 이벤트 형식은 유지한다. 완료 확인 결과는 체크리스트 2-1장과 9장에서 관리한다.

### 입력과 선택 규칙

- 빈 바탕화면의 왼쪽 드래그가 기존 8픽셀 기준을 넘으면 영역 선택을 시작한다. 누른 위치와 현재 위치의 최솟값·최댓값으로 사각형을 만들어 네 방향 드래그를 같은 방식으로 처리한다.
- 시작 시 이전 선택을 보관하고, 드래그 중에는 사각형에 면적으로 겹치는 활성 아이콘으로 선택을 교체한다. 판정 영역은 기존 아이콘 루트의 144×152 영역을 재사용한다. 가장자리만 닿는 경우는 제외하며, 빈 영역을 선택하면 선택이 없어진다. 이번 단계에서는 보조키로 선택을 누적하지 않는다.
- 빈 곳 클릭은 전체 해제한다. 다중 선택에 포함된 아이콘을 누르면 드래그 여부가 정해질 때까지 집합을 유지하고, 이동 없이 클릭을 마치면 그 아이콘만 남긴다. 선택되지 않은 아이콘을 누르면 해당 아이콘만 선택한다.
- 영역 선택 시작·종료·취소와 아이콘 이동은 더블클릭 연속 상태를 초기화한다. 드래그가 끝난 입력은 클릭으로 처리하지 않는다. 정상 더블클릭은 누른 아이콘 하나의 고정 ID만 요청한다.
- 창에서 시작한 입력은 바탕화면이 받지 않는다. 빈 바탕화면에서 시작한 영역 드래그는 포인터가 아이콘·창 위를 지나도 같은 작업으로 유지하고 창에 새 조작을 전달하지 않는다. 선택 판정은 바탕화면 아이콘의 위치를 기준으로 하며 선택 상자는 창 뒤에 표시한다.
- 포인터 좌표는 `IconArea` 로컬 좌표로 변환한다. 시작점·현재점을 영역 경계로 제한하되 바깥 여백에서 시작한 입력도 처리한다. 선택 상자는 아이콘 위·창 아래의 별도 레이어에 두고 모든 Graphic의 `raycastTarget`을 끈다.
- 버튼을 놓으면 선택을 확정하고 상자를 숨긴다. Escape·포커스 상실·컨트롤러 비활성화는 진행 중 선택을 취소하고 시작 전 집합을 복원한다. 중간 해상도 변경은 조작을 취소한 뒤 레이아웃을 재검사한다. 선택·이동 중에는 자동 배치가 끼어들지 않게 한다.

### 선택 후 묶음 이동

선택된 아이콘의 드래그에서는 집합 전체의 시작 위치를 보관하고 동일한 이동량을 적용한다. 각 아이콘을 따로 경계 보정하면 간격이 무너지므로 집합의 전체 경계로 이동량을 한 번 제한한다. 집합이 화면보다 커서 들어갈 수 없으면 이동을 거부한다. 이동 중 구성 아이콘이 비활성화되면 묶음 전체를 취소하고 그 아이콘을 선택 집합에서 제거한다.

드롭 시 집합 내부와 비선택 아이콘을 포함해 배치 유효성을 검사한다. 하나라도 겹치거나 경계를 벗어나면 전체를 시작 위치로 복귀한다. 일부만 이동을 확정하지 않는다. 휴지통 삭제·게임의 드롭 규칙은 이 이동 처리에 연결하지 않는다. 기존 겹침 금지를 묶음 단위 원위치 복귀 방식으로 구현했다. 실제 게임의 삭제 판정과 결합할 때에는 별도 합의가 필요하다.

### 확인할 경우

선택 판정은 사방향·부분 교차·경계 접촉·빈 영역·활성 상태를 확인한다. 입력은 작은 흔들림·드래그 후 클릭 억제·다중 선택 뒤 클릭과 이동·더블클릭 대상 하나·취소와 포커스 복원을 확인한다. 묶음 이동은 간격 유지·화면 경계·한 아이콘만 충돌하는 경우의 전체 복귀를 확인한다.

실제 Input System 경로에서는 창에서 시작한 드래그의 차단, 바탕화면에서 시작한 드래그의 지속, 선택 표시가 입력을 가로막지 않는지 확인한다. 기존 배율 0.5·1.5와 두 해상도에서 조작을 확인하고 기존 14개 검증도 회귀 확인한다. 테스트를 마친 뒤 빌드를 실행하며, 실제 팀원 창이 없다면 가림 패널 검증과 통합 미확인을 구분해 기록한다.
