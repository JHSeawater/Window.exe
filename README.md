# WINDOW.exe

오래된 컴퓨터에 남겨진 전 사용자의 흔적과 창 너머 공간을 조사하며, 정체불명의 프로그램을 삭제하고 살아남는 아날로그 호러·미스터리·퍼즐 어드벤처 프로젝트다.

## 문서 안내

상세 문서는 `docs/`에 모으고, 루트에는 이 안내 문서와 [AGENTS.md](AGENTS.md)를 둔다. AGENTS.md는 개발 전 문서 확인과 개발 중·후 문서 갱신 절차를 정한다.

각 내용은 아래 담당 문서 한 곳에서 관리한다. 다른 문서에는 필요한 연결만 남긴다.

|---|---|---|
| [PROJECT_CONTEXT.md](docs/PROJECT_CONTEXT.md) | 프로젝트 배경 | 게임잼, 행사 조건, 채점 기준, 제작 목표의 배경 |
| [GDD.md](docs/GDD.md) | 순수 게임 기획 | 플레이 경험, 세계관, 등장인물, 규칙, 퍼즐, 엔딩, 연출, 기획 미정 사항 |

## 어디부터 읽을까

데스크톱을 실행하려면 Unity에서 `Assets/Scenes/Desktop.unity`를 열고 Play Mode를 시작한다. 프로젝트를 여는 방법과 창 시스템 연결은 [개발 가이드](docs/DEVELOPMENT.md)에서 확인한다.

`Assets`는 `Scripts`, `Editor`, `Tests`, `Prefabs`, `Data`, `Scenes`, `Art`, `Settings`처럼 역할별로 나누고, 각 역할 아래에 `Desktop` 같은 기능 폴더를 둔다. 새 파일의 위치와 Git 공유 규칙은 [개발 가이드의 Assets 폴더 배치](docs/DEVELOPMENT.md#assets-폴더-배치-확정--사용자-지정)를 따른다. 폴더 정리 후 확인 결과와 공유 상태는 [체크리스트 10장](docs/IMPLEMENTATION_CHECKLIST.md#10-assets-역할별-정리와-재검증)에서 확인한다.

기본 데스크톱 구현·제공 아트·테스트는 `fab196a`로 공유했다. 이후 영역 선택·묶음 이동과 역할별 폴더 정리도 현재 코드에 포함되어 있다. 더블클릭은 고정 식별자의 열기 요청을 전달한다. 현재 작업 트리에서는 팀원 창 관리자와 연결해 실제 창을 생성·최소화·복원한다. 최초 공유 시점의 검증 결과는 [구현 체크리스트 8장](docs/IMPLEMENTATION_CHECKLIST.md#8-1030-구현검증-결과와-공유-범위)에서 확인한다.

빈 곳 클릭은 전체 선택 해제, 선택된 아이콘 드래그는 묶음 이동, Escape는 진행 중 조작 취소다. 추가 검증 결과는 [체크리스트 9장](docs/IMPLEMENTATION_CHECKLIST.md#9-영역-선택묶음-이동-추가-구현-결과), 현재 경로의 재검증은 10장에서 확인한다.

작업 표시줄 `e37873c`와 팀원 창 작업은 `0962ce4`로 병합·공유했고, 이후 실제 호환 구현은 현재 작업 트리에 있다. 아이콘 더블클릭으로 실제 검증 창을 열고 제목 표시줄 이동·8방향 리사이즈·최대화·최소화·작업 표시줄 복원·닫기를 사용할 수 있다. 검증용 콘텐츠와 게임 퍼즐은 구분한다.

현재 구성과 실행 방법은 [개발 가이드 10-8장](docs/DEVELOPMENT.md#10-8-현재-구현과-실행-방법--2026-10-31), 구현·검증 상태는 [체크리스트 12장](docs/IMPLEMENTATION_CHECKLIST.md#12-팀원-창-구현-원격-검토와-표시-문제)을 따른다. 이전 임시 제공자 결과는 11장에 보존했고 구현 순서의 원안은 [제작 계획 8장](docs/PRODUCTION_PLAN.md#8-창데스크톱-호환-구현-순서-제안)이다.

게임 글꼴은 제공된 NeoDunggeunmo로 통일한다. 기존·새 텍스트의 공통 설정과 적용 규칙은 [개발 가이드 11장](docs/DEVELOPMENT.md#11-공통-게임-글꼴-확정--사용자-지정), 검증 결과는 [체크리스트 13장](docs/IMPLEMENTATION_CHECKLIST.md#13-공통-게임-글꼴--2026-10-31)에서 확인한다.

좌하단 시작 버튼의 추가 구현 계획은 [개발 가이드 12장](docs/DEVELOPMENT.md#12-좌하단-시작-버튼-구현-계획-제안), 작업 순서는 [제작 계획 9장](docs/PRODUCTION_PLAN.md#9-좌하단-시작-버튼-추가-제안)에서 확인한다. 작은 실행 메뉴는 제안 단계이며 아직 구현하지 않았다.

- 게임이 어떤 내용인지 보려면 **GDD**를 읽는다.
- 지금 본인·팀원이 무엇을 만들지 보려면 **구현 체크리스트 2~4장**을 읽는다.
- 프로젝트를 열거나 두 시스템을 연결하려면 **개발 가이드**를 읽는다.
- 행사 조건과 평가 이유는 **프로젝트 배경**, 남은 시간과 시연 준비는 **제작·시연 계획**에서 확인한다.

2026-10-31 전체 검수의 통과 범위·당시 재현된 코드 문제 3건·빌드 제약·미검증 항목은 [구현 체크리스트 15장](docs/IMPLEMENTATION_CHECKLIST.md#15-구현-전체-검수--2026-10-31)에서 확인한다. 수정 전 검수 기록과 수정 후 검증 결과를 구분한다.

세 문제는 검토 보완을 포함한 사용자 착수 지시에 따라 수정했다. 기술 계약은 [개발 가이드 13장](docs/DEVELOPMENT.md#13-전체-검수-문제-수정-계획-제안), 진행 순서의 원안은 [제작 계획 10장](docs/PRODUCTION_PLAN.md#10-전체-검수-문제-수정-순서-제안), 현재 검증 결과와 남은 직접 조작 항목은 [체크리스트 15-4장](docs/IMPLEMENTATION_CHECKLIST.md#15-4-수정-작업과-완료-조건-계획)을 따른다.

전체 화면 CRT 오버레이를 Desktop 씬에 연결했다. Play Mode에서 데스크톱·창·작업 표시줄 위에 약한 기본 효과가 표시되고, 기본 단계 0~3·독립 Spike·Full/Simple/Off 품질을 제어할 수 있다. 기술 계약과 API는 [개발 가이드 14장](docs/DEVELOPMENT.md#14-전체-화면-crt-노이즈-구현-계획-제안), 진행 순서는 [제작 계획 11장](docs/PRODUCTION_PLAN.md#11-전체-화면-crt-노이즈-적용-순서-제안), 검증 결과와 남은 항목은 [체크리스트 16장](docs/IMPLEMENTATION_CHECKLIST.md#16-전체-화면-crt-노이즈-구현-계획--2026-10-31)을 따른다. 게임 오염도 판정·실패/엔딩·재시작과의 연결은 후속 범위다.

## 문서 관리 규칙

- **[확정]**은 기존 합의나 사용자가 지정한 내용이다. **[제안]**은 합의 전인 안, **[미정]**은 결정이 필요한 질문이다. 문서를 옮겼다는 이유로 상태를 바꾸지 않는다.
- 확정 여부는 기획·요구사항의 상태이고, 체크박스는 실제 작업의 완료 확인 상태다. 기획 확정만으로 완료 체크하지 않는다.
- 내용이 바뀌면 위 표의 담당 문서를 수정한다. 구현 완료 체크는 **구현 체크리스트에서만** 갱신한다.
- GDD에는 담당·날짜별 할 일·기술 구조를 넣지 않는다. 기획 미정 사항은 GDD에, 구현 방식의 제안은 개발 가이드에 남긴다.
- 중요한 결정이나 범위가 바뀌면 담당 문서를 고치고 **CHANGELOG**에 날짜와 이유를 기록한다. 단순 완료 체크마다 이력을 추가할 필요는 없다.
- 로컬 시험 구현·원문의 제작 기록과 공유 프로젝트에서 확인한 완료 상태를 구분한다.
